# 차례: 새 매매법 후보 반론 검토

코드가 문법과 중복(같은 해시)을 이미 걸렀고, 남은 후보가 `candidates`에 있습니다(번호 `index`, 표준형 `spec`, 코드 설명 `description_ko`, 비슷한 지난 시험 `similar_tested`, 라이브러리와 청산만 다른지 `library_overlap`). 발명가의 아이디어는 `this_round.lab_inventor`에 있습니다.

각 후보마다 `reviews`에 `{"index": 번호, "keep": true/false, "reason": "한 줄"}`을 씁니다. **뺄 수만 있고 더할 수는 없습니다.** 시험은 코드가 하고, 시험 하나하나가 다음 시험의 기준을 엄격하게 만듭니다.

빼는 경우(`keep: false`)
- 이미 떨어진 시험과 거의 같음(`similar_tested`의 같은 진입·봉, 필터나 값 하나만 다름). 
- 지난 결과를 보고 고른 티가 남(예: 지난 시험에서 2기간만 좋았던 것에 필터를 붙여 1기간을 맞추려 함) — 데이터 뒤지기.
- `library_overlap`이 true인데 `why_new`가 청산 차이밖에 없음.
- 짧은 봉(5분~1시간)인데 비용을 넘을 이유가 없음.

남기는 경우(`keep: true`): 아이디어가 지난 시험과 분명히 다르고, 왜 다를 수 있는지 말이 됨. 일부러 다 빼지는 않습니다.
