# 합친 봇 (여러 매매법을 한 계좌로)

2026-10-17 두 분 요청으로 만든 봇입니다. 코드는 `paperbot/combo.py`, 테스트는 `tests/test_combo.py`입니다.

## 0. 한 줄 요약

- 두 분이 고른 매매법들의 신호를 **한 계좌**로 모아서 거래합니다. 규칙봇 기본값과 커스텀값봇 커스텀값 둘 다 넣을 수 있습니다.
- **포지션은 항상 1개**입니다. 같은 순간 신호가 둘 이상이면 **더 좋은 자리 하나만** 들어갑니다. 나머지는 "밀림"으로 기록합니다.
- 배수는 **BTC 40배, 나머지 30배 고정**입니다. 증거금은 배수%입니다(40배면 40%, 30배면 30%).
- 페이퍼 봇입니다. 주문은 내지 않습니다. 실거래는 지금 실거래 프로그램(실행기)이 이 계좌를 그대로 따라가는 방식입니다. 실행기 코드는 바꾸지 않았습니다.
- 규칙봇 파일은 하나도 바꾸지 않았습니다. 30일 판정(11/04)에 영향이 없습니다.

## 1. 어떻게 움직이나

| 항목 | 규칙 | 설정 이름 |
|---|---|---|
| 매매법 목록 | 두 분이 고른 것. 목록 순서도 의미가 있음(동점일 때) | `members` |
| 기본값 매매법 | 규칙봇이 계산한 신호를 그대로 받음(규칙봇 계좌와 같은 시각, 같은 가격) | `{"strategy": "V39_ALL", "tf": "1h"}` |
| 커스텀값 매매법 | 커스텀값봇과 같은 함수·같은 숫자로 이 봇이 직접 계산 | `{"pick": "core-N13_3OUTSIDE-30m-1"}` |
| 배수 | BTC 40배, 나머지 30배 고정 | `leverage` |
| 증거금 | 배수% (BTC 40%, 나머지 30%) | `margin: "leverage"` |
| 한 번 손절 최대 손실 | 계좌의 15%. 넘으면 크기를 줄여서 맞춤(배수는 그대로) | `max_loss_frac`, `loss_cap` |
| 손절 | 아래 2-1 | `stop` |
| 익절 | 계단 익절. 순ROE 11%에서 10% 잠금, 그 뒤 5%씩 | `ladder` |
| 동시 신호 | 진입 점수 → 긴 봉 → 목록 순서 | `rank` |
| 비교용 동전 계좌 | 같은 신호, 같은 시각, 방향만 무작위 | `flip_twin` |

**"더 좋은 자리"의 기준(진입 점수)**
- 5년 진입 연구의 진입 강도 점수(1~5, 대시보드의 "좋은 자리" 표시와 같은 것)를 씁니다.
- 점수가 없는 신호(딥시크, 강도 정의가 없는 매매법)는 3점(가운데)으로 봅니다.
- 연구에서는 이 점수에 수익 차이가 없었습니다. 두 분 규칙이라 그대로 넣었습니다.
- 밀린 신호는 모두 기록되므로 나중에 "고른 쪽이 정말 나았나"를 확인할 수 있습니다.

### 1-1. 동시 신호 예

- 30분봉 OBV 추세형 숏 ETH와 1시간봉 V3.9 롱 BTC가 같은 순간(정각)에 떴다고 합시다.
- 점수가 높은 쪽이 들어갑니다. 같으면 긴 봉(1시간봉 V3.9)이 들어갑니다.
- 포지션이 열려 있는 동안 나온 신호는 모두 건너뜁니다("포지션 있음").

### 1-2. 매매법별 조건 (`when`, 10/17 추가)

매매법마다 "이럴 때만 거래"를 붙일 수 있습니다. 조건을 여러 개 적으면 **하나라도 맞으면** 들어갑니다. 한 조건 안의 항목은 **모두 맞아야** 합니다.

```json
{"pick": "core-N07_ICHI_CMO-30m-2", "when": [
  {"symbol": "LTCUSDT", "session": "europe"},
  {"symbol": "SOLUSDT", "side": "long"}
]}
```
위 예는 "LTC는 유럽 시간에만, SOL은 롱만"입니다.

| 항목 | 값 | 뜻 |
|---|---|---|
| `symbol` | `"SOLUSDT"` 또는 목록 | 그 코인만 |
| `side` | `"long"` / `"short"` | 롱만 / 숏만 |
| `session` | `"asia"` 09-17시, `"europe"` 17-22시, `"us"` 22-06시, `"dawn"` 06-09시 (한국 시간, 신호 봉이 닫힌 시각) | 그 시간대만 |
| `weekend` | `true` / `false` | 주말(한국 시간 토·일)만 / 평일만 |
| `btc_trend` | `"with"` / `"against"` | BTC 4시간봉 종가가 EMA(50) 위면 상승, 아래면 하락. 그 추세와 같은 방향만 / 반대 방향만. 커스텀값봇의 g1 필터와 같은 계산입니다 |

- 조건 밖 신호는 어느 계좌(합친 봇, 동전 계좌)에도 가지 않습니다. 합친 봇 DB의 `signal_log`에 `FILTERED`로 남습니다.
- BTC 4시간봉은 바이낸스에서 받습니다(4시간에 한 번). 못 받으면 `btc_trend`가 필요한 조건은 "안 맞음"으로 보고 경고를 남깁니다.

## 2. 배수 고정에서 꼭 알아야 할 것

### 2-1. 손절 방식 (두 분이 하나 고르기)

BTC 40배는 가격이 약 2.1%, 30배 알트는 약 2.7~2.8% 움직이면 강제청산입니다. 그런데 2 ATR 손절은 봉이 길수록 멀어집니다(가격 기준 가운데값: 15분 0.7%, 30분 1.0%, 1시간 1.5%, 4시간 2.3~3.3%). 그래서 고정 배수와 2 ATR 손절은 긴 봉에서 충돌합니다.

| 방식 | 설정 | 하는 일 | 진입 거절(지난 11일 실제 신호, BTC / 알트) |
|---|---|---|---|
| A. 2 ATR 그대로 | `{"mode": "atr", "atr": 2}` | 손절이 강제청산 안쪽(여유 1 ATR)에 안 들어가면 진입 안 함 | 1시간봉 9% / 33%, 4시간봉 99% / 96% |
| B. 2 ATR, 안 맞으면 당김 | `{"mode": "atr_fit", "atr": 2, "min_atr": 1}` | 들어갈 수 있는 가장 넓은 손절로 당김. 1 ATR보다 좁아야 하면 진입 안 함 | 1시간봉 0% / 3%, 4시간봉 32% / 76% |
| C. 고정 ROE -50% | `{"mode": "roe", "roe": 0.5}` | -50% ROE에서 손절. BTC는 가격 1.25%, 알트는 1.67% | 1시간봉 0% / 14%, 4시간봉 82% / 88% |
| C. 고정 ROE -60% | `{"mode": "roe", "roe": 0.6}` | BTC 1.5%, 알트 2.0% | 1시간봉 20% / 48%, 4시간봉 100% |

- 15분봉·30분봉은 어느 방식이든 거의 다 진입합니다(30분봉 알트는 A에서 7%만 거절).
- **4시간봉 매매법(예: OBV 추세형 4시간봉)은 40배·30배에서는 어느 방식으로도 대부분 진입하지 못합니다.** 4시간봉은 평소 움직임(ATR)이 커서 강제청산까지 거리가 모자라기 때문입니다. B가 가장 많이 들어갑니다.
- 손절 -%를 넓혀도 낙폭은 거의 같습니다. 낙폭을 정하는 것은 크기입니다(`docs/live1019-analysis-ko.md` 3장 "낙폭과 손절 -%").

### 2-2. 40배에서 계단 익절은 아주 짧습니다

- 순ROE +11%는 40배에서 가격 약 +0.42%(수수료 포함), 30배에서 약 +0.51%입니다.
- 그래서 이기면 금방 +10%에서 잠겨 나옵니다. 지면 2 ATR 손절은 ROE로 약 -20%(15분봉)~-60%(1시간봉 BTC)입니다.
- 지난 11일 다시 돌려 보기: 이긴 거래 평균 순ROE +11.8%, 진 거래 평균 -34.6%였습니다. 본전이 되려면 약 75% 이상 이겨야 합니다.

### 3-3. 5년에 최대한 맞춘 설정 (`deploy/combo.fitted.json`, 10/17)

두 분 요청("과거에 최대한 좋게 맞춰서 한번 돌려 보고 싶다")으로 만든 설정입니다.

- **같은 코드로 다시 확인**: 이 설정 파일을 이 봇의 엔진·조건 코드로 5년 1분봉에 다시 돌렸고, 고를 때 계산과 거래 수·승률·손익·낙폭이 똑같았습니다.
- **정직하게 알아야 할 것** (성적 숫자는 딥시크 커스텀값이 들어 있어 저장소에 적지 않습니다):
  - 이 성적은 시험이 아니라 맞춘 결과입니다. 같은 방법으로 **동전 방향(무작위)** 신호에 맞춰도 거의 비슷하게 좋아 보였습니다.

  - 그래서 앞으로도 같은 성적을 기대하면 안 됩니다. 실거래는 작은 금액과 실행기 한도(하루 $10, 낙폭 30%, 연속 6패)를 그대로 두고 돌리세요.

## 4. 두 분이 정할 것

1. **매매법 목록**: 규칙봇 기본값 6개에 더해, 커스텀값봇에서 넣을 것.
   - 이름은 커스텀값봇 화면의 매매법 번호(예: `core-N13_3OUTSIDE-30m-1`, `ds-F9_FVG-1h-1`)로 적습니다.
   - 딥시크 매매법도 넣을 수 있습니다. 다만 딥시크 신호는 실거래 안전 점검을 거치지 않은 경로입니다.
2. **손절 방식**: A / B / C (2-1).
3. **실거래 크기**(아래 6장): $400 상한(권장) 또는 증거금 = 배수%.
4. **언제 실거래로 넘어갈지**: 페이퍼로 최소 며칠 + 테스트넷 1일 이상.

## 6. 실행기가 합친 봇을 따라가게 하기

테스트넷에서 먼저 하루 이상 돌립니다(`"mode": "testnet"`, 새 db 파일). 그 뒤 mainnet으로 바꿉니다.

```json
{
  "mode": "testnet",
  "account": "COMBO@mix",
  "paper_db": "/var/lib/paperbot/combo/combo.db",
  "db": "/var/lib/paperbot/exec/executor-combo-testnet.db",
  "budget_usd": 100,
  "qty_scale": 0.1,
  "entry_source": "paper",
  "stop_from": "ratio",
  "risk": {
    "daily_max_loss_usd": 10,
    "max_drawdown_pct": 0.3,
    "max_consecutive_losses": 6,
    "max_leverage": 40,
    "max_notional_usd": 400,
    "allowed_symbols": ["BTCUSDT", "ETHUSDT", "SOLUSDT", "DOGEUSDT", "LTCUSDT", "BCHUSDT"],
    "kill_file": "/var/lib/paperbot/STOP"
  }
}
```

| 설정 | 값 | 이유 |
|---|---|---|
| `account` / `paper_db` | `COMBO@mix` / combo.db | 합친 봇 계좌 |
| `entry_source` | **paper** | signal은 계좌 하나짜리 매매법용이라 합친 봇에서는 쓰면 안 됩니다 |
| `max_leverage` | **40** | 실행기는 페이퍼 배수를 그대로 쓰고 이 값으로 낮추기만 합니다. 40이면 BTC 40배, 알트 30배 그대로 |
| `qty_scale` | 0.1 | 실거래 수량 = 페이퍼 수량 × 0.1 ($100 ÷ 페이퍼 $1,000). 페이퍼 지갑이 크게 바뀌면 다시 계산 |
| `max_notional_usd` | 400 | 한 번 진입 상한. 이 값이 실제 크기를 정합니다 |
| `db` | 새 파일 | DB 파일 하나는 계좌 하나만 기록합니다. 기존 실행기 db를 쓰면 거부됩니다 |

**크기 두 가지**
- **$400 상한(권장)**: BTC든 알트든 한 번에 약 $400입니다. 배수는 증거금만 바꿉니다(40배면 $10, 30배면 $13). 손절 한 번은 보통 $3~8입니다.
- **증거금 = 배수%(BTC $1,600, 알트 $900)**: `max_notional_usd`를 1600으로 올립니다. 다만 실행기가 손절 한 번 손실을 "오늘 남은 하루 한도와 계좌의 15% 중 작은 값"으로 줄입니다. 그래서 $100에서는 한 번 최대 약 $15이고, 낙폭 30% 멈춤까지 손절 2번이면 닿습니다.

## 7. 확인과 멈춤

- 매일 확인할 것과 바로 멈출 일은 `docs/live1019-analysis-ko.md` 5장과 같습니다. 대시보드 대신 `combo status`를 봅니다.
- 비상 정지: `sudo touch /var/lib/paperbot/STOP`. 실행기가 모두 닫고 멈춥니다. 합친 봇 페이퍼는 계속 돕니다.
- 합친 봇을 끄기: `sudo systemctl stop paperbot-combo`.
  - 실행기가 따라가는 중에 끄면 페이퍼 상태가 5분 넘게 멈춥니다. 그러면 실행기는 새 진입을 하지 않습니다.
  - 열린 포지션은 거래소 손절이 지킵니다. 그래도 끄기 전에 실행기를 먼저 STOP하세요.

## 8. 테스트로 확인한 것 (tests/test_combo.py)

- 기본값·커스텀값·커스텀값봇 번호로 매매법 목록 만들기, 잘못된 목록 거부.
- BTC 40배·알트 30배, 증거금 배수%, 15% 손실 상한(줄이기/거부), 강제청산 안쪽 손절, 세 가지 손절 방식.
- 동시 신호: 점수 → 긴 봉 → 목록 순서. 포지션 중 신호는 건너뜀.
- 규칙봇 DB를 흉내 낸 파일로 끝까지 실행:
  - 신호 봉이 닫힌 다음 분에 기준 가격으로 진입, 손절 청산
  - 늦은 신호 거부, 재시작 뒤 이어서 돌기
  - 동전 계좌도 같은 신호를 받음
- **실행기(코드 수정 없음)가 합친 봇 계좌를 가짜 거래소에서 BTC 40배로 따라 들어가고, $400 상한을 지킴.**
- **커스텀값 계산에 기본값을 넣으면 규칙봇과 똑같은 신호**가 나옴(규칙봇 36개 중 4개, 딥시크 8개, 여러 봉에서 하나도 안 틀림). 커스텀값 매매법이 규칙봇과 같은 차트·같은 계산으로 돈다는 뜻입니다.
- 조건(`when`): 잘못 적은 조건 거부, 한국 시간 시간대·주말 경계(금 23:59는 평일, 토 00:00은 주말, 일 23:59까지 주말), BTC 4시간 추세가 커스텀값봇 g1과 같은 값, 4시간마다 한 번만 받기, 못 받으면 "안 맞음". 조건 밖 신호는 합친 봇·동전 계좌 어디에도 안 감(`FILTERED` 기록).
