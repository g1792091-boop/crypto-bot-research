# 추세판단 봇 (10/21)

두 분 결정(10/21): "추세형 매매법은 진입 안 하고 추세만 보는 거고, 1시간봉 추세 보고 30분봉에서 진입 … 1시간봉 진입은 4시간봉 추세",
"실거래 바로 돌릴꺼고 바이비트봇이랑 woo pro봇 둘다 -50%로 할꺼고 … 나머지는 다 추천대로".

바이비트와 WOO X Pro 실행기가 **같은 페이퍼 봇 하나(−50%)** 를 따라갑니다. 그 페이퍼 봇이 지금의 "규칙봇 15" 자리(`paperbot-combo`,
`/etc/paperbot/combo.json`, 기록 `live-ac.db`)에서 새 규칙으로 바뀝니다. 기록 파일이 같아서 실거래 사이트·텔레그램 감시·아침 점검은
설정을 따로 바꾸지 않아도 새 봇을 그대로 읽습니다. 계좌(지갑 $1,000 기준)와 지난 기록은 이어집니다.

코드: `paperbot/trendjudge.py`(추세 판단과 진입 전 검사), `paperbot/trendbot.py`(되돌림 진입, 감독),
설정 `deploy/combo.trend.json`, 바꾸는 도구 `deploy/trend_switch.py`.

## 1. 역할

| 역할 | 매매법 | 하는 일 |
|---|---|---|
| 판단만 (진입 안 함) | V3.9 · EMA·DMI·ADX · OBV 추세형 · 일목·AO | 끝난 상위 봉의 **지표 상태**로 추세 판단 |
| 30분 진입 (끝난 1시간봉 추세) | 일목·%R · PSAR·POC · 구조 돌파 BOS · 시가 범위 돌파 ORB · MACD·시가범위 · CMO 샌드위치 30분 · EMA9·초피(숏만) | 1시간 추세와 같은 방향 신호가 하나라도 나오면 진입 후보 |
| 1시간 진입 (끝난 4시간봉 추세) | FVG 되돌림 · 뒤집힌 FVG · CMO 샌드위치 1시간 | 4시간 추세와 같은 방향 신호가 하나라도 나오면 진입 후보 |

판단 4개의 계산은 실거래 사이트 각 매매법 차트 화면의 선과 **같은 함수·같은 숫자**입니다(시험으로 봉마다 같은지 확인).

## 2. 규칙 (설정 파일의 숫자 그대로)

- **추세 판단:** 4개 중 3개 이상 같은 쪽이면 상승/하락, 아니면 보류(진입 안 함).
  V3.9 = 슈퍼트렌드(10·3) 방향 · EMA·DMI·ADX = 종가 vs EMA20 그리고 +DI vs −DI · OBV = OBV vs 30봉 평균 · 일목·AO = 구름 위/아래 그리고 AO 0 위/아래.
- **힘:** 상위 봉 ADX 20 이상. 40 넘고 꺾이면 끝물 → 진입 안 함. ADX가 높다고 들어가지는 않습니다.
- **흔들림 방지:** 1시간은 끝난 봉 2개 연속 같은 판단, 4시간은 1개.
- **진입 전 검사(모든 진입 매매법):** 상위 봉 EMA20에서 진입 방향으로 1.5 ATR 넘게 멀면 안 함 · 진입 봉 EMA20에서 1.5 ATR 안 ·
  RSI 롱 70 미만 / 숏 30 초과 · 추격 막기(24시간 위 10% · 7일 위 20% 안 롱 금지, 숏 반대) 전체 · 돌파형(BOS, ORB, MACD·시가범위)은
  상위 ADX 30 미만이고 오를 때(추세 초입)만.
- **진입 방식(되돌림):** 검사를 통과한 신호는 바로 들어가지 않고, 진입 봉 하나(30분 또는 1시간) 동안 **0.25 ATR 유리한 가격**을 기다립니다
  (신호 봉이 2 ATR 넘는 장대봉이면 0.5 ATR). 닿으면 다음 분에 진입(실행기는 그때 시장가로 따라감), 안 오면 버립니다.
  신호가 나온 그 1분은 보지 않고 다음 1분부터 봅니다(그 1분봉에는 신호 가격을 잡기 전 움직임이 섞여 있어서). 기다림은 진입 봉이
  끝나기 1분 전까지(신호 기록의 "…까지"가 그 시각).
- **동시 신호:** 점수로 고름 = 판단 강도(4/4면 +1) + 자리(진입 봉 EMA20에 가까울수록 +1까지) + 그 매매법 최근 10번 승률(3번 미만이면 0).
- **쉬기: 없습니다.** 손실 뒤 매매법 쉬기·코인 쉬기는 10/21 밤 두 분 결정("쉬기는 빼주고")으로 뺐고(설정 `member_losses: null`,
  `coin_pause_h: null`), 하루 손실 한도도 없습니다(10/21 "10번은 없애고"; 설정 `daily_loss: null`). 진입을 막는 시간은 원래 규칙인
  주말·경제 발표 앞뒤 30분·나스닥 개장 앞뒤 30분뿐입니다(아래 3번).
  (손실은 손절뿐 아니라 빠른 청산·감독 청산의 손실도 셉니다. 새 봇이 켜진 뒤의 거래만 셉니다.)
- **들어간 뒤(감독, 1분마다, 첫 잠금 전까지만):**
  - 상위 봉(1시간 또는 4시간)이 진입 뒤 끝난 봉에서 **반대 판단(3/4)** 이면 청산 → "감독 청산(추세 판단 뒤집힘)"
  - ~~진입 봉 4개 안에 첫 잠금(+10%)을 못 가면 청산 → "감독 청산(시간 정리)"~~ — **10/21 밤 두 분 결정("시간청산 빼줘")으로
    없음**(설정 `time_bars: null`). 첫 잠금 전에는 손절(−50%)·추세 뒤집힘·빠른 청산만 지킵니다.
  - 같은 매매법 반대 신호의 빠른 청산(첫 잠금 전)도 그대로 둡니다.
  - 청산 뒤 반대로 갈아타지 않습니다.
  - 동전 쌍둥이(비교용, 방향은 무작위)는 자기 방향이 아니라 **봇이 진입할 때 본 추세가 뒤집힐 때** 같이 닫힙니다(같은 순간, 공정한 비교).
- **실행기:** 감독 청산은 빠른 청산처럼, 실거래 포지션에 **자기 잠금이 없을 때만** 따라 닫습니다(잠금이 있으면 거래소 기준 계단 익절로 계속).

## 7. 서버 순서 (한 줄씩 붙여 넣기)

**두 실행기와 페이퍼 봇 모두 포지션이 없을 때만** 3번부터 합니다. 1~2는 언제 해도 됩니다.

1. 코드 받기: `cd /root/crypto-bot-research` → `git pull`
2. 포지션 확인 (셋 다 포지션 없음이어야 함):
   ```
   sudo -u paperbot-exec /opt/paperbot/venv/bin/python -m paperbot.executor status --db /var/lib/paperbot/exec/executor-bybit-live.db
   ```
   ```
   sudo -u paperbot-exec /opt/paperbot/venv/bin/python -m paperbot.executor status --db /var/lib/paperbot/exec/executor-wooxpro-live.db
   ```
   ```
   sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/live-ac.db
   ```
   실행기 둘은 `포지션: null`, 페이퍼는 `COMBO@mix: … 포지션 없음`.
3. 두 실행기 끄기: `systemctl stop paperbot-executor paperbot-executor-mexc`
   (끈 뒤 2의 실행기 status를 한 번 더 보고 `포지션: null`인지 확인. 거래소 앱에서도 열린 포지션·남은 주문이 없는지 봅니다.)
4. 무엇이 바뀌는지 보기: `python3 deploy/trend_switch.py`
   - `/etc/paperbot/combo.json: 규칙봇 15 → 추세판단 봇 · 매매법 14개 → 진입 10개 …`
   - `/etc/paperbot/executor-mexc.json (WOO X Pro): paper_db /var/lib/paperbot/combo/live15-mexc.db → /var/lib/paperbot/combo/live-ac.db`
   - `/etc/paperbot/executor.json (바이비트): paper_db 그대로 /var/lib/paperbot/combo/live-ac.db`
5. 바꾸기: `python3 deploy/trend_switch.py --write` (예전 파일은 `….before-trend-<시각>`으로 남음)
6. 새 설정 확인 (새 코드로): `cd /root/crypto-bot-research && /opt/paperbot/venv/bin/python -m paperbot.combo check-config --config /etc/paperbot/combo.json`
   → "추세 판단: …", "진입 전 검사: …", 1~10번 매매법, 마지막 줄 `준비됨`. (`[문제]`가 있으면 여기서 멈추고 알려 주세요.)
7. 설치: `cd /root/crypto-bot-research && bash deploy/install.sh`
   (페이퍼 봇이 새 코드·새 설정으로 다시 켜짐. 텔레그램 시작 알림에 "추세 판단(30분→1시간·1시간→4시간)·되돌림 진입·감독 청산"이 보입니다.)
8. 1~2분 뒤 실거래 사이트 첫 화면 **관제**의 추세 지도에 코인별 판단이 보이는지 확인.
9. 두 실행기 켜기: `systemctl start paperbot-executor paperbot-executor-mexc`
10. 확인: 2의 실행기 status 두 줄. 맨 아래 시작 기록에 `(페이퍼 DB /var/lib/paperbot/combo/live-ac.db)`가 **둘 다** 보이면 됩니다.

되돌리기(옛 규칙봇 15로): 두 실행기·페이퍼 포지션 없음 → 3 → 각 파일을 `.before-trend-<시각>` 사본으로 `cp` → 7 → 9.

## 8. 옛 규칙 비교 (선택, 돈 안 듦)

- 옛 규칙봇 15(−50%)를 **그림자 봇**으로 따로 돌리면, 새 봇과 같은 시장에서 옛 규칙이 어땠을지 공짜로 비교할 수 있어요(주문 없음,
  텔레그램 없음, 실거래 사이트 그림자 탭): `systemctl start paperbot-combo-shadow@rule15`
- 옛 −35% 페이퍼 봇(`paperbot-combo-mexc`)은 이제 따라가는 실행기가 없습니다. 비교용으로 그냥 둬도 되고, 끄려면:
  `systemctl stop paperbot-combo-mexc`

## 9. 꺼도 되는 것 / 끄면 안 되는 것 (10/21 밤 질문)

- **끄면 안 됨: 규칙봇 36 (`paperbot-live3`).** 이름은 "규칙봇"이지만 추세판단 봇이 쓰는 신호(멤버 10개)와 1분봉을 만드는
  공장입니다. 끄면 추세판단 봇도, 따라가는 두 실행기도 멈춥니다. 리셋·중지 금지.
