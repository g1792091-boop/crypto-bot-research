## 0. 요약

1. **세 문서는 "헤지펀드식 AI 트레이딩 조직"을 일반론으로 정리한 AI 답변입니다.** 주식·옵션·섹터 기준으로 쓰였습니다. 코인 5종목 선물 봇에 그대로 옮기면 쓸 수 없는 부분이 많습니다. 외인·기관 순매수, ETF 자금, 섹터 로테이션, VIX, 옵션 만기, 09:30 분봉 플레이북 등이 그렇습니다.
2. 그래도 **쓸 만한 것이 분명히 있고**, 우리 설계와 방향이 같은 부분이 많습니다.
   - 같은 방향: 샌드박스 → 섀도 → 소액 실전, 자기수정과 자기승인의 분리, 인간 최종 권한, 과최적화 검정
   - 새로 받아들일 것:
     - 유사 패턴·시나리오 엔진
     - 크로스에셋(DXY·나스닥·금리) 선행성
     - 오더플로(CVD·오더북 불균형)
     - 멀티 타임프레임 일치도
     - 사이징 공식 (위험 %, 청산 버퍼 3×ATR, 포트폴리오 히트)
     - LLM 가설 생성의 가드레일
     - 자기수정 안전장치표 (변경 폭 ±20%, L3 이상 인간 승인)
     - 성과 지표 8종
3. **이미지 속 "전략 에이전트"는 LLM이 아니라 코드여야 합니다.** 추세추종 Agent, 평균회귀 Agent 같은 것들입니다. 매매 판단을 매번 LLM에 맡기면 느리고, 매번 결과가 달라지고, 백테스트할 수 없습니다. 우리 설계에서는 매매법 = Python 코드 봇, LLM = 분석·계획·검증·복기입니다. CIO, Arbitration, Execution, Data Agent도 대부분 코드와 사람이 맡습니다(§2 대응표).
4. **조직 변경:** LLM 에이전트는 16명에서 **17명**이 됩니다. **유사 패턴·시나리오 분석가**(3단계부터)를 추가하고, 기존 6명의 업무를 확장합니다.
5. **새로 요청하신 분석:** 요일·주말·시간대별 성과 분석을 추가합니다(§4). 매매법 확정 전이라도 **다른 채팅의 백테스트 거래 기록으로 바로 계산할 수 있습니다.**
6. **50배 교차 + 최소 10% 익절은 먼저 정리해야 할 위험이 큽니다(§5).** 이미지 속 자료도 "고정 레버리지 금지, 청산가는 3×ATR 이상 떨어뜨릴 것, 1회 위험 0.25~1%"라고 말합니다.

## 1. 문서별 핵심 평가

### 문서 1: 헤지펀드 AI + 차트 유사도 시스템
| 항목 | 평가 | 코인 선물 봇 적용 |
|---|---|---|
| 계층형 조직(CIO → PM → 데스크 → 피더) | 개념은 맞음 | 규모가 2인 + 5종목이라 계층은 얇게 둔다. CIO와 PM은 사람 2명 + 전략가 + 리스크 책임자 |

| 유사도 엔진(DTW·k-NN, regime 필터, forward return **분포**) | **부분 채택** | "지금과 비슷했던 과거 이후 가격이 어떻게 움직였나"를 분포로 제공하는 **정보원**으로 쓴다. 매매 신호로 쓰려면 매매법처럼 검증을 통과해야 함 |

| Vol targeting, CVaR, Portfolio Heat | Heat는 **채택**(손절 위험 합 한도), 나머지는 **보류** | CVaR은 표본이 쌓인 뒤 |
| 청산 버퍼 3×ATR | **채택** | "손절가와 청산가 정합성 검사" 기준값으로 사용 |
| 유동성 기반 레버리지 캡 | **채택(간소화)** | 종목별 레버리지 구간(leverageBracket) 기준으로 상한 |
| "레버리지 동적 조절, 고정 레버리지 금지" | **채택** | 레버리지 **설정값**은 50배여도 실제 노출은 위험 기반 사이징으로 결정(§5) |
| 추천 모듈 14개 | 항목별 §3 참조 | |
| 주의사항 (과최적화, look-ahead, 생존편향, 스누핑, 꼬리위험, 상관 1 수렴, 킬스위치, 규제, 감사 로그) | **전부 이미 반영** | 생존편향은 대형 5종목이라 영향이 작음 |

### 문서 3: 자기진화형 3종
| 에이전트 | 평가 | 우리 설계 대응 |
|---|---|---|
| ① Strategy Discovery (GP·심볼릭·RL·AutoML·LLM·ES·MCTS) | **LLM 가설 생성만 제한 채택.** 자동 대량 탐색(GP·RL·AutoML)은 **보류** | 5종목은 서로 상관이 높고 데이터가 적어, 대량 탐색은 우연한 패턴만 찾는다(문서 스스로 "발굴 전략 대부분은 우연"이라고 적음). 전략 연구원이 월 5개 이하로 가설을 **경제적 근거와 함께** 내고, 모든 시도는 레지스트리에 기록해 DSR·PBO 다중검정에 반영 |
| 발굴 가드레일 (탐색공간 제한, DSR·PBO, Bonferroni·FDR, 경제적 타당성, 비용, look-ahead) + 파이프라인 (상관 < 0.5 필터, 페이퍼 3개월, 인간 승인) | **전부 채택** | 전략 검증관의 도입 관문에 추가 |
| ② Self-Improvement (L1~L5, 트리거, 샌드박스·섀도·롤백·±20%·L3+ 인간 승인·감사) | **안전장치표 채택. 자동 수정은 L1(파라미터) 제안까지만** | 개선 설계자 + 전략 검증관 + 사람 승인. Demo 동안에는 L1도 자동 반영하지 않고 도전자로만 운영. L4(가중치)는 Go-live 뒤, L5(학습 알고리즘 교체)는 해당 없음 |
| 수정 트리거 (Sharpe -30%, KS-test 드리프트, regime 전환, 상관 붕괴, 정기) | **채택(복기 계기로)** | 트리거는 "자동 수정"이 아니라 "복기·검증 시작" 신호 |
| ③ Autonomous Execution (L0~L4) | **개념 채택, 주체 변경** | 우리 봇은 "승인된 매매법 코드가 자동 실행"하는 **L3를 코드로** 한다. LLM은 **L0(정보만)** 이다. L4(전략 수정까지 자동)는 금지 |
| 자동 복구표 | **대부분 채택, 두 가지 수정** | ① "API 장애 → 백업 브로커 전환"은 해당 없음(단일 거래소). 대신 거래소 측 보호 손절에 의존하고 신규 진입을 중지 ② "연결 끊김 → Kill switch(전량 청산)"는 위험하다. 끊긴 상태에서는 청산 주문도 못 낸다. 거래소에 걸어 둔 보호 손절이 지키고, 재연결 후 대조 → 사람 호출 |
| 필수 통제 (pre-trade check, post-trade reconciliation, rate limit, circuit breaker, kill switch, human override) | **전부 이미 반영** | |
| 3중 방어선, 절대 규칙, 금지 사항 | **전부 채택** | "승인 없이 레버리지 변경 금지"는 §5와 연결 |
| 기술 스택 (Kafka·TimescaleDB·Airflow·Grafana·MLflow 등) | **대부분 과잉** | 2인 프로젝트: SQLite/Parquet, systemd 타이머, 텔레그램 + Lightweight Charts, Git. ccxt 대신 **바이낸스 공식 Python 커넥터** 우선 검토. Demo Trading·Algo 주문 지원 여부를 먼저 확인 |

## 3. 조직 v3: 변경 사항

### 3-1. 신규 (1명)
**유사 패턴·시나리오 분석가** `analog-scenario-analyst` (① 시장분석팀, **3단계부터**, Sonnet)
- **코드 엔진**
  - 5종목 × 매매 TF별로 최근 N봉을 정규화(수익률 z-score, ATR 스케일)합니다.
  - 과거에서 k-NN/DTW로 유사 구간 k개를 찾습니다. 필터는 장세·변동성 구간입니다.
  - 이후 수익률 분포를 계산합니다.
    - 기간: 해당 TF 기준 1·3·6·12봉
    - 분포: p10, p25, p50, p75, p90
    - 상승·하락·횡보 확률
  - 표본이 30건 미만이면 "판단 없음"을 반환합니다.
- **분석가 역할**
  - 아침 브리핑에서 분포를 해석합니다. 예: "비슷했던 과거 42번 중 4시간 뒤 p50은 +0.3%, p10은 -1.1%".
  - 복기 때 "그 거래는 과거 분포상 흔한 결과였나"를 평가하는 **기준률**을 제공합니다.
- **하지 않는 것**
  - 매매 신호를 내지 않습니다. 패턴매칭을 매매법으로 쓰려면 전략 연구원 → 전략 검증관 절차를 밟습니다.
  - "시각적 유사 ≠ 통계적 유사"라는 문서의 경고를 따릅니다.
- **시작 시점**: 1분봉 저장소와 장세 판정기가 생긴 뒤(3단계). OOS에서 분포가 실제 결과를 잘 보정하는지(캘리브레이션) 확인하고 나서 브리핑에 넣습니다.

## 4. 요일·주말·시간대 성과 분석 (신규)

### 4-1. 무엇을 보나
| 구분 | 구간 (KST) | 이유 |
|---|---|---|
| 요일 | 월~일 7개 | |
| 평일 / 주말 | 주말 = 토 09:00 ~ 월 09:00 KST (UTC 기준 토·일) | 주말은 거래량이 적고 기관이 쉼. CME 비트코인 선물도 쉼 |
| 세션 4구간 | 아시아 09~16 / 유럽 16~22 / 미국 22~05 / 새벽 저유동 05~09 | 시간대별로 유동성과 변동성 성격이 다름 |
| 특수 창 | ① 미국 증시 개장 ±1시간 (서머타임 22:30, 해제 23:30) ② 미국 경제지표 발표 (21:30 / 22:30) ③ 펀딩 정산 ±10분 (보통 09·17·01시, 종목별 간격은 API 확인) ④ 월요일 아시아 개장 · CME 주말 갭 ⑤ 월말·분기말 | 이벤트성 변동 |
| 24시간 × 7요일 히트맵 | 168칸 | **설명용으로만** 봅니다(판정에 쓰지 않음) |

**기준 시각은 진입 시각**입니다. 보유 중 주말을 넘긴 거래는 "주말 보유" 플래그로 따로 봅니다.

### 4-2. 칸마다 계산하는 지표 (코드)
- 거래 수, 승률, 평균 R, 기대값, Profit Factor, 최대 낙폭
- 평균 슬리피지·스프레드: 시간대별 **체결 비용 차이**도 봅니다
- 익절·손절 도달률, 평균 보유 시간
- 손실 태그 분포 (예: 새벽에 가짜 돌파가 많은가)

### 4-3. 통계 주의 (중요)
- **칸이 많을수록 우연히 좋아 보이는 칸이 생깁니다.** 168칸이면 운으로도 몇 칸은 크게 좋거나 나빠 보입니다. 그래서 판정은 **세션 4구간 × 평일/주말 = 8칸**으로 시작합니다. 칸마다 최소 30건 이상일 때만 신뢰구간을 붙여 표시합니다.
- **매매법×TF별로 따로 봅니다.** 5분봉 매매법과 4시간봉 매매법의 "좋은 시간대"는 다를 수 있습니다.
- **Demo 8주 데이터만으로는 부족합니다.** 다른 채팅의 **다년 백테스트 거래 기록**으로 먼저 계산하고, 연도별로 같은 결과가 반복되는지 봅니다. 한 해만 좋은 시간대는 우연일 가능성이 큽니다.
- 서머타임 때문에 미국 세션이 1시간 이동합니다. 미국 관련 창은 뉴욕 시각 기준으로 계산합니다.

### 4-4. 결과를 어떻게 쓰나
- 성과 분석가: 주간·월간으로 표를 해석합니다.
- 개선 설계자: "시간 필터" 가설을 만듭니다. 예: "매매법 A는 새벽 05~09시 기대값이 신뢰구간상 음수 → 그 시간 신규 진입 금지".
- 전략 검증관: 전체 기간·연도별·OOS로 검증합니다.
- 두 분 승인 후 도전자로 운영합니다.
- 시간 필터도 **매매법 수정**이므로 개선 루프를 똑같이 거칩니다.

## 5. 50배 교차 레버리지 + "최소 10% 익절": 먼저 정리해야 할 것

> 수치는 바이낸스 USDⓈ-M VIP0 기본 수수료(메이커 0.02%, 테이커 0.05%)와 대략적인 유지증거금률을 기준으로 한 **근사치**입니다. 실제 값은 계정의 `/fapi/v1/commissionRate`와 종목별 `/fapi/v1/leverageBracket`으로 확인해야 합니다.

### 5-1. "10%"가 무엇 기준인지에 따라 전혀 다른 매매가 됩니다
| 해석 | 50배에서 실제 가격 움직임 | 문제 |
|---|---|---|
| 화면 ROE 10% | **가격 0.2%** | 왕복 테이커 수수료만 명목의 0.1% = **ROE 5%**. 익절 10% 중 절반이 수수료입니다. 슬리피지까지 더하면 남는 게 거의 없을 수 있습니다 |
| 가격 10% | ROE 500% | 50배를 계좌 전체로 쓰면 **가격이 약 1.5~2% 반대로 가는 순간 청산**됩니다. 10%에 닿기 전에 청산될 가능성이 매우 큽니다 |

→ **두 해석 모두 그대로는 위험합니다.** 어느 쪽인지 알려 주시면 청산 실험실로 백테스트 거래에 직접 적용해 보겠습니다.

### 5-2. "50배 교차"의 실제 의미
- **교차 마진에서 청산을 결정하는 것은 레버리지 설정값이 아니라 실제 노출입니다.** 실제 노출 = 전체 포지션 명목가 ÷ 계좌 잔고입니다.
  - 설정 50배로 계좌 전액만큼(1배) 포지션을 잡으면 실제 노출은 1배입니다.
  - 계좌 50배만큼 잡으면 가격 약 2%(유지증거금 빼면 1.5% 안팎) 역행에 **계좌 전체가 청산**됩니다.
- **교차는 모든 포지션이 한 지갑을 공유합니다.** 5종목 × 여러 매매법이 한 계좌에 있으면, 한 포지션의 큰 손실이 다른 포지션까지 함께 청산시킬 수 있습니다. 코인은 급락할 때 5종목이 같이 움직입니다(문서 1: "위기 시 상관 1 수렴").
- 종목마다 최대 레버리지와 유지증거금 구간이 다릅니다. SOL·LTC·BCH가 50배를 허용하는지, 그 구간의 유지증거금이 얼마인지 API로 확인해야 합니다.

### 5-3. 권장 운용 (이미지 속 자료의 규칙과 같음)
1. **레버리지 설정은 50배로 두더라도, 포지션 크기는 "1회 위험 = 계좌의 0.25~1%" 공식으로 정합니다.** 포지션 크기 = 위험 금액 ÷ 손절폭입니다(문서 1 2-4). 그러면 손절폭이 좁을 때만 실효 레버리지가 올라가고, 손절하면 계좌의 정해진 %만 잃습니다.
2. **계좌 단위 한도를 코드로 고정합니다.**
   - 전체 실효 레버리지 상한 (예: 5~10배, 두 분이 정함)
   - 동시 손절 위험 합 상한 (포트폴리오 히트, 예: 계좌 3~5%)
   - 계좌 전체 청산가까지 거리 ≥ 3×ATR (문서 1 청산 버퍼)
3. **진입 전 검사:** 손절이 청산가보다 충분히 안쪽인지 확인하고, 아니면 진입을 거부합니다(이미 필수 항목).
4. **레버리지 설정 변경은 사람 승인**만으로 합니다(문서 3 절대 규칙).
5. 매매법끼리 청산 위험을 분리하고 싶다면, 매매법(또는 종목)마다 **서브계정을 나누는 방법**도 있습니다. Demo에서 서브계정을 지원하는지는 미확인입니다.

### 5-4. 익절 방식은 데이터로 정합니다
- 구조 익절 vs 고정 익절(10% 등) vs R배수 vs 트레일링 vs 분할 익절은 이미 설계한 **청산 실험실**로 비교합니다(`docs/trade-review-system.md` B장).
- 다른 채팅의 백테스트 거래 기록(진입 시각·가격·손절)과 1분봉만 있으면 **Demo 전에 바로** 계산할 수 있습니다.
- 결론은 매매법×TF마다 따로 냅니다. 5분봉과 4시간봉의 적정 익절은 다릅니다.
- 익절 규칙은 가격·R·ATR로 정의하고, ROE는 화면 표시용으로만 씁니다. 그래야 레버리지를 바꿔도 익절 가격이 흔들리지 않습니다.
