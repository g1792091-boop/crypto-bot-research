두 분 결정(10/24): "실거래 해야된다니까". 두 번째 WOO X Pro 계정(WOO X Pro 2)이 **10/26(월)부터** 이 매매법으로 거래합니다.
설치는 **10/25(일)** 에 합니다. 규칙은 10/24 밤 두 분이 최근 19일 기록을 보고 고른 구조입니다(2장).

- 지금 돌고 있는 봇은 **아무것도 안 바뀝니다.** 추세판단 봇(바이비트·WOO X Pro 실행기가 따라감), VWAP 개선판(딥코인 실행기)은 그대로입니다.
- 이 문서의 1~6장과 8장은 **페이퍼 봇** 이야기입니다. 실거래 실행기는 7장에 있습니다.

## 2. 규칙 (설정 파일 `deploy/combo.friend.json` 그대로)

### 신호: 15분봉이 끝날 때마다, 6개 코인 모두

| | 롱 | 숏 |
|---|---|---|
| 1 (15분봉) | EMA21이 EMA52 위 | EMA21이 EMA52 아래 |
| 2 (15분봉) | RSI26이 50 위 | RSI26이 50 아래 |
| 3 (15분봉) | ROC9이 0 이하에서 0 위로 (앞 봉 ≤ 0, 이 봉 > 0) | ROC9이 0 이상에서 0 아래로 |
| 4 (상위 봉) | 끝난 1시간봉 **또는** 끝난 4시간봉의 ROC9이 0 위 | 끝난 1시간봉 또는 끝난 4시간봉의 ROC9이 0 아래 |

- 네 가지가 모두 맞으면 신호입니다. 1시간봉·4시간봉은 ROC9만 보고, 둘 중 하나만 맞아도 됩니다.
- 1시간봉·4시간봉은 그 15분봉이 끝난 순간까지 **이미 끝난 봉**만 봅니다. 15분봉이 정시(예: 10:00)에 끝나면 같은 시각에 끝난 1시간봉을 봅니다.
- 지표는 연구와 같은 계산(저장소 지표 라이브러리)이고 종가로 계산합니다. 봉은 한국 시간과 상관없이 UTC 기준입니다(15분봉 00·15·30·45분,
  4시간봉 01·05·09·13·17·21시 KST에 끝남).
- 설정 이름: `"members": [{"strategy": "FRIEND_ROC", "tf": "15m"}]` (`"higher"`를 안 적으면 이 규칙 `"roc_any"`).
- 4번은 설정으로 바꿀 수 있지만 **설정 파일에는 넣지 않았습니다**: `"higher": "rsi_roc_all"`(1시간봉과 4시간봉 둘 다 RSI26·ROC9이 같은 쪽),
  `"higher": "rsi_roc_1h"`(끝난 1시간봉 하나만 RSI26 > 50 그리고 ROC9 > 0, 4시간봉은 안 봄. 10/24 밤 한 시간 동안 정했던 규칙).

### 진입: 신호가 나오면 차례로 확인

| 순서 | 확인 | 걸리면 | 설정 이름 |
|---|---|---|---|
| 1 | 한국 시간 토·일요일 | 진입 안 함 | `no_weekend` |
| 2 | 미국 경제 발표 앞뒤 30분 | 진입 안 함 | `macro_blackout_min` |
| 3 | 나스닥 개장 30분 전 ~ 30분 후 | 진입 안 함 | `us_open_pre_min`, `us_open_pause_min` |
| 4 | 이미 포지션이 있음 | 건너뜀 | (항상) |

- 다른 조건(4시간 ADX, 거래량 등)은 없습니다(`adx_gate`, `quiet_gate` 끔).
- 통과하면 신호 봉이 끝난 다음 1분 시가에 시장가로 들어갑니다. 같은 분에 신호가 겹치면 BTC → ETH → SOL → DOGE → LTC → BCH.
- 들어가지 않은 신호와 이유는 기록에 남습니다(`status` 명령의 "진입 안 한 신호(이유별)").

### 청산

| 항목 | 내용 | 설정 이름 |
|---|---|---|
| 손절 | 순ROE −50%(수수료·슬리피지 포함). 35배에서 진입가부터 가격 약 1.29%(= 50% ÷ 35 − 왕복 비용 0.14%) | `stop`: `{"mode": "roe", "roe": 0.5, "net": true}` |
| 계단 익절 | 순ROE(수수료 뺀 값) 12% → 10% 잠금, 17% → 15%, 22% → 20%, 이후 5%씩 | `ladder`: 첫 잠금 0.10, 간격 0.02, 단계 0.05 |
| 보유 한도 · 반대 신호 청산 | 없음 | `max_hold_bars` null, `early_exit` null |

- 손절 자리는 들어갈 때 정하고 **옮기지 않습니다**. 계단이 잠기면 그 잠금 자리로만 올라갑니다.
- 페이퍼의 손절은 봇이 본 진입 가격(신호 직후 읽은 호가, 못 읽으면 진입 분 시가)에서 약 1.29%입니다. 연구와 같은 방식이고,
  페이퍼는 들어갈 때 미끄러짐 0.02%를 따로 더해서 계산합니다(체결가에서 보면 약 1.31%). 왕복 비용은 페이퍼가 쓰는 테이커 수수료로
  정해서, 수수료가 바뀌면 0.01%p쯤 달라집니다. 실거래(WOO X Pro 2)의 손절은 실행기가 **자기 체결가에서** 잽니다(7장).

### 크기

- 잔고의 40%를 증거금으로, 35배(`margin` 0.4, `leverage` 35). 손절 한 번이면 계좌 약 −20%, 두 번 연속이면 약 −36%입니다.
- 페이퍼는 1,000달러로 시작합니다.
- 손절 한 번 최대 손실 `max_loss_frac` 0.25: 손절이 계좌 약 20%라 보통 거래의 수량을 줄이는 일이 없습니다. ATR 여유 `liq_buffer_atr` 0
  (손절 자리를 ATR로 따지지 않음). 동전 쌍둥이 계좌(비교용, 따로 도는 계좌)도 켭니다.
- **돈이 커지면:** 바이낸스는 크기가 커지면 그 구간에서 쓸 수 있는 최대 배수가 낮아집니다. 35배가 안 되는 크기가 되면 진입은 하되
  수량을 35배가 되는 크기까지 줄입니다. 페이퍼 지갑 기준으로(크기 = 지갑 × 0.4 × 35 = 지갑의 14배):

  | 코인 | 수량을 줄이기 시작하는 크기 | 페이퍼 지갑 |
  |---|---|---|
  | LTC, BCH | 16만 달러 | 약 11,400달러 |
  | DOGE | 75만 달러 | 약 53,600달러 |
  | SOL | 100만 달러 | 약 71,400달러 |
  | BTC, ETH | 1,200만 달러 | 약 86만 달러 |

  100달러~500만 달러 사이 어느 지갑에서도 거절되는 진입은 없습니다(손절 1.29%가 늘 강제청산 가격 안쪽,
  `research/friendroc/frlive_parity3.json`의 `tiers`). 다만 크기가 커질수록 손절과 강제청산 사이가 좁아집니다: 시작 크기에서 BTC·ETH 약
  1.15%, SOL·LTC·BCH 약 1.05%, DOGE 약 0.9%이고, 수량을 줄이기 시작하는 크기에서 LTC 약 0.26%(숏 0.21%), BCH·DOGE 약 0.4%입니다.
  봇은 이 사이가 0.2%보다 좁으면 그 진입을 건너뛰고 알립니다(손절을 옮기지 않음). LTC 숏은 지갑 약 11,400달러부터 이 선에 가깝습니다.

## 4. 일요일 순서 (서버, 한 줄씩 붙여 넣기)

### A. 설치 — 추세판단 봇 페이퍼에 포지션이 없을 때

`install.sh`는 코드를 바꾸는 동안 규칙봇·페이퍼 봇들을 잠깐 껐다 켭니다(실행기는 건드리지 않음). 그래서 페이퍼 포지션이 없을 때 합니다.

```bash
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/live-ac.db
```

- `COMBO@mix: … 포지션 없음`이면 다음 줄로. 포지션이 있으면 닫힐 때까지 기다렸다가 다시.

```bash
cd /root/crypto-bot-research && git pull && sudo bash deploy/install.sh
```

- 끝에 `친구 매매법 페이퍼 봇(paperbot-combo-friend) 설치만 했습니다` 줄이 나옵니다. 아직 켜지지 않습니다.

### B. 친구 매매법 페이퍼 봇 켜기 (돈·주문 없음)

1) 설정 파일 넣기 (처음 한 번. 이미 있으면 덮어쓰지 않고 그대로 둠):

```bash
sudo test -e /etc/paperbot/combo-friend.json || sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/combo.friend.json /etc/paperbot/combo-friend.json
```

2) 확인:

```bash
cd /opt/crypto-bot-research && sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo check-config --config /etc/paperbot/combo-friend.json
```

- 볼 줄: `배수: BTCUSDT 35배, …`, `손절: 순ROE -50%(수수료·슬리피지 포함: 35배 가격 1.29%) / 계단 익절: 순ROE 12%에서 10% 잠금, 이후 5%씩`,
  `1. FRIEND_ROC 15분 - 친구 매매법(EMA·RSI·ROC): EMA21·EMA52·RSI26·ROC9, 상위 봉 1시간·4시간 중 하나라도 ROC9이 같은 쪽 …`,
  마지막 줄 **`준비됨`**.
- 손절 줄이 다르면(예전 설정 파일이 이미 있던 경우) 설정 파일을 새로 넣습니다:
  `sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/combo.friend.json /etc/paperbot/combo-friend.json` 후 다시 확인.

3) 켜기:

```bash
sudo systemctl start paperbot-combo-friend
systemctl is-active paperbot-combo-friend
```

- `active`. 텔레그램에 `[합친 봇 페이퍼 친구 매매법] 시작: 매매법 1개(친구 매매법(EMA·RSI·ROC) 15분), BTC 35배·나머지 35배, 증거금 잔고의 40%, 손절 순ROE -50%(수수료·슬리피지 포함: 35배 가격 1.29%), …`가 옵니다.
- 1~2분 뒤 기록 확인:

```bash
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/friend.db
```

- `마지막 1분봉: (지금에 가까운 시각) KST`, `COMBO@mix: 지갑 $1,000.00, 거래 0번 …`. 이때부터 페이퍼로 돌기 시작합니다.
- 주말(한국 시간 토·일)에는 신호가 나와도 들어가지 않으니, 일요일에 켜면 첫 진입은 월요일입니다.
- 며칠 괜찮으면 서버를 다시 켜도 같이 켜지게 `sudo systemctl enable paperbot-combo-friend`.
- 끄기: `sudo systemctl stop paperbot-combo-friend` (기록은 남고, 다시 켜면 이어서 돕니다).

## 5. 텔레그램 메시지 읽는 법

- **진입** (두 줄):
  ```
  [합친 봇 페이퍼 친구 매매법] 진입 BTC 롱 · 친구 매매법(EMA·RSI·ROC) 15분 · 35배, 증거금 $400.00, 손절 59226.9 (순ROE -50%(수수료·슬리피지 포함), 35배)
  신호 봉: 15분봉 10/26 09:00~09:15 KST · EMA21 60010.5 > EMA52 59980.2 · RSI26 55.3 · ROC9 -0.12 → +0.31 · 1시간 ROC9 +0.84 · 4시간 ROC9 -0.20 · 4시간 ADX 27 · 거래량 0.41배
  ```
  - 둘째 줄은 트레이딩뷰에서 같은 15분봉(바이낸스 선물, 그 코인)을 찾아 맞춰 보는 값입니다. EMA21·EMA52·RSI26·ROC9을 종가로 띄우면 같은
    숫자가 나와야 합니다. "1시간 ROC9"·"4시간 ROC9"은 그 순간까지 끝난 1시간봉·4시간봉의 값입니다(하나라도 같은 쪽이면 신호).
  - "4시간 ADX"와 "거래량(신호 봉 거래량 ÷ 앞 20봉 평균)"은 참고로만 보여 줍니다. 진입 판단에는 쓰지 않습니다.
- **청산**: `[합친 봇 페이퍼 친구 매매법] 청산 BTC 롱 · 친구 매매법(EMA·RSI·ROC) 15분 · 계단 익절 · 순ROE +10.7%, +$42.80, 지갑 $1,042.80`
- **진 거래**는 청산 줄 아래에 한 줄이 더 붙습니다(손실 리뷰, 6장):
  ```
  손실 이유 후보: BTC가 거래 동안 반대로 -0.4% · 손절 전 최고 +3% · 1.2시간 보유 · 4시간 ADX 27 · 거래량 0.41배 · 24시간 범위 끝에서 진입(0.93) · 소비자물가(CPI) 발표 3.2시간 뒤 진입
  ```
  | 말 | 뜻 |
  |---|---|
  | BTC가 거래 동안 반대로 −0.4% | 진입 분 시가부터 청산 분 종가까지 BTC가 우리 방향과 반대로 0.4% 움직임(롱이면 BTC가 내림). 같은 방향이면 "BTC는 거래 방향으로 +0.4%" |
  | 손절 전 최고 +3% | 손절 맞기 전에 가장 좋았던 순ROE. +12%에 닿았다면 계단(10% 잠금)이 걸려서 손절까지 안 갔을 것 |
  | 1.2시간 보유 | 진입부터 청산까지 시간 |
  | 4시간 ADX 27 | 진입할 때 4시간 추세 힘(참고값) |
  | 거래량 0.41배 | 신호 봉 거래량 ÷ 앞 20봉 평균(참고값) |
  | 24시간 범위 끝에서 진입(0.93) | 진입가가 앞 24시간 고저 범위의 어디였나(1 = 추격 쪽 끝: 롱이면 고점, 숏이면 저점). 0.9 이상이면 "끝에서", 아니면 "0.55 위치에서" |
  | CPI 발표 3.2시간 뒤 진입 | 가장 가까운 미국 경제 발표와 진입 시각의 거리 |
- 실거래 텔레그램 설정에서 페이퍼 봇의 날것 진입·청산 줄을 꺼 두었으면(`PAPERBOT_COMBO_TRADE_MSGS=0`) 위 진입·청산 줄은 오지 않고,
  진 거래의 손실 이유 줄만 따로 옵니다: `[합친 봇 페이퍼 친구 매매법] BTC 롱 순ROE -50.1% · 손실 이유 후보: …`.
- **봉을 못 읽음**: `친구 매매법 신호 봉을 못 읽어 건너뜀(1번째): 10-26 09:15 KST BTC, ETH … · …`. 바이낸스가 그 15분봉(또는 1시간봉·4시간봉)을
  주지 않아 그 봉의 신호를 계산하지 못한 것입니다(1·10·100번째만 텔레그램).

## 6. 손실 리뷰 (두 분 방식: "손실이 나면 왜 손실이 났는지 알아보고 수정")

- 진 거래마다 5장의 값이 기록 `friend.db`의 `loss_review` 표에 한 줄씩 쌓입니다.
- 일주일에 한 번:

```bash
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/friend.db
```

- 끝에 `손실 리뷰(지난 7일): 손실 3번 (시작부터 5번) · BTC가 반대로 감 2 · 손절 전 +10% 넘게 갔음 1 · 24시간 범위 끝에서 진입 1 ·
  4시간 ADX 25 미만 1 · 경제 발표 3시간 안 0 · 보유 가운데 3.1시간`과 최근 손실 줄들이 나옵니다.
