## 2. 규칙 (설정 파일 `deploy/combo.friend.json` 그대로)

### 신호: 15분봉이 끝날 때마다, 6개 코인 모두

| | 롱 | 숏 |
|---|---|---|
| 1 | EMA21이 EMA52 위 | EMA21이 EMA52 아래 |
| 2 | RSI26이 50 위 | RSI26이 50 아래 |
| 3 | ROC9이 0 이하에서 0 위로 (앞 봉 ≤ 0, 이 봉 > 0) | ROC9이 0 이상에서 0 아래로 |
| 4 | 끝난 1시간봉 **또는** 끝난 4시간봉의 ROC9이 0 위 | 끝난 1시간봉 또는 끝난 4시간봉의 ROC9이 0 아래 |

- 지표는 연구와 같은 계산(저장소 지표 라이브러리)이고 종가로 계산합니다. 1시간봉·4시간봉은 그 15분봉이 끝난 순간까지 **이미 끝난 봉**만 봅니다.
- 4번은 설정으로 바꿀 수 있습니다(`members`의 `"higher"`). 두 분이 아직 고르지 않아 설정 파일은 지금 값 그대로입니다.

  | 값 | 4번 (롱) | 숏 |
  |---|---|---|
  | `"roc_any"` (지금, 안 적으면 이것) | 끝난 1시간봉 **또는** 4시간봉 ROC9 > 0 | 둘 중 하나 ROC9 < 0 |
  | `"rsi_roc_all"` (10/24 밤 친구가 준 그대로) | 끝난 1시간봉 **과** 4시간봉 **둘 다** RSI26 > 50 이고 ROC9 > 0 | 둘 다 RSI26 < 50 이고 ROC9 < 0 |

  예: `"members": [{"strategy": "FRIEND_ROC", "tf": "15m", "higher": "rsi_roc_all"}]`. 15분봉 쪽(1~3번)은 둘 다 같습니다.
- 배수 40(`"leverage": {"BTCUSDT": 40, "default": 40}`)과 순ROE −50% 손절(`"stop": {"mode": "roe", "roe": 0.5, "net": true}`)도
  설정 검사를 통과하고, 시작 크기에서 6개 코인 모두 강제청산 안쪽에 손절이 들어갑니다(시험으로 확인). 이것도 아직 설정 파일에는 없습니다.
- 봉은 한국 시간과 상관없이 UTC 기준입니다(15분봉 00·15·30·45분, 4시간봉 01·05·09·13·17·21시 KST에 끝남).

### 진입: 신호가 나오면 차례로 확인

| 순서 | 확인 | 걸리면 | 설정 이름 |
|---|---|---|---|
| 1 | 한국 시간 토·일요일 | 진입 안 함 | `no_weekend` |
| 2 | 미국 경제 발표 앞뒤 30분 | 진입 안 함 | `macro_blackout_min` |
| 3 | 나스닥 개장 30분 전 ~ 30분 후 | 진입 안 함 | `us_open_pre_min`, `us_open_pause_min` |
| 4 | 끝난 4시간봉 ADX(14)가 20 미만 (추세 약함) | 진입 안 함 | `adx_gate` |
| 5 | 신호 봉 거래량이 앞 20봉 평균의 0.64배보다 큼 (조용한 봉이 아님) | 진입 안 함 | `quiet_gate` |
| 6 | 이미 포지션이 있음 | 건너뜀 | (항상) |

- 통과하면 신호 봉이 끝난 다음 1분 시가에 시장가로 들어갑니다. 같은 분에 신호가 겹치면 BTC → ETH → SOL → DOGE → LTC → BCH.
- 4번·5번은 바이낸스 공개 봉으로 계산합니다. 봉을 못 읽으면 그 신호는 들어가지 않고 이유가 기록됩니다.
- 들어가지 않은 신호와 이유는 기록에 남습니다(`status` 명령의 "진입 안 한 신호(이유별)").

### 청산

| 항목 | 내용 | 설정 이름 |
|---|---|---|
| 손절 | 순ROE −75%(수수료·슬리피지 포함). 30배에서 진입가부터 가격 약 2.36% | `stop` |
| 계단 익절 | 순ROE 22% → 20% 잠금, 32% → 30%, 42% → 40%, 이후 10%씩 | `ladder` |
| 보유 한도 · 반대 신호 청산 | 없음 | `max_hold_bars` null, `early_exit` null |

### 크기

- 잔고의 40%를 증거금으로, 30배(`margin` 0.4, `leverage` 30). 손절 한 번이면 계좌 약 −30%, 두 번 연속이면 약 −51%입니다.
- 페이퍼는 1,000달러로 시작합니다.
- 연구와 같게 하려고 고른 값: 손절 한 번 최대 손실 `max_loss_frac` 0.35(손절이 계좌 30%라 수량을 줄이는 일이 없음),
  ATR 여유 `liq_buffer_atr` 0(손절 자리를 ATR로 따지지 않음), 동전 쌍둥이 계좌 켬(비교용, 따로 도는 계좌).
- **돈이 커지면:** 바이낸스는 크기가 커지면 유지증거금이 올라갑니다. 페이퍼 지갑이 약 2배(2,000달러 안팎)를 넘으면 LTC·BCH는 30배
  −75% 손절 자리가 강제청산 가격에 너무 가까워져서 그 진입을 **건너뜁니다**(손절을 옮기지 않음). 건너뛸 때 텔레그램에
  `진입 거절(n번째): LTC - 손절 자리가 강제청산 가격에 너무 가까움 …`이 옵니다(1·10·100번째).

## 4. 일요일 순서 (서버, 한 줄씩 붙여 넣기)

### A. 설치 — 추세판단 봇 페이퍼에 포지션이 없을 때

`install.sh`는 코드를 바꾸는 동안 규칙봇·페이퍼 봇들을 잠깐 껐다 켭니다(실행기는 건드리지 않음). 그래서 페이퍼 포지션이 없을 때 합니다.

```bash
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/live-ac.db
```

- `COMBO@mix: … 포지션 없음`이면 다음 줄로. 포지션이 있으면 닫힐 때까지 기다렸다가 다시.

```bash
cd /root/crypto-bot-research && git pull && sudo bash deploy/install.sh
```

- 끝에 `친구 매매법 페이퍼 봇(paperbot-combo-friend) 설치만 했습니다` 줄이 나옵니다. 아직 켜지지 않습니다.

### B. 친구 매매법 페이퍼 봇 켜기 (돈·주문 없음)

1) 설정 파일 넣기 (처음 한 번. 이미 있으면 덮어쓰지 않고 그대로 둠):

```bash
sudo test -e /etc/paperbot/combo-friend.json || sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/combo.friend.json /etc/paperbot/combo-friend.json
```

2) 확인:

```bash
cd /opt/crypto-bot-research && sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo check-config --config /etc/paperbot/combo-friend.json
```

- 볼 줄: `손절: 순ROE -75%(수수료·슬리피지 포함: 30배 가격 2.36%) / 계단 익절: 순ROE 22%에서 20% 잠금, 이후 10%씩`,
  `4시간 ADX(14)가 20 미만이면 진입 안 함(추세 약함)`, `신호 봉 거래량이 앞 20봉 평균의 0.64배보다 크면 진입 안 함(조용한 봉만)`,
  `1. FRIEND_ROC 15분 - 친구 매매법(EMA·RSI·ROC) …`, 마지막 줄 **`준비됨`**.

3) 켜기:

```bash
sudo systemctl start paperbot-combo-friend
systemctl is-active paperbot-combo-friend
```

- `active`. 텔레그램에 `[합친 봇 페이퍼 친구 매매법] 시작: 매매법 1개(친구 매매법(EMA·RSI·ROC) 15분), BTC 30배·나머지 30배, 증거금 잔고의 40%, …`가 옵니다.
- 1~2분 뒤 기록 확인:

```bash
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.combo status --db /var/lib/paperbot/combo/friend.db
```

- `마지막 1분봉: (지금에 가까운 시각) KST`, `COMBO@mix: 지갑 $1,000.00, 거래 0번 …`. 이때부터 페이퍼로 돌기 시작합니다.
- 주말(한국 시간 토·일)에는 신호가 나와도 들어가지 않으니, 일요일에 켜면 첫 진입은 월요일입니다.
- 며칠 괜찮으면 서버를 다시 켜도 같이 켜지게 `sudo systemctl enable paperbot-combo-friend`.
- 끄기: `sudo systemctl stop paperbot-combo-friend` (기록은 남고, 다시 켜면 이어서 돕니다).

## 5. 텔레그램 메시지 읽는 법

- **진입** (두 줄):
  ```
  [합친 봇 페이퍼 친구 매매법] 진입 BTC 롱 · 친구 매매법(EMA·RSI·ROC) 15분 · 30배, 증거금 $400.00, 손절 58584 (순ROE -75%(수수료·슬리피지 포함), 30배)
  신호 봉: 15분봉 10/26 09:00~09:15 KST · EMA21 60010.5 > EMA52 59980.2 · RSI26 55.3 · ROC9 -0.12 → +0.31 · 1시간 ROC9 +0.84 · 4시간 ROC9 -0.20 · 4시간 ADX 27 · 거래량 0.41배
  ```
  - 둘째 줄은 트레이딩뷰에서 같은 15분봉(바이낸스 선물, 그 코인)을 찾아 맞춰 보는 값입니다. EMA21·EMA52·RSI26·ROC9을 종가로 띄우면 같은
    숫자가 나와야 합니다. "1시간 ROC9"·"4시간 ROC9"은 그 순간까지 끝난 1시간봉·4시간봉의 값, "거래량 0.41배"는 신호 봉 거래량이 앞
    20봉 평균의 0.41배라는 뜻입니다(0.64배 넘으면 안 들어감).
- **청산**: `[합친 봇 페이퍼 친구 매매법] 청산 BTC 롱 · 친구 매매법(EMA·RSI·ROC) 15분 · 계단 익절 · 순ROE +20.6%, +$82.33, 지갑 $1,082.33`
- **진 거래**는 청산 줄 아래에 한 줄이 더 붙습니다(손실 리뷰, 6장):
  ```
  손실 이유 후보: BTC가 거래 동안 반대로 -1.2% · 손절 전 최고 +3% · 5.2시간 보유 · 4시간 ADX 27 · 거래량 0.41배 · 24시간 범위 끝에서 진입(0.93) · 소비자물가(CPI) 발표 3.2시간 뒤 진입
  ```
  | 말 | 뜻 |
  |---|---|
  | BTC가 거래 동안 반대로 −1.2% | 진입 분 시가부터 청산 분 종가까지 BTC가 우리 방향과 반대로 1.2% 움직임(롱이면 BTC가 내림). 같은 방향이면 "BTC는 거래 방향으로 +0.4%" |
  | 손절 전 최고 +3% | 손절 맞기 전에 가장 좋았던 순ROE. +22%에 닿았다면 계단(20% 잠금)이 걸려서 손절까지 안 갔을 것 |
  | 5.2시간 보유 | 진입부터 청산까지 시간 |
  | 4시간 ADX 27 | 진입할 때 4시간 추세 힘(20 미만은 안 들어감) |
  | 거래량 0.41배 | 신호 봉 거래량 / 앞 20봉 평균 |
  | 24시간 범위 끝에서 진입(0.93) | 진입가가 앞 24시간 고저 범위의 어디였나(1 = 추격 쪽 끝: 롱이면 고점, 숏이면 저점). 0.9 이상이면 "끝에서", 아니면 "0.55 위치에서" |
  | CPI 발표 3.2시간 뒤 진입 | 가장 가까운 미국 경제 발표와 진입 시각의 거리 |
- 실거래 텔레그램 설정에서 페이퍼 봇의 날것 진입·청산 줄을 꺼 두었으면(`PAPERBOT_COMBO_TRADE_MSGS=0`) 위 진입·청산 줄은 오지 않고,
  진 거래의 손실 이유 줄만 따로 옵니다: `[합친 봇 페이퍼 친구 매매법] BTC 롱 순ROE -74.9% · 손실 이유 후보: …`.
- **진입 거절**: `진입 거절(1번째): LTC - 손절 자리가 강제청산 가격에 너무 가까움 …`(2장 "돈이 커지면").
- **봉을 못 읽음**: `친구 매매법 신호 봉을 못 읽어 건너뜀(1번째): 10-26 09:15 KST BTC, ETH … · …`. 바이낸스가 그 15분봉을 주지 않아
  그 봉의 신호를 계산하지 못한 것입니다(1·10·100번째만 텔레그램).

  - 신호: 2026-06-01 ~ 10-22, 6개 코인 15분봉 82,944개에서 연구 신호 5,654개와 봇 신호 5,654개가 **모두 같았습니다**(시각·코인·방향).
    4시간 ADX 판정·거래량 판정도 5,654개 모두 같았고, 값(EMA·RSI·ROC·ADX)도 같은 숫자였습니다.
    `"higher": "rsi_roc_all"`(1시간·4시간 둘 다)도 연구 계산(`frand.py`)과 신호 2,551개가 모두 같았습니다.
  - 거래(09-01 ~ 10-22, 1분씩, 연구와 같은 수수료로): 연구 73번(61승).
    | | 거래 | 승 | 연구와 같은 진입 | 같은 청산 분 | 지갑 |
    |---|---|---|---|---|---|
    | 봇 그대로(설정 파일) | 61번 | 51승 | 50번 | 44번 | ×2.69 |
    | 크기 거절만 뺀 확인용(코인마다 바이낸스 첫 구간) | 73번 | 61승 | **73번 모두** | 59번 | ×3.92 |
    - 9/18 14:45까지 26번은 모두 같은 진입이었습니다. 그때 페이퍼 지갑이 2,157달러가 되면서 BCH·LTC 진입이 처음 "손절 자리가
      강제청산 가격에 너무 가까움"으로 거절됐고(이 기간 31번), 그 뒤로는 다른 코인에 들어가 거래 순서가 갈라졌습니다(2장 "돈이 커지면").
    - 확인용에서 청산 분이 다른 13번은 모두 계단 익절이고, 아래 "계단 잠금" 차이 때문입니다(3번은 한 칸 낮게 잠김: 40→30%, 30→20%).
      순ROE는 계단 익절이 평균 +0.4%p 좋고, 손절은 ±0.06%p 안(펀딩을 낸 거래 하나만 −0.97%p).
    - 페이퍼 기본 수수료(테이커 0.05%)로 돌리면 66번(53승), 같은 진입 56번입니다.
    - 지갑 숫자는 코드가 같은지 보려는 것입니다. 이 7주는 이 매매법에 좋았던 기간이고, 5년 기록은 3장 그대로입니다.
- **연구와 다른 점** (봇 코드의 정해진 방식):
  - 계단 잠금: 페이퍼는 체결가(미끄러짐 포함)에서 순ROE를 계산합니다. 그래서 계단이 연구보다 조금 늦게 잠기고(가격 약 0.02% 더
    가야 함), 잠긴 익절은 약 +0.6%p 더 좋게 나옵니다. 가끔 이 차이로 청산 시각이 바뀝니다.
  - 펀딩: 연구는 낸 펀딩만큼 손절 자리를 옮기고, 페이퍼는 손절 가격을 그대로 둡니다(펀딩은 지갑에서 빠짐).
  - 수수료: 페이퍼는 규칙봇의 바이낸스 키로 읽은 테이커 수수료(키가 없으면 0.05%)로 계산합니다. 연구는 테이커 0.042%(WOO X Pro)였습니다.
  - 크기가 커지면 LTC·BCH 진입을 건너뜀(2장).
- **바이낸스 봉**: 15분봉이 끝나고 몇 초 뒤 바이낸스에서 그 15분봉·1시간봉·4시간봉을 받아 계산합니다(코인마다 작은 요청 몇 개).
  바이낸스가 안 될 때는 그 봉의 신호를 계산하지 못했다고 알립니다(5장).
- **경제 발표 일정**: `data/macro_events.csv`가 2026-12-23까지 들어 있습니다. 그 뒤 일정은 채워야 2번 금지가 계속 동작합니다.
