## 0. 결론

1. **이 파일들은 "Claude 에이전트팀 만드는 가이드"가 아닙니다.** PIXEL TRADING FLOOR라는 완성된 앱의 설치·사용 설명서(PDF)와 그 앱의 소스코드(zip)입니다.
2. 앱이 하는 일: 티커 하나를 넣으면 AI 에이전트 13명이 시세·뉴스를 보고 토론합니다. 그 결과로 **BUY/SELL/HOLD 의견**을 내고, 과정을 픽셀아트 사무실 화면으로 보여 줍니다. **주문 기능, 거래소 연동, 자동매매는 없습니다.**
3. **우리 봇을 테스트하는 기능은 전혀 없습니다.** 외부 봇의 로그·주문·포지션을 받는 입구가 없습니다. 이 앱의 에이전트는 시장을 분석할 뿐이고, 봇의 버그나 리스크 규칙 위반을 찾지 않습니다.
4. **악성코드 흔적은 없습니다.** 자격증명 탈취나 숨은 외부 전송도 발견되지 않았습니다. 다만 설계상 보안·비용 함정이 여러 개 있어서, 돌리기 전에 설정을 바꿔야 합니다(§6, §9).
5. 가져다 쓸 가치가 있는 부분도 있습니다. 역할을 나누고 서로 반박하게 하는 구조, 프롬프트 규칙, 계산 모듈(`riskmath.js`, `indicators.js`), 텔레그램 알림 모듈입니다(§8).
6. **"데모" 용어에 주의하세요.** 앱의 "데모 모드"(`?demo=1`)는 AI 대신 미리 준비된 고정 문구로 화면만 재생하는 기능입니다. 우리가 말하는 **모의거래(데모 트레이딩)와는 다른 개념**입니다.

## 2. 앱 구조

```
[공개 시세 API] ──▶ market.js (시세·지표·뉴스·공포탐욕)
                        │
                        ▼
engine.js ── 모드별 파이프라인 ──▶ agents.js
                        │            └─ 역할마다 `claude -p --model opus` 프로세스 1개씩 스폰
                        │               (프롬프트는 stdin, 응답은 JSON)
                        ▼
riskmath.js 리스크 게이트 (손익비·청산가 → 미달이면 HOLD/PASS로 강등)
                        │
                        ▼
positions.js 가상 포지션 자동 기록 → reports/*.md + decisions.json 저장
                        │
                        ▼
server.js ── SSE ──▶ public/ (픽셀아트 화면)
```

- Node 내장 모듈만 씁니다(npm 패키지 0개). Node 20 이상에서 동작합니다.
- 공식 문서 기준으로는 Windows용이지만, 코드 자체는 Linux·Mac에서도 거의 돌아갑니다.
- **Claude Code의 공식 멀티에이전트 기능(Subagents, Agent Teams)은 쓰지 않습니다.** Node가 `claude -p`(공식 headless 모드)를 역할 수만큼 반복 호출하는 방식입니다.

### 2-1. 에이전트 13명 (`server/agents.js:15-31`)

| 에이전트 | 역할 | 쓰이는 모드 |
|---|---|---|
| TARO | 기술적 분석 (MA·RSI·MACD·ATR·변동성) | algo, scalp, attack |
| DIANA | 기본적 분석 (시총·거래대금·공급량) | algo |
| NOVA | 뉴스 (Google News RSS 헤드라인) | algo |
| VIBE | 센티먼트 (공포탐욕지수 + 헤드라인) | algo, scalp, attack |
| BULL / BEAR | 매수·매도 논거, 4턴 교대 반박 | algo |
| BLITZ | 스캘퍼 (15분봉 진입·목표·무효화) | scalp, attack |
| GUARD | 리스크 관리 (20배 청산 버퍼, 비중) | scalp, attack |
| RISKY / SAFE / NEUTRAL | 리스크 위원회 (공격·보수·중재) | algo |
| ACE | 수석 트레이더 (판정·확신도·진입/손절/목표) | 전 모드 |
| PM | 최종 승인 (APPROVE/AMEND/REJECT) | algo |

### 2-2. 모드와 호출 횟수

| 모드 | 파이프라인 | 1회 분석당 claude 호출 |
|---|---|---|
| algo | 애널리스트 4 병렬 → BULL⇄BEAR 4턴 → ACE → RISKY → SAFE → NEUTRAL → PM | **13회** (재시도 시 최대 26회) |
| scalp | TARO·VIBE → BLITZ → GUARD → ACE | **5회** (최대 10회) |
| attack | scalp와 같음. 단 HOLD·PASS 금지로 방향을 강제 | 5회. 가이드도 "판정이 아니라 연출"이라고 명시 |

- 모델 기본값은 `opus`이고, 환경변수 `FLOOR_MODEL`로 바꿀 수 있습니다(`agents.js:724`).
- 타임아웃은 180초, 파싱 실패 시 1회 재시도합니다.
- "과거 판정 회고"는 같은 종목의 최근 판정 3건과 그 뒤 가격 변화를 문장으로 넣어 주는 수준입니다. ACE와 PM에만 들어갑니다.

### 2-3. 데이터 소스 (전부 API 키 없는 공개 API)

- 코인: Binance 현물·선물, CoinGecko, alternative.me(공포탐욕지수)
- 주식: Yahoo Finance
- 뉴스: Google News RSS
- 한국주식 무기한 선물: Bybit, Bitget, Gate

지원 범위와 한계:

- **코인 시세는 Binance USDT 현물 기준입니다.** 업비트·빗썸 원화 시세와 거래소 테스트넷은 지원하지 않습니다.
- 캐시·재시도가 없어서 Binance가 막히면 코인 분석 전체가 실패합니다.

### 2-4. 문서에 없는 v2 기능 (zip에는 들어 있음)

`docs/v2-contracts.md`에만 설명돼 있고, PDF·README에는 없는 기능들입니다.

- **데모 모드도 인터넷이 필요합니다.** 실제 시세를 받아 와야 해서, Binance가 막힌 이 클라우드 환경에서는 실패했습니다. README의 "네트워크 없이"는 사실과 다릅니다.
- 실측으로 확인한 문제:
  - 서버가 `0.0.0.0:8000`(모든 네트워크)에 인증 없이 열립니다.
  - 다른 웹사이트에서 보낸 POST로 설정이 바뀝니다(CSRF).
  - `/project.zip`에 `vendor/.env`가 포함됩니다.
  - 같은 분 안에 다시 분석하면 이전 리포트를 덮어씁니다.
  - 포지션을 수동 청산하면 실현손익이 null로 남습니다.

## 4. 보안 점검

### 4-1. 악성 여부 — 발견되지 않음

47개 파일에 대해 다음을 모두 확인했습니다.

결과:
- 외부 통신은 공개 시세 조회(GET)와 사용자가 켰을 때만 동작하는 텔레그램 발송뿐입니다.
- 외부 리소스는 jsDelivr 폰트 CSS 하나입니다. 버전 고정과 SRI는 없습니다.

## 5. 비용 주의

1. 기본 모델이 **opus**이고, 실전 분석 1회에 **5~13회**를 호출합니다. 파싱에 실패하면 재시도하므로 최대 2배가 됩니다.
2. 실전 호출이 생각보다 쉽게 일어납니다.
   - `start-floor.cmd`는 **실전 모드 주소**(`localhost:8000`)를 엽니다.
   - 워치리스트 칩을 누르면 확인 없이 바로 실전 분석이 시작됩니다.
   - 감시 자동분석·예약·스캔은 **항상 실전 호출**이고, 일일 상한이 없습니다.
   - `doctor.cmd`도 opus를 3~4회 호출합니다.
3. **환경변수 `ANTHROPIC_API_KEY`가 설정돼 있으면 구독 대신 API 요금이 청구됩니다.** PDF 2-3에도 같은 경고가 있고, 이 부분은 정확합니다.
4. 구독 로그인이면 평소 Claude 사용량 한도를 함께 씁니다.

## 8. 우리 목표(친구와 만든 코인봇을 에이전트팀으로 테스트)와의 관계

### 맞지 않는 점
- 봇의 로그·주문·체결·잔고·에러를 넣을 입구가 없습니다. 서버 라우트는 analyze/tape/config/watcher/stats/positions/scan/replay/telegram뿐입니다.
- 에이전트의 일이 "시장 보고 매매 의견 내기"입니다. 봇 코드 리뷰, 리스크 규칙 감사, 주문·잔고 정합성 대조, API 오류 처리 점검 같은 **테스트 역할이 없습니다.**
- Claude Code 공식 에이전트 기능을 쓰지 않아서, 에이전트팀 만드는 법을 배우는 자료로도 맞지 않습니다.

### 재사용할 만한 것
| 부분 | 쓰는 법 | 주의 |
|---|---|---|
| 역할 분담과 상호 반박 구조 (`engine.js` MODES, `agents.js` 프롬프트) | 봇 테스트팀 역할 설계의 참고 (병렬 분석 → 반박 → 판정 → 성향이 다른 심사 → 최종 승인) | 시장 분석 전용 프롬프트이고, "20배"·"탭비트"가 하드코딩돼 있음 |
| 프롬프트 규칙 (`agents.js:165-168, 250-255, 318-334`) | "데이터에 없는 수치 금지", "숫자로 제시", "반대 시나리오와 판단이 바뀌는 조건 명시" | 문구로 지시만 할 뿐 강제하지 않음 |
| `riskmath.js` + `config.js` | 봇 주문의 손익비·격리 청산가·비중 검산 | 가격은 숫자로 넘길 것. 수수료·MMR 구간·안전 여유 없음 |
| `indicators.js` | 봇 지표 교차검증 (SMA·Wilder RSI는 표준값과 일치) | MACD는 봉이 적으면 표준값과 차이가 큼. ATR 없음 |
| `notify.js` | 봇의 체결·에러를 텔레그램으로 알림 | chatId는 문자열로 적어야 함 |
| mock 모드 개념 | AI 호출 없이 흐름만 점검하는 드라이런 | mock 결과는 반드시 표시하고 통계에서 제외해야 함 |

### Claude Code 공식 기능 (code.claude.com/docs 기준)
- **Subagents**
  - 프로젝트의 `.claude/agents/*.md` 파일에 역할별 에이전트를 정의합니다. `name`과 `description`은 필수입니다.
  - `tools`, `model`, `maxTurns`, `permissionMode` 등으로 역할마다 권한과 비용을 제한할 수 있습니다.
  - **봇 테스트팀을 만들기에 가장 적합하고 안정적인 방법입니다.**
- **Agent Teams**
  - 여러 Claude Code 세션이 작업 목록과 메시지를 공유하며 협업하는 기능입니다.
  - 실험 기능이라 기본값은 꺼져 있고, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`로 켭니다.
  - 토큰을 훨씬 많이 쓰고, `-p` 모드에서는 동작하지 않습니다.
- **Headless `claude -p`**: 스크립트·크론에서 에이전트를 돌릴 때 씁니다. `--allowedTools`/`--disallowedTools`, `--max-turns`, `--output-format json` 등으로 제한할 수 있습니다.
- **Claude Agent SDK** (Python/TypeScript): 봇 옆에서 상시 도는 감시 에이전트를 직접 코딩할 때 씁니다.
