**코인별 설정 (30분 진입)**

| 코인 | 1시간 여유 | 손절 ATR × | 계단 시작 ROE → 잠금 | 레버리지 |
|---|---|---|---|---|
| SOL | 8 | 2 | 150 → 10 | 40배 |
| ETH | 8.5 | 1.5 | 200 → 10 | 40배 |
| XRP | 9.5 | 1.5 | 200 → 10 | 40배 |
| BCH | 3 | 2 | 150 → 10 | 40배 |
| ZEC | 6.5 | 2.5 | 100 → 10 | 20배 |
| DOGE | 4 | 2.5 | 100 → 10 | 40배 |

**청산**
- **처음 손절:** 체결가에서 `30분 ATR(14) × 손절 배수`만큼 떨어진 곳입니다. 진입하자마자 WOO X Pro에 **청산 전용 손절 주문**으로 걸어 둡니다(마지막 가격 기준).
- **계단 익절:** 진입 뒤 가장 유리했던 가격(30분봉 고가·저가)이 "계단 시작 ROE"에 닿으면 손절을 ROE +10%로 올립니다. 그 뒤 (시작 ROE − 10%)만큼 더 갈 때마다 같은 폭씩 올립니다.
  - 예: SOL은 ROE 150%에서 손절이 +10%로 오르고, 290%에서는 +150%로 오릅니다.
  - 손절은 **30분봉이 끝날 때만** 옮기고, 유리한 쪽으로만 움직입니다.
- 반대 신호나 시간으로는 청산하지 않습니다. 손절이나 계단 손절에 맞을 때만 나갑니다.

**크기**
- 수량 = 잔고 × 0.25% ÷ 손절 폭(가격)입니다. 레버리지를 바꿔도 손절 1번에 잃는 돈은 같습니다.
- 계약 단위로 내림하고, WOO X 최소 주문보다 작으면 **건너뜁니다**. 올려서 사지 않습니다.

## 3. 안전장치

- **손절 없는 포지션은 두지 않습니다.** 진입 직후든, 점검 중이든, 다시 켤 때든 같습니다.
  - 손절을 한 번 더 걸어 봅니다. 그래도 안 되면 바로 시장가로 닫습니다. 가격이 이미 손절선을 지나서 거래소가 거절한 경우도 시장가로 닫습니다.
  - 닫는 것까지 실패하면 15초마다 다시 해 보고, 텔레그램 긴급 알림을 10분에 한 번씩 보냅니다.
  - 알림은 조치를 먼저 한 뒤에 보냅니다(텔레그램이 느려도 손절·청산이 늦어지지 않게).
- **크기와 방향은 거래소 기준입니다.** 체결 응답이 일부만 보여도 거래소 포지션 크기로 손절을 겁니다. 방향이 봇 기록과 다르면 닫습니다.
- **체결이 안 보인 진입:** 주문 응답이 없거나 0으로 오면 포지션을 몇 번 다시 읽습니다. 10분 안에 그 코인 포지션이 보이면 봇 것으로 받아 손절을 겁니다.
- **15초마다:** 포지션이 아직 열려 있는지 봅니다. 손절에 맞아 닫혔으면 두 번 확인한 뒤에 기록을 정리합니다.
- **5분마다:** 손절이 거래소에 포지션 전체 크기로 걸려 있는지 봅니다. 없거나 모자라면 새로 걸고 예전 것은 취소합니다.
- **캔들 확인:** 서버 시계가 아니라 바이낸스에 다음 30분봉이 생긴 것을 보고 "봉이 끝났다"고 판단합니다.
- **WOO X Pro 청산가 확인:** 진입 전에 WOO X Pro의 유지증거금 구간으로 청산 거리를 계산합니다. 손절이 청산가보다 0.2% 이상 안쪽이 아니면 건너뜁니다.
- **한 번에 하나만:** 같은 설정으로 봇을 두 개 켜면 두 번째는 켜지지 않습니다. 실거래는 텔레그램 설정이 없으면 켜지지 않습니다. 키 확인에 실패하면 계속 재시작하지 않고 멈춥니다.
- **새 진입을 막는 경우** (열린 포지션은 손절·계단 그대로 둡니다)
  - 공용 비상 파일 `/var/lib/paperbot/STOP`이 있을 때입니다. 이 파일은 다른 실행기들을 **전부 청산**시킵니다.
  - 이 봇 전용 정지 파일 `/var/lib/paperbot/exec/mixchop.STOP`이 있을 때입니다. **이 봇만 새 진입을 멈춥니다.**
  - 잔고가 시작 잔고의 70% 아래로 내려갔을 때입니다.
  - 봇이 모르는 포지션이 계정에 있을 때입니다. 텔레그램 긴급 알림이 갑니다.
- **다시 켜면:** 저장된 포지션을 거래소와 맞춰 봅니다. 손절이 없으면 다시 걸고, 못 걸면 시장가로 닫습니다. 모의 봇은 다시 켜도 포지션을 그대로 이어 갑니다.
- **기존 WOO X Pro 2 실행기:** 예전 '친구 매매법' 실행기(`paperbot-executor-wooxpro2`)와는 같은 계정을 동시에 쓰지 않습니다. 이 봇을 켜면 그 실행기는 자동으로 꺼집니다(Conflicts).

## 5. 켜는 순서 (서버에서, 두 분이 직접)

1. **코드 받기**
   ```
   cd /root/crypto-bot-research && git pull && sudo bash deploy/install.sh
   ```
2. **키 넣기:** WOO X Pro 두 번째 계정에서 API 키를 만듭니다.
   - 권한은 "선물 거래"만 켜고 출금은 끕니다. IP는 158.247.200.152로 묶습니다.
   - 키는 **채팅에 붙이지 말고** 서버에서만 넣습니다.
   ```
   sudoedit /etc/paperbot/executor-wooxpro2.env
   ```
   `WOOXPRO_LIVE_KEY`, `WOOXPRO_LIVE_SECRET`, `WOOXPRO_LIVE_MEMO`, `WOOXPRO_LIVE_KEY_CHECKED=FUTURES_ONLY_NO_WITHDRAW_IP_BOUND`, `PAPERBOT_LIVE_MAINNET=I_UNDERSTAND`를 넣습니다. 이미 넣어 두었으면 그대로 씁니다.
3. **설정 파일 복사 (이미 있으면 그대로 둠)**
   ```
   sudo test -e /etc/paperbot/mixchop.json || sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/mixchop.live.json /etc/paperbot/mixchop.json
   sudo test -e /etc/paperbot/mixchop-paper.json || sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/mixchop.paper.json /etc/paperbot/mixchop-paper.json
   ```
4. **점검 (읽기만, 주문 없음)**
   ```
   sudo /opt/crypto-bot-research/deploy/paperbot-exec.sh --keys wooxpro2 mixchop check --config /etc/paperbot/mixchop.json
   ```
   - 잔고, 포지션 모드, 열린 포지션, 코인 6개의 WOO X 계약이 나옵니다.
   - 각 코인에 "지금 손절 폭이면 몇 개·몇 달러로 들어가는지"가 나옵니다.
   - **✘가 나온 코인**은 계약이 없거나 $50에서 최소 주문보다 작은 코인입니다. 그 신호는 건너뜁니다.
5. **트레이딩뷰와 신호 맞춰 보기 (주문 없음)**
   ```
   cd /opt/crypto-bot-research && sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.mixchop signals --config /etc/paperbot/mixchop-paper.json
   ```
   코인마다 최근 색 변화 6개를 보여 줍니다. 시각, 종가, 30분·1시간 평균 RSI, 진입 또는 X 여부입니다. 트레이딩뷰 30분 차트의 표시에 마우스를 올려 같은지 봅니다.
6. **(권장) 모의로 먼저 몇 시간:** 주문 없이 같은 신호로 $50 모의 매매를 합니다. 기록은 `/var/lib/paperbot/mixchop-paper/log.jsonl`에 남습니다.
   ```
   sudo systemctl start paperbot-mixchop-paper
   ```
7. **실거래 켜기**
   ```
   sudo systemctl start paperbot-mixchop
   journalctl -u paperbot-mixchop -f
   ```
   - 텔레그램(실거래 봇 채팅)으로 시작, 진입, 계단, 청산 메시지가 옵니다.
   - 며칠 문제없으면 `sudo systemctl enable paperbot-mixchop`으로 서버 재부팅 뒤에도 자동으로 켜지게 합니다.

## 7. 알아 둘 점

- **진입 금지 시간은 백테스트에 없던 규칙입니다.** 친구 설계의 5년 숫자는 주말·나스닥 개장·경제 발표 때 진입도 포함한 값이라, 실제 진입 수는 그보다 줄어듭니다.
- **모의 봇도 WOO X Pro 최소 주문을 따릅니다.** 실거래가 못 들어가는 작은 신호는 모의도 건너뜁니다.
- **기대 수익:** 설계서의 5년 백테스트는 손절 1번에 0.25%일 때 코인당 한 달 평균 +0.4~1.2%입니다(60개월 중 20~30개월은 마이너스). $50이면 한 달에 몇십 센트 수준입니다. 첫 목적은 **실제 진입·청산이 트레이딩뷰·모의와 같게 나오는지** 확인하는 것입니다.
  - 이 숫자를 봇 코드 그대로 바이낸스 5년 봉으로 다시 돌려 본 결과(코인별, 그리고 실거래 규칙대로 한 번에 1포지션)는 8-5에 있습니다.
- **승률이 낮은 구조입니다:** 승률 20~40%입니다. 작은 손절이 여러 번 이어지다 한 번 크게 먹습니다. ETH·XRP는 승률 20% 안팎이라 연속 손절이 길 수 있습니다.
- **트레이딩뷰와 다를 수 있는 부분**
  - 진입이 봉 종가가 아니라 봉이 끝나고 몇 초 뒤 시장가입니다. 그래서 가격이 조금 다르고, 수수료도 백테스트(진입 0.02%)보다 비쌉니다(WOO X 테이커 약 0.042%).
  - 손절은 WOO X 마지막 가격에 걸리고, 신호와 계단은 바이낸스 캔들로 계산합니다. 두 거래소 가격 차이만큼 다를 수 있습니다.
- **크기 조정:** 손절 1번 손실을 바꾸려면 `/etc/paperbot/mixchop.json`의 `risk_pct`(%)를 고치고 봇을 다시 켭니다. 0.5면 수익과 낙폭이 모두 약 2배가 됩니다.
- **시작 잔고 다시 정하기:** 입금·출금 뒤 "시작 잔고 70%" 기준을 다시 잡으려면 봇을 끄고 `/var/lib/paperbot/exec/mixchop-state.json`의 `start_equity`를 지운 뒤 켭니다. 포지션이 없을 때만 합니다.

## 8. 점검과 손실 분석 (두 분 요청 10/25 밤)

### 8-1. 아침 점검 (매일 09:05)

- 평소에는 조용히 옵니다: `📋 믹스 30분 봇 아침 점검 · 이상 없음`.
- 문제가 있으면 `⚠ … 확인할 것 n개`로 오고, 맨 위에 확인할 것을 적습니다.
- 줄마다 뜻
  - **신호:** 어제 30분봉 색 변화 수, 조건이 맞은 신호 수, 진입 수입니다.
  - **건너뜀:** 진입 금지 시간(주말·나스닥 개장·경제 발표), 최소 주문보다 작음, 보유 중, 같은 봉 다른 코인 먼저, 정지 파일, 잔고 바닥선, 청산가에 너무 가까움으로 나눠 셉니다.
  - **모의와 같은 진입:** 실거래와 모의가 같은 신호에 같이 들어갔는지 봅니다. 다르면 한 줄씩 적고, 다른 쪽이 기록한 이유(예: "실거래는 최소 주문보다 작음")를 붙입니다. 같이 들어간 거래가 다르게 끝났으면(손절·계단, R 차이 0.5 넘음) 그것도 적습니다.
  - **놓친 신호:** 8-4를 보세요.
  - **거래:** 어제 닫힌 거래와 손실 카드 판정입니다.
  - **진입 체결:** 체결가가 신호 봉 종가보다 평균 몇 % 불리했는지, 수수료 추정(테이커 0.042% 양쪽)입니다.
  - **안전:** 손절이 보유 내내 걸려 있었는지(손절 실패·다시 걸기·손절 못 걸어 청산 기록), 거래소·바이낸스 읽기 실패 수, 봇 재시작 수, 모르는 포지션이 있었는지, 지금 보유 중인 포지션과 손절입니다.
  - **잔고:** 지금 잔고, 시작 대비, 70% 바닥선까지 남은 돈(손절 몇 번 분량인지)입니다.
  - **운이냐 고장이냐:** 8-3을 보세요.
- `⚠`가 뜨는 경우: 봇이 멈춘 것 같을 때, 실거래와 모의가 이유 없이 다르게 들어갔을 때, 손절 주문 문제, 보통과 다른 청산(손절 못 걸어 청산·꺼진 사이 청산·직접 청산), 모르는 포지션, 읽기 실패 10번 이상, 진입 체결이 평균 0.3% 넘게 불리할 때, 바닥선 아래, 설계보다 큰 손실, 놓친 신호, 성적이 "아주 드묾"일 때입니다.

### 8-2. 손실 카드 (거래가 닫히고 5분 안)

- 5분마다 봇 기록을 보고, 새로 닫힌 실거래마다 한 번 보냅니다.
- **진 거래**는 카드로 옵니다. 계획과 실제를 나란히 봅니다.
  - 계획: 손절 1번 = 잔고의 0.25%, 거기에 수수료(테이커 0.042% 양쪽)를 더한 손실입니다. 이것을 1R이라고 부릅니다(예: −1.08R).
  - **설계대로 손절 (정상):** 실제 손실이 계획보다 0.25R 넘게 크지 않을 때입니다. 조용히 옵니다.
  - **설계보다 큰 손실:** 계획보다 0.25R 넘게 더 잃었을 때입니다(1R 넘게면 "아주 큰"). `⚠`로 오고 이유 후보를 적습니다.
    - 손절가보다 더 밀려 나감(갭·급변), 손절이 가격을 한참 지나서 체결됨
    - 진입이 신호 종가보다 많이 불리하게 체결됨
    - 손절이 한동안 없었거나 다시 걸었음, 손절을 못 걸어 시장가로 닫음, 봇이 꺼진 사이 닫힘
    - 체결을 늦게 확인했거나 수량을 거래소 기준으로 맞춤(일부 체결)
    - 진입하고 곧(1시간 안) 진입 금지 시간이 시작됨, 청산이 진입 금지 시간 안에서 일어남
    - 보유 중 봇이 다시 켜짐
  - 모의 봇이 같은 신호에서 어떻게 끝났는지(R)와, 지금 몇 번째 연속 손절인지(5년 재생에서 흔한지)도 붙입니다.
- **이긴 거래**는 한 줄로 옵니다: 손익, R, 계단 몇 단계, 보유 시간, 모의 결과.
- **청산 가격:** 봇 기록에는 청산 체결가가 없습니다(사이트에 "체결가 기록 없음"). 그래서 잔고 변화와 진입가·수량·수수료로 거꾸로 계산합니다. 펀딩비가 섞여 조금 다를 수 있습니다. 정확한 값은 WOO X Pro 앱의 체결 내역에서 확인합니다.
- 타이머를 처음 켤 때는 3시간보다 오래된 청산은 보내지 않습니다(사이트에는 모두 보입니다).

### 8-4. 놓친 신호 (신호 다시 계산)

## 9. 크기와 계단 바꿈 (두 분 10/26: "시드비중 40%", "12% 도달하면 10%, 17%면 15%, 22%면 20%")

설정 원본(`deploy/mixchop.live.json`, `deploy/mixchop.paper.json`)에 세 줄이 더해졌습니다. 신호·손절 거리·레버리지·코인·진입 금지는
그대로입니다.

- **크기 `margin_frac: 0.4`**: 진입할 때마다 그때 잔고의 40%를 증거금으로 씁니다(수량 = 잔고 × 0.4 × 배수 ÷ 가격). 전에는 "손절 1번 =
  잔고의 0.25%"였습니다. 이제 손절 1번에 잔고의 대략 15~25%가 빠집니다(손절 거리에 따라 다름). `max_notional_usd`(한 포지션 최대)는
  500 → 10,000달러로 올렸습니다(500이면 $50의 40%·40배 = $800을 못 채움).
- **계단 `ladder: {"trigger": 12, "lock": 10, "step": 5}`**: 모든 코인에 같은 계단입니다. **순ROE**(WOO X Pro 테이커 0.042%를 진입·청산
  둘 다 뺀 값, 그 코인의 배수로) 12%에 닿으면 손절을 순ROE 10% 자리로, 17%면 15%, 22%면 20%, 그 뒤로도 5%마다 한 칸. 전에는 코인별로
  ROE 100~200%에 닿아야 10%로 잠갔습니다.
- **`ladder_every_s: 60`**: 30분봉 마감만 기다리지 않고 **60초마다 바이낸스 1분봉**으로 가장 유리했던 가격을 갱신하고 계단 손절을
  WOO X Pro에 옮깁니다(모의 쌍둥이는 같은 1분봉으로 손절도 판단). 계단이 촘촘해서 30분마다만 옮기면 늦습니다.
- 그대로인 것: **`equity_floor_frac: 0.7`**(잔고가 시작의 70% 아래면 새 진입 멈춤). 40%로 들어가면 손절 두 번쯤에 70% 아래로 내려가
  새 진입이 멈출 수 있습니다. 계속 돌리려면 이 값을 낮추거나(예: 0.3) 0으로 두면 됩니다(두 분이 정할 일).
- 화면·알림: 실거래 사이트의 믹스 카드와 규칙 표, 텔레그램 시작·진입·계단 문구가 새 크기와 순ROE 계단으로 나옵니다. 아침 점검의
  "운이냐 고장이냐"(5년 재생 비교)는 옛 크기·계단으로 만든 기준이라, 이 설정에서는 **비교하지 않는다고** 적고 넘어갑니다. 손실 카드의
  R은 그 거래의 "손절에 맞았을 때 잃는 돈"을 1로 셉니다.

## 10. 두 번째 매매법 + 손절 ATR 3배 (두 분 10/26: "친구 봇 ATR 3배 계단 고정으로 넣어서 실거래 돌리자", "둘 다")

설정 원본(`deploy/mixchop.live.json`, `deploy/mixchop.paper.json`)에 두 줄이 더해졌습니다. 코인·배수·증거금 40%·계단(9장)·진입 금지
시간(주말, 나스닥 개장 앞뒤 30분, 경제 지표 앞뒤 30분)·바닥선 70%는 그대로입니다.

- **`rules: ["mix", "st"]`**: 친구 매매법(지금 그대로) + 새 매매법 "슈퍼트렌드·스톡RSI"를 같이 봅니다. 한 번에 1포지션 그대로입니다.
  - 새 매매법 롱: 슈퍼트렌드(ATR 14, 3배)와 (ATR 14, 6배)가 둘 다 상승 · 스톡RSI(RSI 14, 스토캐스틱 11, K 4, D 5)의 K가 D를 위로
    뚫음(골든크로스) · 30분 RSI(26) 50 위 · 마지막으로 닫힌 1시간봉 RSI(26) 50 위. 숏은 반대(하락 · 데드크로스 · 둘 다 50 아래).
  - 같은 코인 같은 봉에서 두 매매법이 다 신호면 **친구 매매법이 먼저**입니다. 코인끼리는 전처럼 설정의 코인 순서입니다.
- **`stop_atr: 3`**: 두 매매법 모두 손절 = 30분봉 ATR(14) × 3, 모든 코인 같음(전에는 코인별 1.5~2.5배). 청산가 검사도 이 거리로 합니다.
- **5년 시험에서 기대할 것** (research/mixchop_st/REPORT_KO.md, 계단 12→10 고정, 달마다 $50 새로 시작): 한 달 중앙값 고른 기간 ×0.25,
  확인 기간 ×0.25. 지금 친구 봇(×0.24 / ×0.14)보다 조금 낫지만, 대부분의 달에 잔고가 줄어드는 쪽입니다. 작은 돈으로 보는 시험입니다.
- **바닥선 70%:** 증거금 40%면 손절 두 번쯤에 시작의 70% 아래로 내려가 새 진입이 멈출 수 있습니다(5년 시험은 바닥선을 끄고 셈).
  바꾸려면 서버 설정의 `equity_floor_frac`를 고칩니다(두 분이 정할 일).
- **화면·알림:** 텔레그램 시작 메시지에 `매매법 친구 매매법 + 슈퍼트렌드·스톡RSI(같은 봉이면 친구 매매법 먼저) · 손절 ATR 3배(모든 코인)`,
  진입 메시지에 `근거(슈퍼트렌드·스톡RSI): …` 또는 `근거(친구 매매법): …`. 실거래 사이트 "최근 48시간"에 `SOL 슈퍼트렌드·스톡RSI 골든크로스`
  같은 줄(K·D, RSI26 값과 함께). 아침 점검에 `스톡RSI 크로스 N번`, 놓친 신호 다시 계산도 두 매매법을 각각 계산합니다.
- **나스닥 개장·횡보 대책 시험** (research/mixchop_st/OPENTIME_REPORT_KO.md): 이 설정에는 넣지 않는 것을 권합니다. A6(이익이면 본전, 손해면
  닫기)는 두 기간 모두 나빴고, A2(이익이면 본전)는 기준은 넘었지만 5년 4,849번 중 20번만 바뀌어 차이가 거의 없습니다.
