# 청산 비교 리그 설치 안내 (두 분용)

두 분 말씀(2026-10-12): "규칙봇은 그대로 두고 커스텀값봇들을 익절기준이랑 손절기준을 좀 바꾸고 싶어서".
이 안내대로 하면 **후보 리그(커스텀값 봇)만** 바뀝니다. 규칙봇은 손대지 않습니다.

## 무엇이 바뀌나

후보 49개(지금 돌던 16개 매매법의 38개 + 약한 단서 11개)마다 아래 계좌를 **같은 신호 · 같은 크기(규칙봇과 같은 크기)** 로 나란히 돌립니다.
모든 계좌가 **고른 커스텀값**으로 돌고, 기본수치 계좌는 없습니다(기본수치는 규칙봇이 이미 돌립니다).
**메인은 새 구조 6종**(구조 확실히 무너지면 빠른 손절 · 매매법 자체 판단 · 스위칭 · 손절 좁힘 · 처음 손절을 자체 무효화 가격에 · 자체 구조 청산 + 자체 익절 목표)이고, 모두 **매매법마다 자기 구조·가격 기준**으로 판단합니다. 이 중 **"구조 확실히 무너지면 빠른 손절"이 실전 후보**입니다. 약한 단서 11개 매매법은 연구에 자체 구조 코드가 없어서, **이 리그가 새로 정한 구조 기준**(그 매매법의 지표로, 아래 표 아래 설명)으로 같은 계좌를 만듭니다. 이 11개의 기준은 연구가 검증한 것이 아니라 우리가 정한 것입니다. **대조는 원래 메인이던 고정 손절 구조**("계단 익절 · 손절 최대 2 ATR" 등 4개)입니다. 메인이 대조보다 나은지 같은 신호에서 나란히 봅니다. 모든 매매법에 같은 3봉 구조를 쓰는 "구조 청산"은 자체 판단과 비교하는 연구용입니다. 나머지도 청산만 다르게 가정한 연구용 모의입니다. 모두 같은 신호 · 같은 크기 · 같은 엔진이라 '메인'과 '대조'는 이름과 화면 순서의 차이일 뿐입니다.

※ 과거 백테스트로 검증한 것은 **진입에 쓰는 커스텀값**이고, 위 청산 구조들은 이 값으로 직접 검증하지 않았습니다. 그래서 원래 구조(대조)와 동전 던지기 계좌를 옆에 둡니다.

## 설치 (규칙봇 서버에서, 10~15분)

개발자가 "코드 올렸습니다"라고 한 뒤에 합니다. 아래 명령을 한 줄씩 복사해 붙여 넣으세요.

**1. 최신 코드 받기**
```bash
cd /root/crypto-bot-research && git fetch origin claude/keen-pasteur-wav02u && git checkout claude/keen-pasteur-wav02u && git pull origin claude/keen-pasteur-wav02u
```

**2. 엔진 잠깐 멈추기** (대시보드는 계속 켜져 있어도 됩니다)
```bash
sudo systemctl stop candleague-live candleague-watch.timer
```

**3. 지금 기록 사본 만들기** (원본은 그대로 둡니다)
```bash
D=$(date -u +%Y%m%d)
sudo -u candleague /opt/candleague/venv/bin/python -I -c "import sqlite3,sys; s=sqlite3.connect('/var/lib/candleague/league.db'); d=sqlite3.connect(sys.argv[1]); s.backup(d); d.close(); s.close(); print('사본 완료:', sys.argv[1])" /var/lib/candleague/league_watch_1011_to_$D.db
sudo cp -p /var/lib/candleague/league_start.json /var/lib/candleague/league_watch_1011_to_${D}_start.json
ls -la /var/lib/candleague/
```
`league.db`, `league_start.json`과 새 사본 `league_watch_1011_to_(날짜).db`가 모두 보이면 됩니다.

**4. 규칙 파일 쓰기** (저장소 밖, 서버에만 있는 파일)
```bash
sudo cp /root/crypto-bot-research/candleague/data/rules_owner_exits.json /etc/candleague/rules.json
sudo chown root:candleague /etc/candleague/rules.json && sudo chmod 640 /etc/candleague/rules.json
```

**4-2. 후보 파일 복사** (지금 후보 38개 + 약한 단서 11개 = 49개)
```bash
sudo cp /root/crypto-bot-research/candleague/data/candidates_owner.json /etc/candleague/candidates.json
sudo chown root:candleague /etc/candleague/candidates.json && sudo chmod 640 /etc/candleague/candidates.json
```

**5. 설치 시각을 정하고 설정 파일에 적기** (설치 시각 = 지금을 5분 단위로 내린 UTC 시각)
```bash
T=$(date -u -d "@$(( $(date +%s) / 300 * 300 ))" +%Y-%m-%dT%H:%MZ); echo "설치 시각: $T"
sudo sed -i '/^# 청산 비교 리그/d;/^CANDLEAGUE_RULES=/d;/^CANDLEAGUE_CANDIDATES=/d;/^CANDLEAGUE_DB=/d;/^CANDLEAGUE_START=/d;/^CANDLEAGUE_EXPECT_START=/d;/^CANDLEAGUE_EQUITY=/d;/^CANDLEAGUE_MIN_LEV=/d' /etc/candleague/candleague.env
printf '%s\n' "# 청산 비교 리그 (설치 $T)" "CANDLEAGUE_RULES=/etc/candleague/rules.json" "CANDLEAGUE_CANDIDATES=/etc/candleague/candidates.json" "CANDLEAGUE_DB=/var/lib/candleague/league_exits.db" "CANDLEAGUE_START=$T" "CANDLEAGUE_EXPECT_START=$T" "CANDLEAGUE_EQUITY=1000" "CANDLEAGUE_MIN_LEV=30" | sudo tee -a /etc/candleague/candleague.env > /dev/null
sudo grep -E '^CANDLEAGUE_(RULES|CANDIDATES|DB|START|EXPECT_START|EQUITY|MIN_LEV)=' /etc/candleague/candleague.env
```
화면에 나온 **설치 시각(예: 2026-10-13T03:05Z)을 적어 두세요.** 마지막 줄에 일곱 줄(RULES, CANDIDATES, DB, START, EXPECT_START, EQUITY=1000, MIN_LEV=30)이 보이면 됩니다.
엔진은 시작 시각이 이 설치 시각과 다르면 아무것도 쓰지 않고 멈춥니다(시작 지킴이). 그러니 날짜가 엉뚱하게 시작될 일은 없습니다.

## 서버 부담 (CPU · 메모리)

후보 리그 엔진은 CPU 한 개의 30%, 메모리 1.3 GB까지만 쓰도록 묶여 있습니다(규칙봇 보호). 계좌 수는 190개 → 1,384개로 7배 남짓 늘어납니다(1,188계좌일 때 한 번 처리에 약 12초가 걸렸고, 이번에는 약 14초로 예상. 5분 주기 안에서 여유가 있습니다).
이 PC(Xeon 2.8 GHz)에서 가짜 시세(6코인, 실제 후보 38개 · 실제 매매법 코드)로 재 본 값:

| | 지금 리그 (190계좌) | 청산 비교 리그 (189계좌) |
|---|---|---|
| 5분마다 한 번 계산 (기록 쓰기 포함) | 평균 1.2초 | 평균 1.0초 |
| 하루치 따라잡기 | 약 5.4초 | 약 3.9초 |
| 메모리 최대 | 약 170 MB | 약 185 MB |

- 5분(300초)마다 1초 남짓(가장 길 때 3초)이라 평균으로는 CPU 한 개의 1%도 안 됩니다. 30% 제한 아래에서는 같은 계산이 3~10초쯤 걸릴 뿐입니다.
  서버의 실제 값은 대시보드 **서버 상태**의 '한 번 처리 시간'과 '엔진 메모리 (최대)'에 나옵니다.
- 엔진을 다시 켤 때(업데이트 등)는 열린 이동평균 · 반납 보호 포지션마다 1분 봉을 다시 받아 상태를 맞춰 보느라 처음 한 번 몇십 초 더 걸릴 수 있습니다.
- 메모리는 한도 1.3 GB의 2할도 안 됩니다. 실제 서버 값은 대시보드 **서버 상태**의 메모리 칸에서 볼 수 있습니다.
- 시세를 받아 오는 시간(바이낸스 응답 대기)은 CPU를 쓰지 않아 위 숫자에 없습니다. 지금 리그와 같습니다.

## 읽는 법 (짧게)

대시보드 위쪽 메뉴는 두 줄입니다: 묶음 탭(거래 · 홈 · 분석 · 매매법 · 안내) 아래에 지금 묶음의 화면만 나옵니다.

- **요약**: 계좌 종류별 한눈에, 14일째 · 28일째 일정, 판정 한 줄.
- **판정**: 미리 정한 규칙으로 승자를 가리는 화면. 14일째는 보기만 하고, 28일째에 한 번만 판정합니다.
- **메인 vs 대조** · **짝 비교** · **청산 이유** · **발동 기록**: 새 청산 구조가 원래 방식(대조)과 같은 신호에서 어떻게 달랐는지.
- **목표 진척도**: 승률 70% · 하루 1~3번 진입 · 거래당 +10% · 한 달 4배 · 낙폭에 지금 얼마나 가까운지.
- **한 달 시뮬**: 지금 성적이 한 달 이어진다면 $1,000이 얼마가 될 수 있는지(5%~95% 범위)와, 동전 던지기도 이만큼 나오는지.
- **조건별**: 요일 · 시간대 · 방향 · 코인 · 봉 · BTC 추세 · 변동성별로 언제 잘 맞고 안 맞았는지(탐색용, 판정에 쓰지 않음).
- **위험 점검**: 포지션이 한쪽 방향에 몰렸는지, 가장 나빴던 거래 · 연속 손실 · 낙폭.
- **계좌 비교**: 후보마다 계좌 종류별 한 줄(잔고 수익률 · 거래 수 · 승률 · 보유 시간 중앙값).
- 거래가 적은 동안(후보마다 30번 전)은 운이 큽니다. 며칠 성적으로 청산을 바꾸지 말고, 28일째 판정을 보고 두 분이 정하시면 됩니다.

연구 전체 지도와 앞으로의 시험(비용 · 두 분 결정이 필요한 것)은 `docs/candleague-research-roadmap-ko.md`에 있습니다.

## 화면 추가: 거래 다시보기 · 왜 이 수익률인가

화면만 늘었습니다. 리그 엔진 · 규칙 · 기록은 그대로라서 **리그를 다시 시작할 필요가 없습니다** (거래 기록도 안 지워집니다). 코드를 받은 뒤 평소처럼 `git pull` → 설치 스크립트 → 브라우저 강력 새로고침(Ctrl+Shift+R)만 하세요.

- **거래 다시보기**: 거래 한 건을 봉 하나씩 다시 봅니다. ▶ 재생 · ❚❚ 멈춤 · 한 봉씩 ◀ ▶ · 1x 2x 4x. 진입가 · 처음 손절 · 익절 · 청산가 선과 "진입: …", "N봉 뒤 가장 유리했을 때 …", "가장 불리했을 때 …", "청산: …" 설명이 봉마다 나옵니다. 진입 차트 · 체결 기록 · 계좌 화면의 거래 줄에 있는 '다시보기'를 누르면 열립니다. 거래 한 건의 이야기일 뿐 매매법의 판정이 아닙니다. 계단 잠금선은 그리지 않습니다(잠금 단계 가격이 거래 기록에 없음).
- **왜 이 수익률인가** (계좌 자세히 맨 위 카드): 시작 잔고에서 지금까지, 나간 이유별(손절 · 계단 잠금 · 규칙 청산 · 익절 · 강제청산) 개수와 손익, 이긴 비율과 본전에 필요한 비율, 가장 큰 손실 3번과 전체 손실 대비 비율. 닫힌 거래 30번 전에는 '표본 적음'이라고 적습니다. 딥시크 금액 숨김 설정에서는 개수만 보여 줍니다. 후보 리그의 거래 기록은 순손익만 남겨서 수수료 폭포는 없습니다.

## 화면 추가: 손실 해부

진 거래를 따로 모아 "어떤 식으로 졌는지"를 보여 주는 화면(분석 묶음의 **손실 해부**)이 늘었습니다. 규칙봇의 손실 카드는 AI 회의에서 나와서 그대로 가져올 수 없어서, 이 리그의 닫힌 거래 기록만으로 계산합니다. 숫자와 설명만 보여 주고 무엇을 하라는 말은 없습니다.

- **리그는 다시 시작하지 않습니다.** 규칙 · 계좌 · 거래 기록은 그대로이고, 엔진만 새 코드로 다시 켜집니다 (읽기만 하는 계산 한 블록이 추가됨). 순서는 평소와 같습니다: `git pull` → 설치 스크립트(`sudo bash deploy/candleague/install_candleague.sh`) → 브라우저 강력 새로고침(Ctrl+Shift+R).
- **숫자는 다음 5분 스냅샷부터 나옵니다.** 그전에는 화면에 '준비 중'이라고 나옵니다. 그것은 고장이 아닙니다.
- 진 거래를 일곱 가지 유형(강제청산 · 벌었다가 놓침 · 조금 벌었다가 놓침 · 규칙 청산으로 잃음 · 손절보다 크게 잃음 · 오래 끌다 잃음 · 처음부터 불리하게 감)으로 나누고, 코인 · 롱/숏 · 배수 · 시간대 · 평일/주말별로 보여 줍니다. 연속으로 진 최다, 여러 계좌가 같은 신호에서 함께 진 비율, 가장 크게 진 거래 10개(각각 '다시보기' 링크)도 있습니다.
- 처음 화면은 핵심 2개(빠른 손절 + 원래 방식)입니다. 진 거래가 30건 미만이면 '표본 적음'이라고 적으니 결론을 내지 마세요. 딥시크 금액 숨김 설정에서는 딥시크 계좌를 모든 숫자에서 뺍니다.

## 화면 추가: 레버리지 비교 · 놓친 신호

화면만 늘었습니다 (분석 묶음, 손실 해부 바로 뒤). 엔진 · 규칙 · 계좌 · 거래 기록은 그대로이고, 스냅샷에 새 블록도 없어서 **리그를 다시 시작하거나 엔진을 다시 켤 필요가 없습니다.** 코드를 받은 뒤 평소처럼 `git pull` → 설치 스크립트(`sudo bash deploy/candleague/install_candleague.sh`) → 브라우저 강력 새로고침(Ctrl+Shift+R)만 하세요.

- **레버리지 비교**: 빠른 손절 · 원래 방식 각각을 30배 규칙 계좌(-fq, -ld)와 40배 · 50배 고정 계좌(-fq40 -fq50 -ld40 -ld50)로 나란히 놓습니다. 거래 수 · 이긴 비율 · 거래당 평균 ROE · 총 수익률 · 가장 큰 손실 · 최대 낙폭 · 강제청산 횟수를 보여 주고, 한 줄로 차이만 적습니다. 위험 비교이지 높은 배수가 낫다는 증거가 아닙니다 (배수가 오르면 포지션이 지갑의 약 9배 → 16배 → 25배로 커집니다). 40배 · 50배 계좌가 기록에 없으면 '준비 중'이라고 나옵니다.
- **놓친 신호**: 계좌 종류마다 들어온 신호 중 진입 · 이미 포지션이 있어 건너뜀 · 거절이 몇 개이고 몇 %인지, 진입 비율이 낮은 매매법 10개를 보여 줍니다. 거절 이유별 건수는 기록하지 않아서 횟수만 나옵니다.
- 두 화면 모두 거래가 30건 미만이면 '표본 적음'이라고 적으니 결론을 내지 마세요.
