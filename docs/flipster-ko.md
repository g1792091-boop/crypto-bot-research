# 플립스터 실행기 (10/23, "플립스터로 확정할게 만들어줘")

두 분이 10/23에 정했습니다: **"VWAP 개선판" 페이퍼 봇을 따라가는 세 번째 실거래 실행기를 플립스터(flipster.io)로 만든다.**

## 무엇이 바뀌나

- **세 번째 실행기**가 생깁니다. 플립스터 USDT 무기한 선물로 거래합니다.
  - 따라가는 페이퍼 봇: **VWAP 개선판** (`/var/lib/paperbot/combo/vwap.db`, 계좌 `COMBO@mix`)
  - 서비스 `paperbot-executor-flipster`, 설정 `/etc/paperbot/executor-flipster.json`(원본 `deploy/executor.live-flipster.json`),
    DB `/var/lib/paperbot/exec/executor-flipster-live.db`
  - 텔레그램과 실거래 사이트에는 **"플립스터"**, 알림 머리말은 `[플립스터 실거래 실행기]`로 나옵니다.
- **바이비트 실행기와 WOO X Pro 실행기는 그대로입니다.** 이름·서비스·설정·DB·매매 규칙 모두 안 바뀝니다.
- 매매 규칙은 WOO X Pro의 VWAP 설정과 같습니다:
  - 1포지션, 시장가만, 6개 코인(BTC, ETH, SOL, DOGE, LTC, BCH)
  - 배수는 페이퍼를 그대로 따릅니다: VWAP 개선판은 **BTC도 30배**라서 진입할 때마다 그 코인을 30배로 맞추고 들어갑니다.
    (켤 때는 다른 실행기와 같은 기본값 BTC 40배·나머지 30배로 맞춰 두고, 진입 직전에 페이퍼 배수로 다시 맞춥니다.)
  - 계단 익절 거래소 기준(첫 잠금 +10%, 간격 2%, 단계 5%), 신호등(최근 20번 중 75% 이상), 손절 한 번 최대 손실 계좌의 20%
- **수수료:** 플립스터는 수수료를 다 떼고, 페이백 앱으로 가입한 몫은 나중에 따로 돌려받습니다.
  - 봇은 다 떼인 수수료로 계산합니다. 설정의 `net_costs`에 테이커 0.06%(두 분이 알려 준 숫자)를 넣었습니다.
  - 플립스터 API 문서에는 수수료율 숫자가 없습니다. drill 결과의 `fee_rate_pct`가 실제로 떼인 수수료입니다.
    0.06%와 다르면 알려 주세요. 설정을 맞추겠습니다.
  - 페이백은 봇 밖의 돈이라 봇 계산에 넣지 않습니다.

## 문서로 확인한 것과, 실제로 해 봐야 아는 것

플립스터 공식 API 문서(api-docs.flipster.io)로 확인했습니다:
- 주소 `https://trading-api.flipster.io`, 모든 요청에 키 서명(`api-key`, `api-expires`, `api-signature`)
- 시장가 주문: 바로 체결되고, 못 채운 부분은 취소됩니다. 그래서 상태만 믿지 않고 **체결 기록으로 실제 체결량을 다시 읽습니다.**
- 손절: `STOP_MARKET`(발동 가격 = `price`), 청산 전용(`reduceOnly`)
- 대기 주문, 주문 기록, 체결 기록(수수료, 펀딩 포함), 포지션, 잔고, 레버리지·격리, 단방향 모드, 1분봉, 서버 시간
- 단방향 모드는 포지션이 있으면 바꿀 수 없습니다(문서). 실행기는 켤 때 단방향으로 맞추고 답을 확인해 DB에 적어 둡니다.

문서로 알게 된, 다른 거래소와 다른 점:
- **플립스터 API에는 "우리 주문 번호(client order id)"가 없습니다.** 실행기는 우리 번호가 있어야 답이 끊긴 주문을 다시 찾습니다.
  그래서 **실행기 DB 안에 주문 장부(`flipster_ids` 표)** 를 둡니다.
  - 주문을 보내기 **전에** 장부에 적고, 답이 오면 플립스터 주문 번호를 같이 적습니다.
  - 답을 못 받으면 플립스터 주문 기록에서 같은 주문(코인, 방향, 수량, 시각)을 찾습니다. 기록에 늦게 올라올 수 있어
    **25초까지는 "아직 모름"** 으로 기다립니다. 맞는 주문이 둘 이상이면 "모름"으로 두고 알립니다(없다고 하지 않습니다).
  - **진입 주문은 절대 두 번 보내지 않습니다.** 장부에 적지 못하면 진입하지 않습니다. 손절과 청산은 장부에 못 적어도 보냅니다
    (보호가 먼저).
  - 장부는 실행기 DB에 같이 있어서 밤마다 같이 백업됩니다. 30일 지난 줄은 지웁니다. 진입 주문 줄은 98일 둡니다(손익 계산의
    시작점이라서).
- 플립스터는 체결마다 손익을 주지 않습니다. 봇이 체결 가격으로 다시 계산하는데, **우리 진입 주문의 첫 체결(포지션이 없던 곳)부터만**
  계산합니다. 시작점을 못 찾거나 체결이 맞아떨어지지 않으면 그 거래는 체결 계산 대신 지갑 변화로 잡고 알립니다.
- 손절은 **대기 주문 목록에 보일 때만** "걸렸다"고 봅니다. 약 5초 기다려도 목록에 없으면 새 포지션은 닫고, 손절 옮기기면 옛 손절을
  그대로 둡니다. 주문 기록의 "대기(NEW)"만으로는 확인하지 않습니다(기록이 늦으면 이미 취소된 손절이 "대기"로 보일 수 있습니다).
- 계약 정보에 **최소 주문 금액이 없는 코인**은 0으로 보지 않습니다. 그 코인은 새 진입만 하지 않고(이유를 적음), 열린 포지션의
  손절·청산은 그대로 합니다. 실행기는 그대로 켜집니다. `specs`·`check`에 "최소 주문 없음 → 새 진입 안 함"으로 나옵니다.
- 입출금 기록을 읽는 API가 문서에 없습니다. 봇은 입출금을 따로 알아보지 못합니다. 선물 계좌에 돈을 넣고 빼는 것은 **포지션이 없을
  때** 하고 알려 주세요.
- 요청 한도 숫자가 문서에 없습니다("키마다 초당·분당 한도"). 봇은 스스로 **초당 8번, 분당 240번 이하**로 보내고, 한도 답(429)이
  오면 읽기는 기다렸다가 다시 읽습니다. 주문에 한도 답이 오면, 문서에 한도 답이 "막거나 거절한다"고 되어 있어 주문이 들어갔을
  수도 있으니 **먼저 우리 번호로 주문 기록을 찾습니다.** 진입·청산 주문은 다시 보내지 않습니다. 손절은 처음 찾았을 때 어디에도
  없으면 **같은 번호로 한 번만 더** 보냅니다(손절이 둘 걸리면 청산 전용이라 해가 없고, 실행기가 남는 하나를 취소합니다). 손절·청산은
  **최대 10초 안에서** 찾고, 못 찾으면 실행기의 원래 보호 동작이 이어받습니다(손절을 못 걸면 포지션을 닫고, 손절 옮기기가 안 되면
  옛 손절을 그대로 둡니다).
- `maxSlippagePrice`(가격 상한)는 보내지 않습니다. 청산은 반드시 다 닫혀야 하고, 문서에서 선택 항목이며, 페이퍼 규칙도 그냥
  시장가입니다.
- 플립스터 API는 지금 **일부 사용자에게만 열려 있다**고 문서에 적혀 있습니다(private launch). 계정의 API 관리 메뉴가 없으면 플립스터
  고객센터에 API 사용을 신청해야 합니다.

아래는 실제 거래소에서만 확인됩니다. **drill이 하나씩 확인합니다:**
1. 손절 두 개가 **잠깐 동시에** 걸리는지. 손절을 옮길 때 "새 손절 → 확인 → 옛 손절 취소" 순서라서 필요합니다.
2. 손절이 **진짜로 발동해서** 포지션을 닫는지. "손절 발동 시험"이 마지막 가격 0.1% 옆에 손절을 걸고 최대 20분 기다립니다.
3. 손절이 **마지막 가격으로 발동하는지, 마크 가격으로 발동하는지**. 기다리는 동안 두 가격을 같이 보고 어느 쪽이 닿았는지 적습니다.
4. 발동한 손절의 체결이 그 손절의 주문 번호로 기록되는지(그래야 거래 손익을 체결로 정확히 잡습니다. 못 찾으면 지갑 변화로 잡습니다).
5. 가격 상한 없는 시장가가 다 체결되는지.
6. 실제 수수료율, 서버 시간 차이, 체결로 계산한 손익 = 지갑 변화.
7. 주문 장부: 방금 보낸 주문을 우리 번호로 찾는지, **답을 잃은 것처럼 해도** 주문 기록에서 같은 주문을 찾는지.
8. 레버리지 읽기(진입한 포지션의 배수·격리), 펀딩 기록의 +/− 부호(앱 화면과 비교해 주세요).
9. 새 손절이 대기 주문 목록에 **5초 안에** 보이는지(늦게 보이면 실행기가 새 포지션을 닫으니 알려 주세요). 그때 늦게 보인
   손절은 포지션 없이 남을 수 있는데, 청산 전용이라 포지션을 열지 않고 실행기가 다음 확인에서 취소합니다.

**drill이 모두 `[OK]`가 아니면 실행기를 켜지 않습니다.** 결과를 그대로 붙여 주시면 고칠 것을 고친 뒤 다시 합니다.

## 서버에서 하는 순서

명령은 서버에서 순서대로 한 번씩 합니다. **키 값은 채팅에 절대 쓰지 않습니다.**

**0) 코드 받기**

```bash
cd /root/crypto-bot-research && git pull && sudo bash deploy/install.sh
```

**1) 플립스터 준비 (앱·웹에서)**

- 신원 확인(KYC)을 끝냅니다.
- USDT를 입금하고 **선물(무기한) 계좌로 옮깁니다.**
- flipster.io 계정 → **API 관리**(API Management)에서 새 키를 만듭니다:
  - 권한: **읽기 + 거래만.** **출금 권한은 켜지 않습니다.**
  - IP 바인딩: **`158.247.200.152`** (서버 주소. 집 컴퓨터 주소가 아닙니다)
  - API 키와 비밀 키(Secret)는 한 번만 보입니다. 따로 안전하게 적어 둡니다.
  - API 관리 메뉴가 없으면 위에 적은 대로 플립스터 고객센터에 API 사용을 신청합니다.

**2) 키를 서버 키 파일에 넣기**

```bash
sudo nano /etc/paperbot/executor.env
```

아래 세 줄을 채우고(빈 줄이 이미 있으면 채우고) 저장합니다(Ctrl+O, Enter, Ctrl+X):

```
FLIPSTER_LIVE_KEY=(API 키)
FLIPSTER_LIVE_SECRET=(비밀 키)
FLIPSTER_LIVE_KEY_CHECKED=TRADE_ONLY_NO_WITHDRAW_IP_BOUND
```

- 마지막 줄은 "키를 '읽기 + 거래만, 출금 없음, 서버 IP만'으로 만들었다"는 두 분의 확인입니다. 플립스터는 키 권한을 API로 알려 주지
  않아서, 이 줄이 없으면 실행기가 켜지지 않습니다.
- 바이비트·MEXC·WOO X Pro 키와 같은 값이면 실행기가 거부합니다(거래소마다 다른 키).

**3) 6개 코인 정보 보기 (주문 없음)**

```bash
sudo /opt/crypto-bot-research/deploy/paperbot-exec.sh flipster specs
```

- 플립스터는 계약 정보도 키로만 읽을 수 있어서, 2)를 먼저 해야 합니다.
- 6줄(BTC, ETH, SOL, DOGE, LTC, BCH)에 `API 거래 가능`이 보여야 합니다. `최대`는 BTC 40배 이상, 나머지 30배 이상이어야 합니다.

**4) 읽기 점검 (주문 없음)**

```bash
sudo /opt/crypto-bot-research/deploy/paperbot-exec.sh flipster check
```

- 모든 줄이 `[OK]`여야 합니다: 서버 시간, 계약 정보, 선물 계정 읽기, 수수료율, 열린 주문, 펀딩 기록, 거래 모드 단방향, 격리 레버리지
  BTC 40배·나머지 30배(켤 때의 기본값입니다. 실제 진입은 페이퍼 배수 30배로 다시 맞춥니다), 키 확인.
- 레버리지 줄에 "확인 못 한 코인"이 있으면, 5)의 주문 시험에서 포지션으로 다시 확인합니다.

**5) 진짜 최소 주문 시험 (약 $6, 손절 발동 시험 포함, 최대 35분쯤)**

```bash
sudo /opt/crypto-bot-research/deploy/paperbot-exec.sh flipster drill --confirm-order REAL_ORDER
```

- 가장 싼 코인(보통 DOGE)으로 진입 → 주문 장부로 찾기 → 손절 걸기 → 손절 옮기기(두 개 동시) → 손절 발동 시험 → 정리 → 손익 대조를
  합니다. 수수료와 약간의 손실(몇 센트)이 납니다.
- 줄이 하나씩 바로 나옵니다. 기다리는 동안에는 `... 기다리는 중` 줄이 5분마다 나옵니다. 마지막 줄 `끝: drill …`이 나와야 끝난
  것입니다. 그 전에는 다른 명령을 치지 말고 창을 닫지 않습니다.
- **기다리는 동안 Ctrl+C를 누르지 않습니다.** 손절 발동 시험은 가격이 움직일 때까지 기다리는 것이 정상입니다(최대 20분).
- 그래도 멈추면(Ctrl+C, 창 닫힘, 오류) 시험 코인의 포지션을 닫고 주문·손절을 모두 취소한 뒤 끝납니다(`정리 후 상태` 줄).
  그 줄이 `[FAIL]`이면 앱에서 포지션과 주문을 직접 확인합니다.
- 이익 쪽 손절은 가격이 진입가보다 0.15% 유리하게 가야 시험할 수 있습니다. 10분 안에 안 가면 "확인 못 함"으로 넘어갑니다.
  그때는 반대 방향으로 한 번 더 합니다(`--side short`).
- 20분 안에 가격이 시험 손절에 닿지 않으면 "발동을 못 봤습니다"로 끝납니다(실패는 아님). 그때는 한 번 더 합니다.
- `손절을 발동시킨 가격` 줄이 "둘 다 지남"이나 "확인 못 함"이면 한 번 더 하면 가려질 수 있습니다.

**6) 결과 붙여 주기**

- 3)·4)·5)의 **결과 전체를 붙여 주세요.** 모두 `[OK]`인지, 수수료율과 발동 가격이 무엇인지 같이 봅니다.
- **drill이 모두 `[OK]`가 되기 전에는 실행기를 켜지 않습니다.**

## 실행기 켜기

drill이 모두 `[OK]`인 뒤에 `docs/vwap-bot-ko.md` 5-C 순서대로 합니다: 설정 파일 넣기 → 시작 금액 맞추기(`vwap_switch.py --exec
flipster --balance …`) → check-config·preflight → `sudo systemctl start paperbot-executor-flipster`. 끄는 법은 같은 문서 5-D.

## 같이 알아 두실 것

- 비상 정지는 그대로 `sudo touch /var/lib/paperbot/STOP` 하나로 세 실행기가 모두 멈춥니다.
