# 실거래 전 안전장치 (테스트넷 전용)

작성: 2026-10-01 (KST). 대상: 두 분(운영자). 코드: `paperbot/testnet.py`, `paperbot/risk.py`, `paperbot/executor.py`.

## 한눈에 보기
- **지금 있는 것:** paper 계좌 **1개**를 골라, 그 계좌가 하는 진입·잠금·청산을 바이낸스 **테스트넷(가짜 돈)**에 실제 주문으로 따라 하는 "실행기"와, 그 실행기를 막아 세우는 위험 규칙입니다.
- **없는 것:** 진짜 돈으로 주문하는 코드. 실행기는 테스트넷 주소(`testnet.binancefuture.com`)가 아니면 켜지지 않습니다. 실거래로 넘어가려면 따로 만들어야 할 것이 남아 있습니다(맨 아래 "실거래 전에 남은 일").
- **테스트넷이 보여주는 것과 못 보여주는 것:** 주문이 제대로 들어가고, 손절이 거래소에 걸리고, 옮겨지고, 오류와 재시작에서 살아남는지 확인합니다. 테스트넷 가격과 체결은 실제 시장과 다르므로 **수익이나 실제 슬리피지는 알 수 없습니다.**

## 1. 안전장치가 하는 일

### 1-1. 손절은 거래소에 걸어 둡니다
- 진입하자마자 손절 주문을 **바이낸스 서버에** 걸어 둡니다. 봇이나 서버가 죽어도 손절은 거래소가 실행합니다.
- 손절은 paper 규칙과 같은 **마지막 체결가**로 발동합니다(보충 규칙 Q4). 마크 가격이 아닙니다.
- 바이낸스는 2025-12-09부터 손절 같은 조건부 주문을 별도 창구("알고 주문")로만 받습니다. 그 창구로 보냅니다.
- 손절 주문은 "포지션을 줄이기만 하는" 주문(reduce-only)이라, 잘못 발동해도 반대 포지션을 새로 만들지 않습니다.
- 걸고 나면 거래소에 다시 물어서 **정말 걸려 있는지 확인**합니다.

### 1-2. 잠금(익절선) 올리는 순서
paper 계좌가 잠금을 올리면 거래소 손절도 따라 올립니다. 순서가 중요합니다.
1. **새 손절을 먼저 겁니다.** (잠깐 동안 손절이 2개 있습니다.)
2. 새 손절이 걸려 있는지 **확인합니다.**
3. 그다음에 **옛 손절을 취소합니다.**

그래서 손절이 하나도 없는 순간이 생기지 않습니다. 시험에서 모든 요청마다 이것을 검사합니다.

- 새 손절이 "이미 가격이 지나서 바로 발동한다"(바이낸스 오류 -2021)며 거절되면: **시장가로 바로 닫습니다**(reduce-only).
- 그 밖의 이유로 새 손절이 거절되면: 옛 손절은 그대로 두고(여전히 보호됨) 다음 반복에서 다시 시도합니다. 3번 연속 실패하면 텔레그램 **소리 있는 알림**을 보냅니다.

### 1-3. 매 반복마다 거래소와 대조 (약 3초마다)
실행기는 매번 거래소의 실제 상태를 읽고, 자기 기록과 맞춰 봅니다.

| 발견한 상황 | 하는 일 |
|---|---|
| 포지션이 있는데 손절이 없음 | **즉시 손절을 다시 겁니다.** 걸 수 없으면 바로 닫습니다. 소리 있는 알림 |
| 손절 수량이 포지션보다 작음(부분 체결 등) | 맞는 수량의 새 손절을 먼저 걸고 옛 것을 취소 |
| 손절이 2개 이상 남아 있음(중간에 끊긴 이동 등) | 맞는 손절 하나만 남기고 나머지 취소 |
| 손절 위치가 기록과 다름 | 기록대로 옮김(새 것 먼저) |
| 실행기가 모르는 포지션(다른 코인, 손으로 연 주문 등) | **바로 닫고** 소리 있는 알림 |
| 포지션 방향이 기록과 반대 | 닫고 **멈춤** |
| 실행기 기록엔 포지션이 있는데 거래소엔 없음 | 손절이 발동했는지 확인하고 거래를 마감 기록 |
| 포지션 없이 손절만 남아 있음 | 취소 |

**주의:** 실행기가 쓰는 테스트넷 계정에서 사람이 손으로 주문하면 "모르는 포지션"으로 보고 닫습니다. 같은 계정에서 손으로 거래하지 마세요.

### 1-4. 위험 규칙 (`paperbot/risk.py`)
결정은 네 가지입니다: **허용 / 줄여서 허용 / 막음 / 모두 닫고 멈춤**. 이유는 한국어로 기록되고 알림에 나갑니다.

| 규칙 | 걸리면 |
|---|---|
| 비상 정지 파일이 있음 | 모두 닫고 멈춤 |
| 하루 손실이 한도에 닿음(오늘 09:00 KST 시작 금액 대비, 열린 포지션 손실 포함) | 모두 닫고 멈춤 |
| 최고점 대비 낙폭이 멈춤 기준에 닿음 | 모두 닫고 멈춤 |
| 연속 손실 횟수가 기준에 닿음 | 모두 닫고 멈춤 |
| 레버리지가 상한보다 높음 | 상한으로 낮춰서 진입(줄여서 허용) |
| 포지션 크기가 상한보다 큼 | 상한에 맞게 줄여서 진입. 줄인 크기가 거래소 최소보다 작으면 진입 안 함 |
| 허용 코인이 아님 | 진입 안 함 |

- **멈춤은 저절로 풀리지 않습니다.** 실행기를 다시 켜도 멈춤 상태 그대로입니다. 사람이 아래 명령으로 풀어야 합니다.
- 같은 날 하루 손실로 멈춘 것을 풀면 곧바로 다시 멈춥니다(그날 한도는 그날 한도). 다음 날 09:00 KST 이후에 푸세요.
- 멈춤을 풀면 낙폭 기준점(최고점)과 연속 손실 수는 그 시점부터 새로 셉니다.
- 설정 값이 하나라도 비어 있으면 실행기는 **켜지지 않습니다.**

### 1-5. 비상 정지
- 설정에 적은 파일(예: `/var/lib/paperbot/STOP`)을 만들면, 실행기가 다음 반복(약 3초 안)에 **모두 닫고 멈춥니다.**
  ```
  sudo touch /var/lib/paperbot/STOP
  ```
- 파일을 지워도 멈춤은 그대로입니다. 풀려면: 파일을 지우고 → 실행기를 끄고 → `clear-halt` 명령(아래 3장).

### 1-6. 오류 처리
- **인터넷 끊김, 시간 초과, 거래소 5xx 오류:** 0.5 → 1 → 2초 간격으로 다시 시도합니다.
- **주문은 두 번 들어가지 않게:** 모든 주문에 고유 번호(client id)를 붙여 보냅니다. 응답을 못 받으면 먼저 그 번호로 거래소에 "이 주문 들어갔나?"를 물어보고, 없을 때만 다시 보냅니다.
- **거래소가 거절한 주문(4xx):** 그대로 다시 보내지 않습니다. 기록하고, 위 규칙대로 처리합니다(예: 손절을 못 걸면 포지션을 닫음).
- **요청 한도:** 거래소가 알려주는 사용량을 보고 한도의 80%에 가까우면 쉬어 갑니다. 429(너무 많음)면 거래소가 말한 시간만큼 기다리고, 418(일시 차단)이면 2분 이상 쉬고 소리 있는 알림을 보냅니다.
- 반복 중 오류가 나도 실행기는 멈추지 않고 기록 후 다음 반복으로 갑니다(3, 10, 30번째 연속 오류에 소리 있는 알림).

### 1-7. 재시작
- 진입 주문을 보내기 **전에** "진입 중"이라고 먼저 기록합니다. 그래서 주문 직후 꺼져도 다시 켜질 때 거래소를 보고 정리합니다:
  - 진입이 체결돼 있으면 → 이어받고 손절을 확인(없으면 즉시 걸기)
  - 체결이 안 됐으면 → 그 진입은 취소로 기록
- 열린 포지션, 현재 손절 위치, 멈춤 상태, 연속 손실 수가 모두 실행기 DB에 있어 재시작 뒤 그대로 이어집니다.

### 1-8. 기록
실행기는 **자기 DB 하나**(예: `/var/lib/paperbot/executor.db`)에만 씁니다. 한 번에 실행기 하나만 쓸 수 있게 잠금 파일(`executor.db.lock`)을 씁니다.

| 표 | 내용 |
|---|---|
| `events` | 모든 판단과 일(진입 검사, 손절 걸기·옮기기, 대조 결과, 오류, 재시도) |
| `requests` | 거래소에 보낸 모든 주문·취소 요청과 답(서명·키는 기록하지 않음), 그리고 실패한 모든 요청 |
| `trades` | 거래별 진입·청산·이유·손익 |
| `halts` | 멈춤과 해제(누가, 언제, 메모) |
| `state` | 재시작용 현재 상태 |

paper DB(`paper3.db`)는 **읽기만** 합니다.

### 1-9. 접근 막기
- **주소 잠금:** 테스트넷 주소가 아니면 연결 자체를 거부합니다. 바이낸스 "Demo Trading"(`demo-fapi.binance.com`)도 지금은 허용하지 않습니다(두 분이 Q6에서 고르면 추가).
- **실거래 모드 없음:** 설정의 `mode`가 `"testnet"`이 아니면 켜지지 않습니다. 실거래를 하려면 나중에 **별도 스위치, 별도 키 이름, 별도 주소 목록**을 따로 만들어야 하도록 나눠 두었습니다.
- **키 분리:** 테스트넷 키는 `TESTNET_API_KEY` / `TESTNET_API_SECRET`에만 둡니다. paper 실행기의 읽기 전용 키(`BINANCE_API_KEY`)와 같으면 켜지지 않습니다. 키는 저장소에 넣지 않습니다.
- **AI 에이전트는 주문하지 않습니다:** 에이전트·대시보드·paper 실행기·매일 점검 코드는 실행기와 테스트넷 코드를 불러오지 않습니다(시험으로 확인).

## 2. 두 분이 정할 것 (보충 규칙 Q6)
설정 파일 `/etc/paperbot/executor.json`(서버에만, 저장소에 넣지 않음)에 적습니다. 빈 칸이 있으면 실행기가 켜지지 않습니다.

| 설정 이름 | 뜻 | 두 분 결정 |
|---|---|---|
| `account` | 따라 할 paper 계좌(예: `V45_AMB@15m`) | ☐ ____ |
| `qty_scale` | 실행기 수량 = paper 수량 × 이 값(예: 0.02 → $5,000 계좌를 $100 규모로) | ☐ ____ |
| `risk.daily_max_loss_usd` | 하루 최대 손실($) | ☐ $____ |
| `risk.max_drawdown_pct` | 멈춤 낙폭(비율, 20%면 0.2) | ☐ ____ |
| `risk.max_consecutive_losses` | 연속 손실 멈춤(번) | ☐ ____ |
| `risk.max_leverage` | 최대 레버리지(배) | ☐ ____ |
| `risk.max_notional_usd` | 포지션 하나의 최대 크기($, 레버리지 포함 금액) | ☐ $____ |
| `risk.allowed_symbols` | 거래 허용 코인 | ☐ ____ |
| `risk.kill_file` | 비상 정지 파일 경로 | `/var/lib/paperbot/STOP` 추천 |
| `stop_from` | `"ratio"`: paper 손절과 같은 **비율 거리**를 실제 체결가에 적용(추천, 테스트넷 가격이 실제 시장과 달라서) / `"price"`: paper 손절 **가격 그대로** | `"ratio"` 추천 |
| `max_entry_age_s` | paper 진입이 이 초보다 오래됐으면 따라 하지 않음 | 180 추천 |
| `paper_stale_s` | paper 기록이 이 초 동안 멈춰 있으면 새 진입 안 함 | 300 추천 |

예시(숫자는 자리만 채운 것입니다. 두 분이 정한 값으로 바꾸세요):
```json
{
  "mode": "testnet",
  "account": "V45_AMB@15m",
  "paper_db": "/var/lib/paperbot/paper3.db",
  "db": "/var/lib/paperbot/executor.db",
  "qty_scale": 0.02,
  "stop_from": "ratio",
  "risk": {
    "daily_max_loss_usd": null,
    "max_drawdown_pct": null,
    "max_consecutive_losses": null,
    "max_leverage": null,
    "max_notional_usd": null,
    "allowed_symbols": ["BTCUSDT", "ETHUSDT", "SOLUSDT", "DOGEUSDT", "LTCUSDT", "BCHUSDT"],
    "kill_file": "/var/lib/paperbot/STOP"
  }
}
```
**참고:** 하루 손실과 낙폭은 거래소 계정 **전체 잔고**로 계산합니다. 테스트넷 계정에는 가짜 돈이 많이 들어 있어서(예: 수천~수만 USDT) %가 작게 나옵니다. 실거래 때는 실행기 전용 하위 계정에 **정한 금액만** 넣어야 숫자가 뜻대로 작동합니다.

그 밖에 정할 것:
- ☐ 주문 연습 환경: 테스트넷(지금 코드) / Demo Trading(추가 작업 필요)
- ☐ 실행기 담당자(멈춤 해제를 누가 하는지)

## 3. 서버에서 하는 테스트넷 연습

### 준비 (한 번)
1. https://testnet.binancefuture.com 에 로그인해 테스트넷 API 키를 만듭니다(진짜 바이낸스 계정 키가 아닙니다).
2. 서버에 키 파일을 만듭니다(저장소에 넣지 않음):
   ```
   sudo install -m 600 -o paperbot /dev/null /etc/paperbot/testnet.env
   sudo nano /etc/paperbot/testnet.env
   # 두 줄:
   # TESTNET_API_KEY=...
   # TESTNET_API_SECRET=...
   ```
3. 위 2장의 설정 파일을 `/etc/paperbot/executor.json`에 만들고 확인합니다:
   ```
   cd /opt/crypto-bot-research && sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.executor check-config --config /etc/paperbot/executor.json
   ```
   "준비됨"이 나와야 합니다. 아니면 빠진 항목이 한국어로 나옵니다.
   (코드는 `/opt/crypto-bot-research`, 파이썬은 `/opt/paperbot/venv`입니다. `deploy/install.sh`와 같은 경로입니다. 아래 명령은 모두 `/opt/crypto-bot-research`에서 실행합니다.)

### 1단계: 주문 연습(drill), 롱·숏 각각
```
cd /opt/crypto-bot-research
sudo -u paperbot bash -c 'set -a; . /etc/paperbot/testnet.env; set +a; /opt/paperbot/venv/bin/python -m paperbot.testnet drill --symbol BTCUSDT --side long'
sudo -u paperbot bash -c 'set -a; . /etc/paperbot/testnet.env; set +a; /opt/paperbot/venv/bin/python -m paperbot.testnet drill --symbol BTCUSDT --side short'
```
9줄 모두 `[OK]`여야 합니다:
1. 시작 전 포지션·주문 없음
2. 레버리지 설정
3. 시장가 진입 체결
4. 포지션 크기 일치
5. 손절이 거래소에 걸림(알고 주문, 마지막 체결가)
6. 손절 옮기기: 새 손절이 걸린 뒤(이때 2개) 옛 손절 취소
7. 재시작 점검: 손절을 일부러 지우면 다시 걸어 놓음
8. 가격보다 잘못된 쪽에 건 손절이 -2021로 거절되고, 시장가로 닫힘
9. 포지션·주문 모두 없음

하나라도 `[FAIL]`이면 실행기를 켜지 말고 그 출력 전체를 개발 쪽에 보내 주세요. 연습 코드는 실패해도 테스트넷 계정을 비워 두려고 시도합니다.

### 2단계: 실행기 켜기 (paper 실행기가 돌고 있어야 함)
```
sudo -u paperbot bash -c 'set -a; . /etc/paperbot/testnet.env; set +a; /opt/paperbot/venv/bin/python -m paperbot.executor run --config /etc/paperbot/executor.json'
```
다른 창에서 상태 보기:
```
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.executor status --db /var/lib/paperbot/executor.db
```

### 3단계: 일부러 문제를 만들어 보기 (포지션이 열려 있을 때)
| 해 볼 것 | 기대하는 결과 |
|---|---|
| 테스트넷 웹 화면에서 손절 주문을 취소 | 3초 안에 손절이 다시 걸리고 소리 있는 알림 |
| 테스트넷 웹 화면에서 다른 코인 포지션을 손으로 열기 | 바로 닫히고 "모르는 포지션" 알림 |
| 실행기를 Ctrl+C로 끄고 1분 뒤 다시 켜기 | 포지션과 손절 그대로 이어받음, 손절이 없었다면 다시 걸림 |
| `sudo touch /var/lib/paperbot/STOP` | 모두 닫히고 "거래를 멈춥니다" 알림, 다시 켜도 멈춤 |
| 서버 인터넷을 잠깐 끊기(가능하면) | 재시도 기록, 주문이 두 번 들어가지 않음 |

### 4단계: 멈춤 풀기
```
sudo rm /var/lib/paperbot/STOP             # 비상 정지 파일이 있었다면
# 실행기를 먼저 끕니다(Ctrl+C). 켜져 있으면 해제 명령이 거부됩니다.
sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.executor clear-halt --config /etc/paperbot/executor.json --by 이름 --note "이유"
```
누가 언제 왜 풀었는지 `halts` 표에 남습니다.

## 5. 실거래 전에 남은 일
1. **실거래 모드 자체:** 별도 스위치, 별도 키 이름, 별도 주소 목록, 출금 권한 없는 거래 키, 서버 IP 제한, 정한 금액만 넣은 하위 계정. 지금은 일부러 없습니다.
2. **진입 지연:** paper 계좌는 1분봉이 끝난 뒤에 진입을 기록하므로, 실행기는 paper보다 **1~2분 늦게** 진입합니다. 실거래 전에 신호 서비스에서 바로 받도록 바꿔야 합니다.
3. **거래소 실시간 알림(사용자 데이터 스트림):** 지금은 3초마다 묻는 방식입니다. 손절 발동·체결을 즉시 받는 연결이 필요합니다.
4. **청산가 확인:** 실제 크기·레버리지에서 손절이 청산가보다 안쪽인지 거래소 값으로 다시 확인하는 기능이 없습니다(paper는 확인함).
5. **손익 계산:** 지금은 진입 전후 지갑 잔고 차이로 계산합니다(수수료·펀딩 포함, 근사). 실제 체결 내역으로 바꿔야 Q6 4번(실제 비용 ÷ 가정 비용 ≤ 1.5)을 잴 수 있습니다.
6. **서버 운영:** 실행기용 systemd 서비스(자동 재시작, 권한 제한), 서버 밖 생존 감시(멈추면 폰 알림), `executor.db` 백업, 주기적 시간 맞추기.
7. **거래소 사정:** 점검 시간, 코인 거래 중지·상장 폐지, 헤지 모드로 바뀐 계정 같은 경우의 처리.
8. **테스트넷 운영 기록:** 위 3장 연습을 모두 통과하고, 테스트넷에서 일정 기간(두 분이 정함) 설명 안 되는 사건 없이 돌아야 합니다.
9. **규칙 조건:** 보충 규칙 Q3(최소 90일), Q6(거래 200건, 우연 아님, 국면 2개, 비용 확인)을 모두 만족해야 합니다. 아무것도 통과하지 못하면 실거래는 하지 않습니다.
