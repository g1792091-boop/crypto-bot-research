## 0. 두 분이 확정한 사항
| 항목 | 결정 |
|---|---|
| 자동 전략 발굴 (유전 프로그래밍·강화학습·AutoML) | **포함** |
| AI 자율 실행 L4 (전략 수정까지 자동) | **포함** |
| 대형 기술 스택 (Kafka·Airflow 등) | **포함** |
| 전략 연구원 가설 수 | **무제한** |

| 익절 기준 | **ROE** |
| 증거금 크기 | 차트 상황에 맞게 자동 결정 |
| 모의거래 방식 | 바이낸스 Demo Trading이 아니라 **봇 자체 paper 모드** |
| 검증 원칙 | **과최적화 없이, 팩트로만** |
| 매매법 | 다른 채팅에서 과거 차트 테스트 중. 끝나면 전달 |

"과최적화 없이, 팩트로만"은 이 문서 전체에 적용되는 규칙입니다.
- **팩트**: 데이터와 계산으로 확인된 것입니다. 확인되지 않은 것은 **가설**로 표시하고, 검증을 통과하기 전에는 수익 근거로 쓰지 않습니다.
- **과최적화 방지**: 규칙과 기준값은 테스트를 보기 **전에** 정하고 기록합니다. 모든 시도 횟수를 세고, 한 번도 보지 않은 데이터(paper 모드의 미래 데이터)에서 확인합니다.

## 1. paper 모드란 (Demo Trading과의 차이)
| 항목 | 바이낸스 Demo Trading | 봇 자체 paper 모드 (채택) |
|---|---|---|
| 주문 | 바이낸스 데모 서버로 실제 API 주문 | 거래소에 주문을 보내지 않고 봇이 내부에서 체결을 **시뮬레이션** |
| 시세 | 데모 서버 시세(메인넷과 다를 수 있음) | **메인넷 실시간 시세** |
| 체결·수수료·펀딩·청산 | 거래소가 계산 | **봇 코드가 계산**. 정확도가 코드 품질에 달려 있음 |
| 여러 매매법 동시 운영 | 한 계정에서 포지션이 섞임 | 매매법마다 **가상 서브계정**을 두고, 합산 포트폴리오도 따로 시뮬레이션 가능 |
| 확인 못 하는 것 | — | 실제 주문 API 동작(주문 거부, Algo 조건부 주문, 레이트리밋, 체결 지연) |

**paper 엔진이 반드시 정확해야 하는 것** (코드, 1단계 필수)
1. **체결가**
   - 시장가: 주문 순간 메인넷 호가(depth) 스냅샷에서 주문 수량만큼 소진한 가격 + 지연 가정
   - 지정가: 가격이 **관통**해야 체결
2. **수수료**: 계정 등급 요율(VIP0 기본 메이커 0.02%, 테이커 0.05%. 실계정 요율은 API로 확인해 반영)
3. **펀딩**: 실제 펀딩률, 정산 시각, 종목별 간격
4. **청산**
   - 바이낸스 **교차 마진 청산 공식**과 종목별 유지증거금 구간(leverageBracket)을 그대로 구현
   - 청산 수수료도 반영
5. **레버리지·증거금**: 실제와 같은 초기증거금과 가용잔고 계산
6. **검증 방법**: 공개된 바이낸스 청산가 계산 예시와 대조하는 테스트를 만듭니다. 계산기 결과와 비교할 사례를 사람이 몇 개 만들어 줘야 합니다.

**실거래 전 권장**: paper에서는 주문 API를 전혀 쓰지 않습니다. 그래서 실거래 직전에 최소 금액으로 **주문 경로 점검(1~2주)**을 권장합니다. 주문·취소·조건부 손절·재시작 복구를 확인하는 단계이고, 수익은 목적이 아닙니다.

## 2. 동적 레버리지·증거금 (ROE 기준, 최소 20배)

### 2-1. 먼저 알아야 할 팩트 3가지
**1. 손익 금액은 포지션 크기(명목가)와 가격 변동으로 정해집니다.**
- 레버리지는 "그 포지션에 증거금을 얼마 묶느냐"를 정합니다.
- ROE = 손익 ÷ 증거금이므로, **같은 포지션이라도 레버리지가 높으면 ROE %가 커 보입니다.**

**2. ROE 익절 목표는 레버리지에 따라 실제 가격 목표가 바뀝니다.**

| ROE 목표 | 20배 | 30배 | 50배 | 75배 |
|---|---|---|---|---|
| 10% | 가격 0.50% | 0.33% | 0.20% | 0.13% |
| 15% | 0.75% | 0.50% | 0.30% | 0.20% |
| 20% | 1.00% | 0.67% | 0.40% | 0.27% |
| **왕복 테이커 수수료(명목 0.1%)의 ROE 환산** | **2%** | **3%** | **5%** | **7.5%** |

그래서 레버리지를 자동으로 바꾸면 **같은 ROE 10% 익절이 차트마다 다른 가격 목표**가 됩니다.

**3. 교차 마진에서는 레버리지 설정값보다 계좌 전체의 실제 노출이 청산을 결정합니다.**
- 실제 노출 = 전체 명목가 ÷ 계좌 잔고입니다.
- 모든 포지션이 한 지갑을 공유하므로, 한 포지션의 큰 손실이 계좌 전체 청산으로 이어질 수 있습니다.
- 급락장에서는 5종목이 함께 움직입니다(참고 자료: "위기 시 상관 1 수렴").

### 2-2. 동적 엔진 규칙 (규칙은 미리 고정, 성과를 보고 튜닝하지 않음)
신호마다 코드가 다음 순서로 계산합니다.

1. **위험 금액**
   - 위험 금액 = 계좌 × 기본 위험% × 장세 계수 × 변동성 계수
   - 기본 위험%와 계수표는 **두 분이 정하고 고정**합니다. 예시(가설): 기본 1%, 추세 1.0 / 박스 0.5 / 혼조 0.25 / 고변동 0.5
2. **포지션 크기(명목가)**
   - 명목가 = 위험 금액 ÷ 손절까지 가격 거리(%)
   - 손절 거리는 매매법이 정합니다.
3. **레버리지 L**
   - 하한은 **20배**입니다.
   - 상한은 **안전 상한**과 **종목 상한** 중 작은 값입니다.
     - 안전 상한: 이 포지션이 **자기 증거금만으로도** 손절 + 3×ATR 너머까지 버티는 최대 레버리지. 식은 L ≤ 1 ÷ (손절거리% + 3×ATR% + 유지증거금률). 참고 자료의 "청산 버퍼 3×ATR" 원칙입니다.
     - 종목 상한: 해당 명목가 구간에서 바이낸스가 허용하는 최대 레버리지(leverageBracket)
   - 이 범위 안에서 **변동성이 낮고 손절이 가까울수록 높게**, 변동성이 높을수록 낮게 정합니다.
   - **안전 상한이 20배보다 낮으면 규칙이 충돌합니다.** 손절이 넓은 매매(주로 4시간봉·일봉)에서 흔합니다. 처리 방식은 두 분이 정해야 합니다(§2-4).
4. **증거금** = 명목가 ÷ L. 계좌에서 증거금 비중도 기록합니다.
5. **익절(ROE 기준)**
   - 매매법의 ROE 목표를 가격 목표로 환산합니다: 가격% = ROE% ÷ L
   - 가격 목표, R배수, 수수료 차감 후 순 ROE를 **함께 기록**합니다.
6. **계좌 단위 검사 (하나라도 걸리면 진입 거부)**
   - 계좌 실제 노출 상한
   - 동시 손절 시 총손실 상한(포트폴리오 히트)
   - 계좌 전체 청산가까지 거리 ≥ 가장 변동성 큰 종목 3×ATR
   - 증거금 사용률 상한

모든 계수와 한도는 **설정 파일에 고정**합니다. 바꿀 때는 버전을 올리고, 변경 전후 비교는 검증 절차를 거칩니다.

### 2-3. 이 엔진이 과최적화가 아닌 이유
- 계수를 백테스트 수익이 가장 좋게 나오도록 고르지 **않습니다.** 사람이 사전에 정한 규칙입니다.
- 계수표 자체가 효과가 있는지는 **가설**입니다. 두 방식을 paper에서 나란히 돌려 판정합니다.
  - 동적 엔진
  - 고정 위험(계수 1.0) 비교판(섀도)
- 판정 기준도 미리 정합니다: 최소 거래 수, 기간, 지표.

### 2-4. 두 분이 정해야 할 것
1. 기본 위험% (1회 손절 시 계좌의 몇 %)와 장세·변동성 계수표
2. **"최소 20배"와 안전 상한이 충돌할 때 처리 방식**
   - (a) 그 거래를 건너뛴다
   - (b) 그 거래만 20배 미만을 허용한다
   - (c) 20배를 유지하고 증거금만 작게 한다. 교차 마진이라 개별 청산은 계좌 잔고가 막아 주지만, 계좌 단위 한도가 대신 지켜야 합니다.
3. 계좌 실제 노출 상한, 포트폴리오 히트 상한, 증거금 사용률 상한
4. 매매법별 ROE 익절 목표 (백테스트 결과를 보고 결정. 청산 실험실에서 ROE 10·15·20%와 구조 익절을 같은 거래로 비교)

## 3. 자기진화·자율 실행 (포함)

### 3-1. 자동 전략 발굴 (유전 프로그래밍·심볼릭 회귀·강화학습·AutoML·LLM 가설, 무제한)
**발굴 방법 (모두 가동)**
| 방법 | 도구 | 담당 |
|---|---|---|
| 유전 프로그래밍 | DEAP, gplearn | 코드 작업 + 알고리즘 발굴 에이전트 |
| 심볼릭 회귀 | PySR | 〃 |
| 강화학습 | Stable-Baselines3, FinRL | 〃 |
| AutoML·하이퍼파라미터 탐색 | Optuna | 〃 |
| 진화 전략 | DEAP | 〃 |
| LLM 가설 생성 | Claude | **전략 연구원 (무제한)** |

**과최적화를 막는 자동 관문** (코드, 모두 통과해야 후보 등록. 발굴 방법과 관계없이 동일)

*데이터 분할*
1. 발굴용 / 검증용 / **잠금 구간**으로 나눕니다.
2. 잠금 구간은 발굴 코드가 접근하지 못하게 막습니다.
3. **가장 확실한 미관측 데이터는 paper 모드의 앞으로의 데이터**입니다. 다른 채팅의 백테스트가 이미 과거 전체를 봤기 때문입니다.

*통계 검정*

4. **모든 시도를 기록**합니다. 무제한이므로 시도 수가 수천~수만 개가 될 수 있고, 그 수만큼 기준을 높입니다.
   - Deflated Sharpe Ratio: 시도 수를 반영
   - PBO: CSCV 방식
   - 다중검정 보정: Benjamini-Hochberg FDR
5. **최소 거래 수**를 매매법×TF별로 사전에 정합니다.
6. **비용 반영 후** 양수여야 합니다: 수수료, 펀딩, 호가 기반 슬리피지, **20배 이상 레버리지에서의 청산 시뮬레이션**.

*강건성*

7. **5종목 중 3종목 이상**, 그리고 **연도별 과반**에서 유지되어야 합니다. 한 종목·한 해에서만 되는 패턴은 기각합니다.
8. **파라미터 고원**: 이웃 값에서도 성과가 비슷해야 합니다.
9. **Walk-forward + Purged CV**를 통과해야 합니다.
10. **기존 매매법과 상관 < 0.5**여야 합니다(참고 자료 기준).

*해석*

11. **경제적 근거 문서**가 있어야 합니다. 규칙이 왜 돈을 버는지 설명하지 못하면 보류합니다(참고 자료 규칙).

*마지막 관문*

12. **paper 섀도 운영**: 자금 배분 없이 기록만 합니다. 사전에 정한 최소 기간과 거래 수를 채우고, 백테스트 예측 분포 안에 있어야 활성화합니다.

**컴퓨팅**: 유전 프로그래밍·강화학습·AutoML은 CPU·메모리를 많이 씁니다. 봇이 도는 서버와 **분리된 연구용 서버**를 권장합니다(§5). 같은 서버에서 돌리면 봇 체결이 지연될 수 있습니다.

### 3-2. 자기개선 (L1~L4)
| 레벨 | 대상 | 자동 적용 조건 |
|---|---|---|
| L1 파라미터 | 임계값, 기간, 배수 | 1회 변경 폭 ±20% 이내 + 관문 통과 + 도전자 운영에서 우위 확인 |
| L2 피처 | 입력 지표 추가·제거 | 관문 통과 + 도전자 운영 |
| L3 구조 | 조건 순서, 로직 | 관문 통과 + 도전자 운영 + **자율 승인관 승인** |
| L4 전략 가중치·교체 | 매매법 켜기·끄기, 자본 배분 | CIO 에이전트 제안 + 자율 승인관 승인 + 코드 한도 이내 |

- **수정 트리거**: 성과 저하(Sharpe가 기준 대비 30% 이상 하락), 피처 분포 드리프트(KS-test), 장세 전환, 상관 붕괴, 월간 정기
- **자기수정 ≠ 자기승인** (참고 자료 절대 규칙)
  - 수정안을 만드는 쪽: 자기개선 에이전트, 알고리즘 발굴 에이전트
  - 승인하는 쪽: **자율 승인관**
  - 두 역할을 분리하고, 승인관도 코드 관문 결과를 뒤집을 수 없습니다.
- 모든 변경은 Git 버전, "왜 수정했나" 감사 로그, **자동 롤백** 규칙(적용 후 성과가 사전 기준 아래로 떨어지면 이전 버전 복원)을 남깁니다.

### 3-3. 자율 실행 L4
- **실행은 코드가 합니다.** L4는 "AI가 주문을 누른다"는 뜻이 아닙니다. **전략의 추가·수정·교체·가중치 변경까지 사람 승인 없이 자동 파이프라인으로 반영**된다는 뜻입니다.
- **AI가 바꿀 수 없는 절대 한도** (코드 상수, 사람만 변경)
  - 최대 레버리지 상한
  - 1회 최대 위험%
  - 일일·주간 최대 손실(도달 시 자동 정지)
  - 계좌 실제 노출 상한
  - 청산 버퍼
  - 킬스위치
- **참고 자료의 금지 사항을 그대로 둡니다**
  - 실계좌에서 코드를 직접 수정하지 않습니다. 반드시 테스트 → 버전 → 배포 파이프라인을 거칩니다.
  - 승인 없이 레버리지 한도를 바꾸지 않습니다. 동적 엔진은 사람이 정한 범위 안에서만 움직입니다.
  - 로그를 조작하지 않습니다.
  - 리스크 한도를 우회하지 않습니다.
  - 사람의 개입을 막지 않습니다. 텔레그램 킬스위치는 항상 동작합니다.
- **paper 모드에서는 처음부터 L4로 운영합니다.**
- **실거래 전환 시점의 레벨은 그때 스위치로 정합니다.** 참고 자료 원문은 "실전에서는 L1~L2에서 시작 → 성과·안정성 확인 후 단계적 상향"을 권고합니다. L4로 가더라도 새 전략과 수정 전략은 **자동 자본 사다리**를 거칩니다(작은 배분에서 시작해 기준 충족 시 증액).

## 4. 매매법 조합 시너지 분석 (신규)
목적은 두 가지입니다. 매매법을 합쳤을 때 **시너지가 나는지(합산 성과가 좋아지는지)**, 아니면 **손실이 커지는지(역시너지)**를 팩트로 판정합니다.

### 4-1. 두 가지 방식으로 동시에 돌립니다 (paper 모드라서 가능)
- **개별 운영**: 매매법마다 가상 서브계정을 둡니다.
- **합산 운영**: 한 교차 마진 계좌에서 모든 매매법을 동시에 돌립니다. 증거금 공유, 넷팅, 같은 종목 반대 포지션, 계좌 단위 청산을 모두 반영합니다.
- 백테스트 결과가 오면 과거 데이터로 먼저 계산하고, 이후 paper 데이터로 계속 갱신합니다.

### 4-2. 판정 지표 (코드 계산)
| 지표 | 의미 | 시너지 신호 | 역시너지 신호 |
|---|---|---|---|
| 일간 손익 상관 | 같이 벌고 같이 잃나 | 낮음(< 0.3) | 높음(> 0.6) |
| **꼬리 상관**(하위 5% 날의 상관) | 급락 날 같이 망하나 | 낮음 | 높음. 평소 상관보다 이게 더 중요 |
| 동시 손실일 비율 | 같은 날 둘 다 손실 | 낮음 | 높음 |
| 합산 Sharpe vs 개별 평균 | 위험 대비 수익 개선 | 합산 > 개별 | 합산 < 개별 |
| 합산 최대 낙폭 vs 개별 | 낙폭 축소 | 합산이 더 작음 | 합산이 더 큼 |
| 회복 기간 | 손실 회복 속도 | 짧아짐 | 길어짐 |
| 한계 기여도 | 그 매매법을 빼면 합산이 어떻게 변하나 | 빼면 나빠짐 | 빼면 좋아짐 |
| 충돌률 | 같은 종목 반대 신호 비율 | 낮음 | 높음(수수료만 내고 서로 상쇄) |
| 장세 보완성 | A는 추세장, B는 박스장에서 수익 | 서로 다른 장세에서 수익 | 같은 장세에서만 수익 |
| **계좌 청산 근접도**(교차 마진) | 합쳤을 때 계좌 청산가까지 거리 | 여유 유지 | 동시 손실 때 급감 |

### 4-3. 과최적화 방지 규칙
- 조합 수가 많아지면(예: 매매법 10개면 1,023개 조합) **우연히 좋아 보이는 조합**이 생깁니다.
- 가중치는 **동일 위험(고정 규칙)**으로 평가합니다. 가중치 최적화로 좋은 조합을 만들지 않습니다.
- 조합은 **앞 구간에서 고르고, 뒤 구간(미관측)에서 확인**합니다(walk-forward).
- 평가한 조합 수를 기록해 다중검정을 보정합니다.
- 결과는 **신뢰구간과 함께** 냅니다(블록 부트스트랩).

### 4-4. 결과물
- 쌍별 시너지 행렬(매매법 A×B 표): 합산 Sharpe 변화, 낙폭 변화, 꼬리 상관, 충돌률, 판정(시너지 / 중립 / 역시너지)
- 합산 포트폴리오 곡선 vs 개별 곡선
- 한계 기여도 순위(뺐을 때 나아지는 매매법 표시)
- 담당: 코드(조합 분석기) → **조합 시너지 분석가**(해석) → 전략 검증관(미관측 구간 확인) → CIO 에이전트(가중치 제안) → 자율 승인관

## 7. 과최적화 방지·팩트 원칙 (전 조직 공통)
1. 기준값, 판정 규칙, 최소 표본은 **결과를 보기 전에** 설정 파일에 기록합니다.
2. 모든 시도(발굴 후보, 파라미터, 조합, 청산 정책, 시간 필터)를 **세고**, 그 수만큼 통계 기준을 높입니다.
3. 최종 판정은 **미관측 데이터**(잠금 구간, 그리고 paper의 앞으로의 데이터)로만 합니다.
4. 모든 결과는 **거래 수와 신뢰구간**을 함께 적습니다. 표본이 부족하면 "판단 불가"라고 씁니다.
5. 에이전트 출력의 숫자는 입력 데이터에 근거 경로가 있어야 합니다(근거 검사기). 근거가 없으면 삭제합니다.
6. 가설과 팩트를 리포트에 구분해 표시합니다.
