# 게이트 봇 (10-31)

친구가 게이트(Gate) 선물 계정에서 직접 진입하면, 봇이 그 포지션에 손절을 걸고 계단식 익절로 손절을 올려 줍니다.
봇에는 매매법이 없습니다. 진입은 하지 않고, 걸려 있는 포지션을 지키기만 합니다.

- 프로그램: `paperbot/gateguard.py` (봇), `paperbot/gate.py` (게이트 연결)
- 설정: `deploy/gateguard.json` → 서버의 `/etc/paperbot/gateguard.json`
- 키: `/etc/paperbot/executor-gate.env` (루트만 읽음, 이 봇의 유닛만 읽음)
- 유닛: `paperbot-gateguard` (설치만 되고, 켜는 건 두 분이 직접)

## 1. 규칙 (두 분이 정한 것)

| 항목 | 규칙 |
|---|---|
| 손절 | 평단 ∓ (게이트 **15분봉** ATR(14) × **3**) |
| 손절이 청산가 너머일 때 | 청산가 안쪽으로 당김 (평단~청산가 거리의 15%를 청산가 앞에 남김) + 알림 |
| 계단식 익절 | 순ROE **10%** 닿으면 손절을 **+8%** 자리로. 그 뒤 2%마다 2%씩 (12%→10%, 14%→12%, 16%→14% …) |
| 순ROE | 포지션 레버리지 기준 마진 수익률, 진입·종료 수수료(계정의 시장가 수수료) 양쪽을 뺀 값 |
| 최고가 | 게이트 1분봉(체결가)의 고가·저가로 봄. 두 번 확인 사이에 튄 가격도 놓치지 않음 |
| 손절 이동 | 조이기만 하고 풀지 않음. 새 손절을 먼저 걸고, 걸린 뒤에 옛 손절을 지움 (손절 없는 순간 없음) |
| 추가 진입 | 수량이 늘고 평단이 바뀌면 **새 평단 기준으로 처음부터**: 새 ATR 손절, 계단도 0부터, 최고가도 그때부터 |
| 일부 종료 | 손절은 그대로 (봇 손절은 남은 수량 전부를 닫음) |
| 친구의 주문 | 봇은 자기가 건 주문만 건드림. 친구가 직접 건 익절·손절이 먼저 닿으면 그게 먼저 |
| 친구가 직접 닫음 | 봇 손절을 지우고 결과(손익)를 알림 |
| 친구가 봇 손절을 지움 | 그 포지션은 봇이 손을 뗌 (알림 1번). 새로 진입하거나 추가 진입하면 다시 지킴 |
| 코인 | 코인마다 따로. 설정의 `coins`가 `null`이면 계정의 모든 포지션 |

### 가격이 손절 자리를 이미 지나 있을 때

게이트는 현재가를 이미 지난 자리에는 손절을 받지 않습니다.

- **계단 잠금 자리를 이미 지났을 때** (예: 10%를 찍고 확인 사이에 8% 아래로 떨어짐): 봇이 **시장가로 닫습니다**. 손절이 있었다면 걸렸을 자리이기 때문입니다.
- **봇이 늦게 본 포지션** (봇이 꺼져 있을 때 진입, 진입 5분 뒤에 처음 봄): 첫 손절 자리를 이미 지났으면 **봇은 닫지 않고 손을 뗍니다**. 알림이 오면 직접 정리해 주세요. 그런 포지션은 최고가도 봇이 본 때부터 셉니다. 봇이 켜지기 전의 최고가로 갑자기 닫는 일은 없습니다.

### 봇이 꺼져 있을 때

봇 손절은 게이트의 **조건부 주문**으로 걸려 있습니다. 봇이 꺼져도 게이트에 남아서 계속 지킵니다. 봇이 꺼져 있는 동안 멈추는 것은 계단 올리기뿐입니다.

## 2. 친구에게 알려 줄 것

1. 게이트 선물은 **단방향(원웨이) 모드**여야 합니다. 양방향 모드면 봇이 시작하지 않습니다.
2. 진입은 평소처럼 앱이나 웹에서 직접 합니다.
3. 봇 손절은 앱의 **조건부 주문(Trigger order)** 목록에 보입니다. 포지션 전부를 시장가로 닫는 주문입니다.
4. 봇 손절을 직접 지우면, 봇은 그 포지션을 더 건드리지 않습니다.
5. 친구가 직접 건 익절·손절(포지션 TP/SL)은 봇이 건드리지 않습니다.

## 3. 키 만들기 (친구 계정에서, 두 분이 확인)

게이트 → API 관리 → APIv4 키 만들기:

- 권한: **무기한 선물(Perpetual Futures) 읽기·쓰기만**. 현물·마진·지갑·**출금은 끔**
- **IP 묶기**: `158.247.200.152` (서버 IP)
- 키와 시크릿은 처음 한 번만 보입니다. 채팅에 붙이지 말고 서버에서만 넣습니다.

## 4. 서버 순서 (두 분이 직접, 한 단계씩 결과를 보고)

### A. 코드 받기와 읽기만 하는 점검 (주문 없음)

1. 코드 받기
   ```
   cd /root/crypto-bot-research && git pull && sudo bash deploy/install.sh
   ```
   - 게이트 봇은 설치만 되고 켜지지 않습니다.
   - 키 파일 틀 `/etc/paperbot/executor-gate.env`이 루트 전용으로 만들어집니다.
2. 설정 파일 복사 (이미 있으면 그대로 둠)
   ```
   sudo test -e /etc/paperbot/gateguard.json || sudo install -o root -g paperbot -m 640 /opt/crypto-bot-research/deploy/gateguard.json /etc/paperbot/gateguard.json
   ```
3. 키 넣기 (서버에서만)
   ```
   sudoedit /etc/paperbot/executor-gate.env
   ```
   - `GATE_LIVE_KEY=` 뒤에 키, `GATE_LIVE_SECRET=` 뒤에 시크릿을 넣습니다.
   - 키 화면에서 "선물만 · 출금 없음 · IP 묶음"을 확인했으면 `GATE_LIVE_KEY_CHECKED=FUTURES_ONLY_NO_WITHDRAW_IP_BOUND`
   - `PAPERBOT_LIVE_MAINNET=I_UNDERSTAND`
   - 다른 거래소 키는 넣지 않습니다. 있으면 봇이 시작하지 않습니다.
4. 점검 (읽기만)
   ```
   sudo /opt/crypto-bot-research/deploy/paperbot-exec.sh --keys gate gateguard check --config /etc/paperbot/gateguard.json
   ```
   다음이 나옵니다:
   - 키 확인, 서버 시각 차이, 한 방향 모드, IP 묶음
   - 선물 잔고
   - 규칙 한 줄
   - 열린 포지션마다 "새로 걸 손절"
   - 봇이 건 것이 아닌 조건부 주문 (친구 것, 손대지 않음)
   - 마지막 줄 "주문은 하나도 내지 않았습니다(읽기만)."

### B. 켜기와 첫 확인 (A가 문제없을 때)

1. 친구가 **가장 작은 수량**으로 포지션 하나를 엽니다.
2. A-4의 점검을 다시 돌려 "새로 걸 손절" 값을 봅니다.
3. 켜기
   ```
   sudo systemctl start paperbot-gateguard
   sudo journalctl -u paperbot-gateguard -n 20 --no-pager
   ```
   - 텔레그램에 `[게이트 봇] 시작: …`이 오고, 이어서 `[게이트 봇] BTC 롱 진입 확인: … 손절 …`이 옵니다.
4. 친구가 앱의 **조건부 주문** 목록에서 봇 손절이 보이는지 확인합니다. 가격이 3번의 알림과 같아야 합니다.
5. 친구가 그 작은 포지션을 직접 닫습니다.
   - `[게이트 봇] … 종료: 직접 종료` 알림과 손익이 와야 합니다.
   - 조건부 주문 목록에서 봇 손절이 사라져야 합니다.
6. 며칠 문제없으면 재부팅 뒤에도 켜지게 합니다.
   ```
   sudo systemctl enable paperbot-gateguard
   ```

### 끄기

```
sudo systemctl stop paperbot-gateguard
```

걸려 있던 봇 손절은 게이트에 남습니다. 계단만 멈춥니다. 봇 손절도 없애려면 친구가 앱에서 직접 지웁니다.

## 5. 텔레그램 알림

| 알림 | 뜻 |
|---|---|
| `시작: 손절 15분봉 ATR(14) × 3 · 계단 익절 순ROE 10%에서 8% 잠금, 이후 2%씩 …` | 봇이 켜짐 |
| `BTC 롱 진입 확인: 평단 …, 수량 …, 20배` / `손절 … (15분봉 ATR … × 3, 가격 -x% · 순ROE -y%)` | 새 포지션에 손절을 걸었음 |
| `… 청산가 … 너머라 청산가 안쪽으로 당김` | 손절이 청산가보다 멀어서 당겼음 |
| `BTC 잠금 순ROE +8%: 최고 … (순ROE +10.4%) → 손절 … → …` | 계단 한 칸 올라감 |
| `가격 …이 이미 잠금 +8% 자리 …를 지나 있어 시장가로 닫았습니다` | 확인 사이에 잠금 자리 아래로 떨어져 시장가로 닫았음 |
| `추가 진입 확인: 평단 … → …` | 새 평단 기준으로 다시 걸었음 |
| `봇 손절 주문(…)이 직접 취소됐습니다. 이 포지션은 더 건드리지 않습니다` | 친구가 봇 손절을 지웠음 |
| `BTC 롱 종료: 봇 손절(…)` / `봇 잠금 익절(…)` / `직접 종료` + `손익 … USDT (수수료 … 포함)` | 포지션이 끝났음 (손익은 게이트 기록) |
| `게이트를 3번 연속 못 읽었습니다(걸린 손절은 게이트에 그대로 있음)` | 연결 문제. 손절은 게이트에 걸려 있음 |

## 6. 첫 실제 포지션에서 확인할 것

이 봇의 게이트 연결은 게이트 공식 SDK(gate-api 7.2.172)의 API 설명을 보고 만들었습니다. 이 작업 환경에서는 게이트 웹 문서가 막혀 있었습니다. 실제 계정에서 아직 돌려 보지 않은 것은 다음과 같습니다. B의 작은 포지션으로 확인합니다.

1. 게이트가 봇 손절 주문을 받는지 (거절되면 `CRITICAL … 거절했습니다` 알림과 이유가 옵니다)
2. 앱의 조건부 주문 목록에 보이는지, 포지션 전부를 닫는 주문으로 보이는지
3. 계단이 올라갈 때 잠깐 두 손절이 같이 걸리는 것이 되는지 (새 것 먼저, 그다음 옛 것 취소)
4. API로 만든 주문에 게이트가 `api` 표시를 하는지
   - 봇은 이 표시로, 포지션이 없는 코인에 남은 자기 손절을 찾아 지웁니다.
   - 표시가 다르면 그 정리만 안 될 뿐, 다른 동작은 같습니다.
