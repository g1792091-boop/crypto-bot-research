## 1. 에이전트 조직: 빠진 것은 에이전트보다 "에이전트가 없는 시간"

Claude Code 서브에이전트는 **호출될 때만 실행되고 상시로 떠 있지 않습니다** (code.claude.com/docs/en/sub-agents). 그래서 에이전트를 20명, 30명으로 늘려도 막을 수 없는 구간이 있습니다.
- 새벽
- 봇이 죽었을 때
- 재시작할 때
- 데이터가 조용히 끊겼을 때

이 구간은 봇 **코드**로 막고, 두 사람 사이의 규칙은 **사람의 결정**으로 정해야 합니다.

### 새로 넣을 LLM 에이전트: 1명
- **전략 연구원** (매매 계획팀, 필요할 때만 호출)
  - 다른 채팅에서 나온 매매법을 명세 카드(`docs/strategies/<이름>.md`)로 옮깁니다. 명세에는 가설, 확정봉 기준 신호, 진입·청산·사이징, 파라미터 범위, 기대 장세, 반증 조건, 은퇴 기준을 적습니다.
  - 명세는 백테스트 전에 커밋합니다(사전 등록).
  - 검증은 전략 검증관이 따로 합니다. 독립성을 지키기 위해서입니다.

### 기존 역할 확장
| 역할 | 추가 업무 |
|---|---|
| 뉴스·일정 분석가 | 바이낸스 공지(점검·상장폐지·규칙 변경·API 이전) 매일 확인, 월 1회 규제·세금 점검 |
| 백테스트 검증관 → **전략 검증관** | 선견 편향, 비용, 과최적화(DSR·PBO·워크포워드), 파라미터 강건성, 시장 충격 시나리오를 체크하는 새 매매법 도입 관문 |
| 테스트 작성자 | 거래소 장애(WS 끊김, -1007 타임아웃, -1021, 429/418, 부분·중복 체결), 크래시 후 재시작, 허용범위 파일 오류, 선견 편향 테스트 |
| 성과 분석가 | "AI 필터 없음" 섀도 장부 대비 AI 계획 레이어의 기여도 측정. 8주 전에는 결론을 내지 않음 |
| 코드 리뷰어 | 주 1회 바이낸스 API 변경 로그 확인, 보안 체크리스트 |

### 선택: 20명 → 13명으로 줄이는 안 (종합 에이전트 권고)
겹치는 역할을 합치자는 제안입니다.
- 기술 분석가 → 장세 판별관
- 파생상품 분석가 + 시장구조 분석가 → 시장 데이터 분석가
- 강세·약세 논객 → 반론 검토관 1명 (8주 측정 후 존폐 결정)
- 포지션 설계자 → 전략가
- 리스크 감시관 → 코드 서킷브레이커로 대체
- 스트레스 테스터 → 테스트 작성자와 전략 검증관이 나눠 맡음
- 장부 감사관 + 에러 분석가 → 운영 감사관
- 보안 점검관 → 코드 리뷰어 체크리스트

**20명을 유지해도 됩니다.** 다만 겹치는 역할은 같은 말을 반복하고 Claude 사용량만 늘어납니다.

### ⑦ 자동 안전장치 (봇 코드, 테스트넷 가동 전 필수)
1. **가동 감시**
   - 자동 재시작(systemd `Restart=always` 또는 Docker 재시작 정책)
   - 1분마다 외부 데드맨 서비스(healthchecks.io 등)에 핑
   - **진입 직후 거래소 쪽 보호 손절 주문 등록** (봇이 죽어도 포지션이 방치되지 않게)
2. **데이터 품질 감시**
   - 스트림별 마지막 수신 시각 추적, 23시간 선제 재연결, listenKey keepalive, 누락 캔들을 REST로 보충, 시계 오차 점검
   - 신호는 메인넷 공개 데이터로 계산하고, 주문만 테스트넷으로 보냄
3. **재시작 복구와 주문 멱등성**
   - 결정적 `newClientOrderId`(예: `bot_` 접두어) 사용
   - `-1007` 타임아웃이 나면 재시도하기 전에 먼저 조회
   - 시작할 때마다 거래소 포지션·주문을 가상 장부와 대조하고, 불일치면 신규 진입 차단
   - SQLite(WAL) 장부
4. **허용범위 파일 관문**
   - pydantic으로 스키마 검증, 절대 한도로 값을 잘라냄(clamp)
   - `valid_until`이 지나거나 파일이 무효면 신규 진입 금지 모드
   - LLM이 한도를 넓힐 수 있는 경로는 코드에 없음
5. **킬 스위치**
   - 텔레그램 `/status`, `/halt`, `/flatten`(2단계 확인). 허용된 chat_id 2개에서만 받음
   - 연속 에러, 429/418, 장부 불일치, 데이터 지연이 생기면 자동 정지
   - 심각 알림에 N분 동안 아무도 응답하지 않으면 신규 진입 자동 중지
6. **포트폴리오 하드캡과 내부 넷팅**
   - 원웨이 모드는 한 종목에 포지션이 하나뿐입니다. 그래서 여러 봇의 서브포지션을 종목별 순포지션으로 합쳐 주문하고, 손익은 봇별로 나눠 기록합니다.
   - 전략 자동 정지 기준(예: 최대낙폭이 백테스트의 1.5배 초과)은 도입할 때 미리 적어 둡니다.
7. **기록 체계**
   - JSON 한 줄 로그 + 상관 ID
   - 모든 주문·장부 행에 커밋·설정·허용범위 해시 기록
   - 백테스트 시행 기록부, 결정 기록부, 섀도 장부
8. **AI 파이프라인 실행기**
   - 아침·저녁 `claude -p`를 타이머로 실행: `--output-format json`, `--json-schema`, 필요한 도구만 허용
   - 실패하면 1회 재시도 후 텔레그램 경보, 봇은 안전 모드로 전환
   - `--bare`는 쓰지 않음(API 과금)
9. **거래소 규격 변경 감지**: `exchangeInfo`, `leverageBracket`, `fundingInfo`(펀딩 주기)를 매일 비교합니다. 펀딩 주기를 8시간으로 하드코딩하면 안 됩니다.

### ⑧ 사람 2명이 정할 것
- **실행 호스트:** 상시 켜 둔 PC나 VPS. 미국 등 제한 지역 IP는 바이낸스가 HTTP 451로 막습니다.
- **Claude 계정 운용:** 파이프라인을 돌릴 계정 주인 1명을 정합니다. 개인 요금제 로그인을 공유하는 것은 피합니다.
- **계좌 구조 합의:** 권장안은 각자 본인 명의 계정과 키로 따로 돌리는 것입니다. 명의를 합치면 과세·신고 문제가 생길 수 있어 세무사 확인이 필요합니다. [미확인]
- **협업 규칙:** main 직접 push 금지, PR과 상대방 승인. 한도 파일과 실거래 스위치는 두 사람 모두 확인합니다.
- **비상 대응 당번표, 킬 스위치 리허설**
- **Go-live 기준 숫자:** 테스트넷 성적을 보기 **전에** 정합니다(최소 기간, 거래 수, 장부 오차 허용치, 초기 규모).
- **세금 참고** [미확인 포함, 판단은 세무사에게]:
  - 현행법상 2027-01-01부터 가상자산 과세, 연 250만원 초과분 22%
  - 2030년 유예 개정안이 발의됐지만 통과 여부는 미확인
  - 무기한 선물 손익의 과세 대상 여부는 불명확

## 2. 트레이딩뷰에서 실시간 타점 보기

### 결론
**tradingview.com의 내 차트에 우리 봇의 실제 체결을 실시간으로 넣는 공식 방법은 없습니다.**
- TradingView에는 외부 프로그램이 사용자 차트에 마커를 그리는 공개 API가 없습니다(데이터 API 없음, REST API는 브로커 제휴용). [미확인]
- Pine Script에는 HTTP 요청 기능이 없습니다.
- Pine Seeds는 일봉 전용이고, 2024-01-26부터 신규 저장소 생성이 중단됐습니다(GitHub 문서 확인).
- TradingView 웹훅은 TradingView에서 밖으로 나가는 방향만 됩니다.

### 방법
| 방법 | 보이는 것 | 실제 봇 체결? | 평가 |
|---|---|---|---|
| **A. Lightweight Charts로 봇 전용 실시간 차트** | 우리 웹페이지(PC·휴대폰)에서 5종목 캔들 + 봇 진입·청산 마커 + 진입가·손절·익절 선. 테스트넷 체결과 가상장부 체결을 색으로 구분 | **예** | **추천.** TradingView가 만든 오픈소스(Apache-2.0, v5.2.1). 로고 표시만 지키면 무료. `createSeriesMarkers`, `series.update`로 실시간 갱신. 외부 접속 시 인증 필요 |
| B. 같은 매매법을 Pine Script로 재현 | tradingview.com 차트에 "같은 규칙이라면 났을 신호" | 아니오 | 참고용. 데이터·봉 마감·리스크 게이트 차이로 어긋남. 매매법마다 이중 관리. 웹훅은 유료 플랜과 2FA 필요 [미확인] |
| C. TradingView–바이낸스 브로커 연동 | 실계좌 USDⓈ-M 포지션 동기화 | 실계좌만 | 테스트넷 지원 근거 없음. 실거래 전환 후에나 의미 있음 [미확인] |
| D. 바이낸스 자체 웹 화면 | 바이낸스 화면의 포지션·주문 | 테스트넷 주문만 | 바이낸스가 2025-08-27 공지로 선물 테스트넷 **웹사이트** 접근을 단계적으로 막고 API 전용과 Demo Trading으로 옮김 [미확인] |

## 3. Astral(heyastral.ai)에서 봇 타점 보기

사용자가 말한 "astral trading"은 heyastral.ai로 보입니다(운영사 법인명 Astral Trading, Inc. [미확인]). 이름이 비슷한 다른 사이트(astralfxtrades.com 등)와 혼동하지 마세요.

### 이 세션에서 직접 확인한 사실 (MCP 조회)
- 계정은 paid 등급이고, 연결된 브로커와 배포된 전략은 0개입니다.
- 5종목 모두 지원하지만 **현물 USD 시세**(`X:BTCUSD` 등)이고, 바이낸스 USDT 무기한 선물이 아닙니다.
- 전략 빌더는 **롱 전용(Long-only)**입니다.
- 차트 도구(`astral_chart_build`)의 매매 오버레이는 **Astral 백테스트 체결(`backtest_trades`)만** 지원합니다. 외부 체결을 넣는 항목은 없습니다.
- 알림 채널은 email, sms, app_push, toast뿐입니다(텔레그램·웹훅 없음).
- 실시간 배포(signals_only / astral_paper / user_approved / full_broker)는 Astral 안에서 만든 전략만 대상입니다.

### 웹 조사 [미확인]
- 지원 브로커 목록(Coinbase, Kraken, Alpaca, Tastytrade 등)에 **바이낸스가 없습니다.**
- 외부 거래를 import하는 기능, 인바운드 웹훅, 공개 API는 확인되지 않았습니다.

### 결론
**우리 Python 봇이 테스트넷에서 잡는 실제 타점을 Astral에서 실시간으로 보는 경로는 없습니다(확인된 범위 기준).**

활용할 수 있는 방법:
1. **교차 백테스트:** 매매법의 **롱 쪽 로직**을 Astral 백테스트로 따로 돌려 봇 백테스트와 방향성·거래 시점을 대조합니다(전략 검증관 업무). 데이터 소스가 달라 수치가 똑같지는 않습니다.
2. **참고 신호** (선택): 롱 신호만 signals_only로 배포해 앱 푸시·SMS로 받습니다. 반드시 "Astral 복제 신호, 봇 체결 아님"이라고 표시합니다.
3. **현물 차트 뷰어**

안전 규칙:
- Astral 도구를 쓰는 에이전트에게는 **조회·백테스트 도구만** 허용합니다.
- `astral_order_submit`, full_broker·user_approved 배포, 브로커 연결 도구는 막습니다("AI는 주문하지 않는다" 원칙).

Astral 지원팀에 물어볼 것:
- 외부 거래 import나 웹훅 지원 여부
- 숏·선물 지원 계획
- `custom` 자산 타입이 무엇인지
