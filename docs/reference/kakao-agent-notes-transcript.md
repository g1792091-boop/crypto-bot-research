# 문서 1. 헤지펀드 AI 에이전트 + 차트 유사도 트레이딩 시스템 통합 정리

## PART 1. 헤지펀드의 AI 활용 & 에이전트 팀

### 1-1. 헤지펀드 AI 활용 3가지 패턴
| 패턴 | 대표 펀드 | AI 역할 |
|---|---|---|
| 에이전트 기반 연구 자동화 | Man Group, Bridgewater | 아이디어 생성 → 코드 작성 → 백테스트 자율 수행 |
| 기본적 투자 연구 강화 | Citadel, Point72 | 공시·리서치 요약, 애널리스트 판단 보조 |
| 플랫폼형 인프라 | Balyasny, Millennium | 전사 AI 인프라 구축 → 투자팀에 배포 |

### 1-2. 주요 활용 영역
- 리서치/데이터: 공시·실적·규제 서류 스캔, 경영진 키워드 추적
- 시그널 생성: Man Group AlphaGPT — 데이터 → 전략 코드 → 백테스트
- 포트폴리오 배분: Bridgewater AIA — ML 기반 매크로, 인간과 낮은 상관 알파
- 리스크/실행: 최적화, 스트레스 테스트, VaR, TWAP·VWAP·아이스버그

### 1-3. AI 에이전트 팀 구성 3유형
| 유형 | 구조 / 예시 | 핵심 |
|---|---|---|
| ① 계층적 스웜 | CIO → 시니어 PM → 데스크 PM → 스웜 피더 → 데이터 | 하위 출력 종합 → 상위 의사결정. 실제 조직도 모방 |
| ② 역할별 전문화 | Bracket22: Houston(총괄), Desmond(퀀트), Steffi(기술적), Doocy(레드팀) | 에이전트 격리 → 독립 판단 → 취합 → 인간 최종 결정 |
| ③ 대규모 스웜 | Magnetar(수백), Abundance(수천 봇) | 추론 레이어 중앙 통제. 리서치→선정→사이징→실행 |

Bracket22 사례: 연간 인건비 500만 달러 → 4만 달러로 대체

### 1-4. 설계 핵심 고려사항
- 에이전트 간 통신: 경쟁적 vs 협력적, 시장 변동성에 맞춰 선택
- 인간 판단 경계: Citadel — AI는 연구 가속 도구 / Magnetar — 최종 매매는 인간
- 비용 구조 혁신: 소규모 펀드도 인건비 대폭 절감 가능
- 전망: 중앙 AI 인프라 + 투자팀 맞춤 배포의 하이브리드 모델

## PART 2. 차트 유사도 기반 트레이딩 시스템

### 2-1. 전체 아키텍처
```
[Data Layer]
   ↓
[Feature/Embedding Layer]  ← 가격·거래량·변동성·오더플로·뉴스·매크로
   ↓
[Similarity Engine]        ← 과거 유사 차트 검색
   ↓
[Scenario Engine]          ← 분봉별 시나리오·확률 분포
   ↓
[Decision Layer]           ← 진입/청산/관망, 방향·확신도
   ↓
[Risk & Sizing Layer]      ← 시드 배분, 레버리지, 손절, CVaR
   ↓
[Execution Layer]          ← TWAP/VWAP, 슬리피지, 주문 분할
   ↓
[Monitoring & Learning]    ← 드리프트, 성과, 재학습
```

### 2-2. 유사도 엔진 설계
| 항목 | 내용 |
|---|---|
| 정규화 | 수익률, z-score, 변동성 스케일링, 분봉 정렬 |
| 특징 | 가격, 거래량, ATR, 스프레드, 오더북 불균형, regime |
| 알고리즘 | DTW, Matrix Profile, Shapelet, Siamese CNN, Transformer |
| 검색 | k-NN + regime 필터 + 유동성 필터 |
| 검증 | forward return 분포, t-test, 샘플 수, OOS |
| 주의 | 시각적 유사 ≠ 통계적 유사. 샘플 부족 시 "거래 없음" |

유사 차트 발견 시 → 이후 1·5·15·30·60분 수익률 분포 추출 (단일 경로 X, 분포 O)

### 2-3. 분봉별 시나리오 엔진
- Analog Forward Path: 과거 유사 사례 이후 경로 정렬
- 확률 분포: p10 / p25 / p50 / p75 / p90
- 시나리오: 강세·약세·중립 + 확률
- 트리거: 가격 돌파, 거래량 급증, 오더북 변화, 시간대
- 무효화: 손절 레벨, 시나리오 폐기 조건
- 분봉 플레이북: 09:30~09:35, 09:35~09:40 … 구간별 행동 지침

출력 예시:
```
[현재] 유사도 87%, 샘플 42건
[1분] 상승 55% / 하락 30% / 횡보 15%
[5분] p50 +0.12%, p10 -0.35%, p90 +0.48%
[트리거] 09:35 고점 돌파 + 거래량 1.5배 → 강세
[무효화] 09:33 저점 이탈 시 손절
```

### 2-4. 시드 비중·레버리지 엔진
기본 공식:
- 리스크 자본 = Equity × Risk% (0.25~1%)
- 손절 거리 = ATR × k 또는 무효화 레벨
- 포지션 크기 = 리스크 자본 ÷ |진입가 − 손절가|
- 레버리지 = 포지션 명목가 ÷ Equity

필수 통제:
| 통제 | 설명 |
|---|---|
| Fractional Kelly | Full Kelly 위험. 1/4 Kelly 권장 |
| Vol Targeting | 목표 변동성 ÷ 실현 변동성 |
| CVaR 한도 | 95% CVaR 기준 최대 손실 제한 |
| Portfolio Heat | 전체 포지션 합산 리스크 한도 |
| 청산 버퍼 | 청산가 3×ATR 이상 |
| 상관관계 | 동시 포지션 리스크 합산 |
| 유동성 | 호가 깊이·스프레드로 레버리지 캡 |

레버리지는 확신도·변동성·유동성·regime에 따라 동적 조절. 고정 레버리지 금지.

# 문서 2. 순환매매법 + 매매법별 에이전트 확장

## PART 1. 순환매매

### 1-1. 순환매매법이란
자금이 섹터·종목·자산군 사이를 **돌아가며** 움직이는 패턴을 포착해, **상대강도가 높은 곳으로 갈아타는** 전략입니다.

### 1-2. 순환매매 에이전트 구성
| 모듈 | 역할 |
|---|---|
| 자금 흐름 감지 | 섹터별 거래대금, 외인/기관 순매수, ETF 자금 유입 |
| 상대강도(RS) 랭킹 | RS = 종목수익률 ÷ 벤치마크수익률 (20·60·120일) |
| 로테이션 신호 | RS 상위 N개 편입, 하위 이탈 / 모멘텀 크로스 |
| 사이클 인식 | 경기·금리·유동성 사이클별 유리 섹터 매핑 |
| 전환 타이밍 | RS 역전, 거래량 다이버전스, 리더십 교체 |
| 리밸런싱 | 주간/월간, 또는 신호 발생 시 |
| 무효화 | 리더십 재역전, 자금 이탈 확인 |

### 1-3. 순환매매 에이전트 의사결정 흐름
```
[자금흐름 스캔]
   ↓
[섹터/종목 RS 랭킹]
   ↓
[사이클 국면 판단] ← Regime Agent 연동
   ↓
[편입/이탈 후보 생성]
   ↓
[Red Team 검증] ← "이 로테이션 진짜야?"
   ↓
[Risk Agent 승인]
   ↓
[Execution Agent 분할 매수/매도]
```

| 강한 추세 | 추세추종, 모멘텀, 돌파 | 평균회귀, 그리드 |
| 횡보 | 평균회귀, 그리드, 페어 | 추세추종, 돌파 |
| 고변동 | 변동성 매매, 옵션 | 스캘핑, 그리드 |
| 저변동 | 스캘핑, 차익거래 | 변동성 매매 |
| 위기 | 현금, 헤지, 롱숏 | 대부분 |

> **Regime Agent**가 국면을 판단 → **CIO Agent**가 전략 가중치 조정

## PART 8. 핵심 주의사항
- **전략 간 상관관계**: 순환매매와 모멘텀은 겹칠 수 있음 → 상관 낮은 전략 조합
- **과최적화**: 각 전략 OOS 검증 필수
- **Regime 오판**: 국면 전환기엔 전략 스위칭 지연 → 손실
- **거래비용**: 순환매매는 회전율 높음 → 비용 반영 필수
- **용량(Capacity)**: 소형주 로테이션은 자금 커지면 슬리피지 급증
- **Human-in-the-Loop**: 전략 가중치·레버리지는 인간 승인

### 최종 한 줄 정리
매매법별 에이전트를 **공통 인터페이스(JSON)** 로 표준화하고, **Regime Agent가 국면을 판단 → CIO Agent가 전략 가중치 배분 → Arbitration Agent가 충돌 조정 → Risk Agent가 사이징**하는 구조로 만들면, 순환매매든 추세추종이든 새 전략을 **플러그인처럼 추가**할 수 있다. 핵심은 **전략 간 상관을 낮추고, Regime별로 유리한 전략에 자본을 몰아주는 것**이다.

# 문서 3. 자기진화형 에이전트 3종 추가

## PART 1. 추가할 에이전트 3종 개요
| 에이전트 | 역할 | 핵심 기술 |
|---|---|---|
| ① Strategy Discovery Agent | 스스로 매매법·진입조건 발굴 | 유전 프로그래밍, 심볼릭 회귀, RL |
| ② Self-Improvement Agent | 성과 보고 스스로 수정·개선 | 메타러닝, 진화 알고리즘, AutoML |
| ③ Autonomous Execution Agent | 승인 없이 실행·자동 복구 | RL 실행, 이상 감지, 자가 치유 |

⚠️ **핵심 원칙:** 자기수정·자율실행은 반드시 **샌드박스 + 킬스위치 + 인간 승인 게이트** 안에서만 작동해야 합니다.

## PART 2. ① Strategy Discovery Agent (전략 발굴)

### 2-1. 무엇을 하는가
인간이 정의하지 않은 **새로운 매매법·진입·청산 조건**을 데이터에서 스스로 찾아냅니다.

### 2-2. 발굴 방법론
| 방법 | 설명 | 장점 | 단점 |
|---|---|---|---|
| 유전 프로그래밍(GP) | 수식 트리를 진화시켜 알파 생성 | 해석 가능 | 과최적화 위험 |
| 심볼릭 회귀 | 수학식으로 전략 표현 | 간결·설명력 | 탐색공간 제한 |
| 강화학습(RL) | 보상 최대화 정책 학습 | 적응력 | 블랙박스·불안정 |
| AutoML | 피처·모델·하이퍼 자동 탐색 | 편의성 | 과적합 |
| LLM 기반 생성 | 자연어로 가설 생성 → 코드화 | 창의성 | 검증 필수 |
| 진화 전략(ES) | 파라미터 집단 진화 | 병렬화 용이 | 국소최적 |
| 몬테카를로 트리 탐색 | 전략 공간 탐색 | 체계적 | 느림 |

### 2-3. 전략 발굴 파이프라인
```
[원시 데이터]
   ↓
[피처 자동 생성] ← 시계열 변환, 상호작용, 비선형
   ↓
[가설 생성] ← GP / LLM / 심볼릭
   ↓
[1차 필터] ← 통계적 유의성, 표본 수
   ↓
[백테스트] ← Walk-forward, Purged CV
   ↓
[과최적화 검정] ← Deflated Sharpe, PBO
   ↓
[상관 필터] ← 기존 전략과 상관 < 0.5
   ↓
[페이퍼 트레이딩] ← 최소 3개월
   ↓
[후보 등록] ← Human PM 승인
```

### 2-4. 발굴 시 필수 가드레일
- 탐색공간 제한: 무한 자유도 → 반드시 제약 (파라미터 수, 연산 종류)
- 과최적화 방지: Deflated Sharpe Ratio, PBO(Probability of Backtest Overfitting)
- 다중검정 보정: Bonferroni, FDR
- 경제적 타당성: 논리 없는 순수 통계 패턴은 기각
- 거래비용 반영: 회전율 높은 전략은 비용 후 재검증
- Look-ahead 차단: 미래 데이터 혼입 검사

### 2-5. LLM 기반 가설 생성 예시
```
프롬프트: "다음 시장 미시구조 데이터에서 알파 후보 5개를
수식으로 제안하라. 각각 경제적 근거를 포함하라."

출력:
1. order_imbalance_5s × volume_zscore → 단기 모멘텀
2. spread_widening ÷ trade_intensity → 유동성 스트레스
3. vwap_deviation × atr_ratio → 평균회귀
...
```
→ 생성된 가설은 반드시 **백테스트 + 통계검정** 통과해야 편입

## PART 3. ② Self-Improvement Agent (자기 수정)

### 3-1. 무엇을 하는가
성과 지표를 모니터링하고, 스스로 **파라미터·피처·전략을 수정**합니다.

### 3-2. 수정 대상
| 레벨 | 수정 대상 | 예시 |
|---|---|---|
| L1 파라미터 | 임계값, 기간, 배수 | RSI 30→25 |
| L2 피처 | 입력 변수 추가/제거 | 거래량 지표 추가 |
| L3 구조 | 전략 로직 | 조건 순서 변경 |
| L4 앙상블 | 전략 가중치 | 순환매매 30%→40% |
| L5 메타 | 학습 알고리즘 자체 | GP → RL 전환 |

### 3-3. 자기수정 루프
```
[성과 모니터링]
   ↓
[드리프트 감지] ← Sharpe 하락, MDD 증가
   ↓
[원인 진단] ← 피처 중요도 변화, regime 변화
   ↓
[수정 후보 생성] ← AutoML, 진화, LLM
   ↓
[샌드박스 백테스트]
   ↓
[shadow 트레이딩] ← 실계좌 병행, 자금 X
   ↓
[성과 비교] ← 기존 vs 신규
   ↓
[승인 요청] ← Human PM or 자동(소액)
   ↓
[배포 or 롤백]
```

### 3-4. 수정 트리거
- 성과 저하: Sharpe 30% 이상 하락
- 드리프트: 피처 분포 변화 (KS-test)
- Regime 전환: HMM 상태 변화
- 상관 붕괴: 기존 알파 소멸
- 정기 재학습: 월/분기별

### 3-5. 안전장치 (필수)
| 장치 | 역할 |
|---|---|
| 샌드박스 | 실계좌 격리, 시뮬레이션만 |
| Shadow Mode | 신규 전략 병행 관찰 |
| 롤백 | 문제 시 즉시 이전 버전 복원 |
| 버전 관리 | 모든 수정 이력 Git 관리 |
| 변경 한도 | 1회 수정 폭 제한 (예: 파라미터 ±20%) |
| 인간 승인 게이트 | L3 이상 수정은 인간 필수 |
| 킬스위치 | MDD 한도 도달 시 전체 중단 |
| 감사 로그 | "왜 수정했는가" 기록 |

## PART 4. ③ Autonomous Execution Agent (자율 실행)

### 4-1. 무엇을 하는가
승인된 전략을 **자동 실행**하고, 오류 발생 시 스스로 **복구**합니다.

### 4-2. 실행 자동화 레벨
| 레벨 | 설명 | 인간 개입 |
|---|---|---|
| L0 | 신호만 제공 | 전부 인간 |
| L1 | 주문 초안 생성 | 인간 승인 |
| L2 | 소액 자동 실행 | 사후 확인 |
| L3 | 전액 자동 실행 | 예외만 개입 |
| L4 | 전략 수정까지 자동 | 감독만 |

> 실전에서는 **L1~L2에서 시작** → 성과·안정성 확인 후 단계적 상향

### 4-3. 자율 실행 구성 요소
```
[신호 수신]
   ↓
[Pre-trade 검증] ← 리스크 한도, 유동성, 상관
   ↓
[주문 생성] ← TWAP/VWAP/아이스버그
   ↓
[실행] ← 브로커 API
   ↓
[체결 확인]
   ↓
[이상 감지] ← 슬리피지, 부분체결, 거부
   ↓
[자동 복구] ← 재시도, 분할, 취소
   ↓
[포지션 관리] ← 손절, 익절, 트레일링
   ↓
[로그·리포트]
```

### 4-4. 자동 복구 시나리오
| 상황 | 자동 대응 |
|---|---|
| 주문 거부 | 재시도 → 실패 시 알림 |
| 부분 체결 | 잔량 재주문 or 취소 |
| 슬리피지 초과 | 실행 중단, 인간 알림 |
| API 장애 | 백업 브로커 전환 |
| 가격 급변 | 주문 취소, 재평가 |
| 포지션 초과 | 즉시 청산 |
| 연결 끊김 | Kill switch 작동 |

### 4-5. 자율 실행 필수 통제
- **Pre-trade risk check:** 주문 전 모든 한도 검증
- **Post-trade reconciliation:** 체결 vs 의도 대조
- **Rate limiting:** 초당 주문 수 제한
- **Circuit breaker:** 이상 변동 시 자동 중단
- **Kill switch:** 수동·자동 전체 정지
- **Human override:** 언제든 인간 개입 가능

```
   ↓
```

```
   ↓
(다시 Discovery로 피드백)
```

## PART 7. 필수 안전장치 (자기진화 시스템)

### 7-1. 3중 방어선
| 방어선 | 역할 |
|---|---|
| 1차: 샌드박스 | 신규·수정 전략은 격리 환경에서만 |
| 2차: Shadow | 실계좌 병행, 자금 투입 X |
| 3차: 소액 실전 | 리스크 한도 10% 이내 |

### 7-2. 절대 규칙
- 자기수정 ≠ 자기승인: 수정과 승인은 분리
- 자율실행 한도: 일일 손실 한도 초과 시 자동 중단
- 롤백 가능: 모든 변경은 되돌릴 수 있어야
- 감사 가능: "왜 이 결정을 했는가" 추적 가능
- 인간 최종 권한: 레버리지·자본배분은 인간 승인
- 킬스위치: 언제든 전체 정지

### 7-3. 금지 사항
- ❌ 자기 코드를 실계좌에서 직접 수정
- ❌ 승인 없이 레버리지 변경
- ❌ 손실 은폐·로그 조작
- ❌ 리스크 한도 우회
- ❌ 인간 개입 차단
