## 0. 설계 원칙 (모든 에이전트 공통)

1. **AI는 주문하지 않는다.** 에이전트가 내는 결과물은 리포트와 "허용 범위" 파일뿐입니다. 주문은 매매법 봇 코드가 냅니다.
2. **절대 한도는 코드에 있다.** 최대 레버리지, 비중, 하루 손실 한도는 코드 상수입니다. 에이전트는 이 한도를 **줄이거나 거부**할 수만 있고, 넓힐 수는 없습니다.
3. **실패는 실패로 기록한다.** 에이전트 응답이 깨졌을 때 '승인'이나 '매수' 같은 기본값을 채우지 않습니다. 받은 앱이 PM 실패를 APPROVE로 기록한 실수를 반복하지 않기 위해서입니다. 계획이 없거나 만료되면 봇은 신규 진입을 멈춥니다.
4. **계산은 코드, 해석은 AI.** 지표, 장세 라벨, 장부 대조, 통계는 스크립트가 숫자로 만들고, 에이전트는 그 숫자를 읽고 해석합니다.
5. **외부 텍스트는 믿지 않는다.** 뉴스와 공지는 "신뢰하지 않는 데이터"로 표시해서 넘깁니다(프롬프트 인젝션 방지). 에이전트는 API 키나 `.env`가 있는 폴더를 읽을 수 없습니다.
6. **측정해서 존폐를 정한다.** 에이전트가 실제로 도움이 되는지 숫자로 재고, 도움이 안 되는 역할은 없앱니다.

바이낸스 펀딩은 보통 09:00, 17:00, 01:00(KST)입니다. 종목별로 다를 수 있으므로 `fundingInfo`로 확인합니다.

## 4. 에이전트가 아닌 두 축

### ⑦ 자동 안전장치 (봇 코드, 24시간, 테스트넷 가동 전 필수)
1. **허용범위 관문**
   - 스키마 검증, 절대 한도로 자르기(clamp)
   - 유효기간이 지나거나 파일이 무효면 신규 진입 금지
   - 파일은 원자적으로 교체하고 해시를 기록
2. **가동 감시**
   - 자동 재시작, 1분 간격 외부 데드맨 핑
   - **진입 직후 거래소 측 보호 손절 주문**
3. **데이터 품질 감시**
   - 스트림 수신 시각 추적, 23시간 선제 재연결, listenKey 유지, 누락 캔들 보충, 시계 점검
4. **주문 멱등성과 재시작 복구**
   - `bot_` 접두어 clientOrderId, -1007이면 조회 후 재시도
   - 시작할 때마다 거래소와 장부를 대조하고, 불일치면 진입 차단
5. **킬 스위치**
   - 텔레그램 `/status`, `/halt`, `/flatten`(2단계 확인). 두 사람의 chat_id만 허용
   - 연속 에러나 장부 불일치가 생기면 자동 정지
   - 심각 알림에 무응답이면 자동 안전 모드
6. **포트폴리오 하드캡과 넷팅**
   - 봇별 서브포지션을 종목별 순포지션으로 합쳐 주문하고, 손익은 봇별로 기록
   - 전체 노출 상한, 전략 자동 정지 기준
7. **가상 장부**
   - 실제(메인넷) 시세 기준, 수수료·펀딩·슬리피지 반영
   - 섀도 장부("AI 계획 없이 돌렸다면")를 함께 기록
8. **기록 체계**
   - JSON 로그 + 상관 ID, 커밋·설정·계획 해시 기록
   - 백테스트 시행 기록부, 결정 기록부
9. **notify 모듈**: 텔레그램 발송·형식 담당, 재시도, 중복 방지
10. **AI 파이프라인 실행기**
    - 아침·저녁 `claude -p` 타이머, JSON 스키마 출력, 실패하면 경보 + 안전 모드
    - `--bare` 금지(API 과금)
11. **거래소 규격 변경 감지**: 틱·수량·최소금액, 레버리지 구간, 펀딩 주기

## 10. 추가: ⑦ 매매 복기·개선팀 (에이전트 2명 + 코드 진단기)

목적: 가상매매에서 손실이 나면 **왜 졌는지**를 빠르게 분류하고, 수정안을 검증한 뒤 반영하는 개선 루프를 돌린다.

### 10-1. 코드 진단기 (실시간, 매 거래 종료 즉시)
진입 순간의 **상황 스냅샷**과 보유 중 **MAE/MFE**(최대 역행·최대 순행)를 장부에 저장하고, 거래가 끝나면 규칙으로 손실 유형 태그를 붙여 텔레그램에 한 줄로 보낸다.

| 유형 | 태그 | 판정 근거(코드 계산) |
|---|---|---|
| 진입 위치 | 고점 롱 / 저점 숏 | 진입가가 최근 N봉 범위의 상위(하위) 10% 이내 |
| 진입 위치 | 추세 막판 진입 | 추세 시작 후 경과 봉 수, 이동평균과의 거리(ATR 배수)가 큼 |
| 진입 방향 | 역추세 진입 | 상위 봉(예: 15m 매매면 1h·4h) 추세와 반대 방향 |
| 장세 | 장세 불일치 | 추세 매매법인데 횡보장, 역추세 매매법인데 강한 추세장 |
| 진입 위치 | 가짜 돌파 | 돌파 후 N봉 안에 범위 안으로 복귀 |
| 청산 | 손절 과소 | 손절 직후 가격이 반전해 목표 도달 / 손절 거리 < k·ATR |
| 청산 | 수익 반납 | MFE는 컸는데 손실로 마감 |
| 청산 | 이른 익절 | 실현 수익이 MFE의 일부에 그침 |
| 타이밍 | 이벤트·시간대 | 지표 발표·펀딩 시각 근처, 주말 새벽 저유동성 |
| 실행 | 실행 문제 | 슬리피지 과다, 신호→체결 지연, 부분체결, 주문 오류 → **매매법이 아니라 코드 문제** |
| 정상 | 정상 손실 | 규칙대로 진입·청산했고 백테스트 통계 범위 안 → **고칠 것 없음** |

### 10-2. 에이전트
| 에이전트 | 언제 | 하는 일 | 모델 |
|---|---|---|---|
| **매매 복기 분석가** `trade-reviewer` | 4시간마다 손실 거래 묶음 + 큰 손실(예: -1.5R 이하)·연속 손실 시 즉시 | 태그와 차트 상황(상위봉 추세, 지지·저항, 파생 지표)을 보고 원인을 서술. 태그가 틀렸으면 정정. "정상 손실"인지 "고칠 문제"인지 구분 | Sonnet |
| **개선 설계자** `improvement-designer` | 주 1회 + 같은 유형 손실이 일정 횟수 쌓였을 때 | 유형별 손실 패턴을 모아 수정 가설을 만든다(예: "손실의 55%가 4h 역추세 진입 → 4h 추세 필터 추가"). 기대 효과와 검증 방법을 명시 | Opus |

### 10-3. 개선 루프
```
가상매매 → 코드 진단 태그(즉시) → 복기 분석가(4시간/즉시) → 개선 설계자(주간 패턴·수정안)
   ▲                                                              │
   │                                                              ▼
 두 사람 승인·배포 ◀─ 코드 리뷰·테스트 ◀─ 가상 장부 A/B(도전자 병행) ◀─ 전략 검증관 백테스트
```
- 수정안은 **바로 적용하지 않는다.** 최근 손실 몇 건에 맞춘 수정은 과최적화가 되기 쉽다. 전체 기간 백테스트를 통과해야 한다.
- 통과한 수정안은 **도전자 버전**으로 가상 장부에서 기존 버전과 **같은 시세로 동시에** 돌린다(추가 주문 없음). 일정 기간 비교 후 이긴 쪽을 채택.
- 매매법 버전은 v1.0, v1.1… 로 기록하고, 모든 거래에 버전이 찍힌다.
- 실시간 보호 조치(전략 일시정지)는 코드 서킷브레이커가 즉시 한다. 규칙 수정은 검증과 승인을 거친다.

## 11. 개정 (2026-09-29): 손익 복기 시스템 v2

세부 내용은 `docs/trade-review-system.md`에 있습니다.

### 손실 유형
- **박스권 계열(B1~B8)을 추가합니다.**
  - 박스 중간 진입
  - 박스 끝 추격
  - 박스권 휩쏘
  - 박스 돌파 실패
  - 돌파 후 리테스트 손절
  - 박스 붕괴
  - 상위봉 박스 벽 앞 진입
  - 진입 후 박스화
- **박스와 혼조를 구분합니다.** 박스는 경계가 분명한 횡보이고, 혼조는 경계 없이 들쭉날쭉한 장입니다.
- **폐지·이동하는 태그**
  - "고점 롱/저점 숏"은 폐지합니다. 돌파 매매 대부분에 붙는 무의미한 태그라서 B2와 E1로 흡수합니다.
  - "이른 익절"은 익절 체계로 옮깁니다.
- **새 태그**
  - 구현·데이터 불일치(X1)와 개입 귀속(X3): 매매법 통계에서 제외합니다.
  - 급변 충격(S1)
- 이긴 거래·본전 거래·백테스트 거래에도 같은 태그를 붙이고, 기대값과 lift로 문제 여부를 판단합니다.

### 익절 분석
- 이익·청산 품질 태그 W1~W10: 이른 익절, 늦은 익절, 적정, 운 좋은 익절, 수수료 잠식, 목표 과대, 구조 레벨 앞 반전, 구조 돌파 연장, 본절 털림, 익절 체결 문제
- **청산 실험실(코드)**: 청산 정책 C0~C11(가격 %, ROE %, R배수, 구조 목표, 샹들리에 트레일, 분할+러너, 시간 청산 등)을 모든 거래에 똑같이 적용해 비교합니다.

### 에이전트 변경
- 매매 복기 분석가 → **손익 복기 분석가**
  - 이익 거래도 복기합니다.
  - 주기: 하루 1회(22:00) + 순손익 −2R 이하는 즉시
  - 5m·15m 거래는 건별로 서술하지 않습니다.
- 개선 설계자: 진입 시점 태그의 lift 표와 청산 정책 비교표만 입력으로 받습니다. 가설은 실험 레지스트리에 등록합니다.
- 전략 검증관: 도전자 A/B와 청산 정책 채택을 판정합니다. 누적 시험 수를 반영하고 다중 비교를 보정합니다.
- 전략 연구원: 명세 카드에 진입 규칙별 스타일, 보유 중 이벤트 처리표, 워밍업·TTL, R 정의, 체결 가정을 추가합니다.
- 전략가: 주간 위험 예산 제안을 폐지합니다(Demo 동안은 거래당 고정 위험).
- 조직 규모: **새 LLM 에이전트는 0명**입니다. 16명을 유지하고, 8주 뒤 상관 분석가 합병을 검토합니다.
