## 0. 설계 원칙 (모든 에이전트 공통)

1. **AI는 주문하지 않는다.** 에이전트가 내는 결과물은 리포트와 "허용 범위" 파일뿐입니다. 주문은 매매법 봇 코드가 냅니다.
2. **절대 한도는 코드에 있다.** 최대 레버리지, 비중, 하루 손실 한도는 코드 상수입니다. 에이전트는 이 한도를 **줄이거나 거부**할 수만 있고, 넓힐 수는 없습니다.
3. **실패는 실패로 기록한다.** 에이전트 응답이 깨졌을 때 '승인'이나 '매수' 같은 기본값을 채우지 않습니다. 받은 앱이 PM 실패를 APPROVE로 기록한 실수를 반복하지 않기 위해서입니다. 계획이 없거나 만료되면 봇은 신규 진입을 멈춥니다.
4. **계산은 코드, 해석은 AI.** 지표, 장세 라벨, 장부 대조, 통계는 스크립트가 숫자로 만들고, 에이전트는 그 숫자를 읽고 해석합니다.
5. **외부 텍스트는 믿지 않는다.** 뉴스와 공지는 "신뢰하지 않는 데이터"로 표시해서 넘깁니다(프롬프트 인젝션 방지). 에이전트는 API 키나 `.env`가 있는 폴더를 읽을 수 없습니다.
6. **측정해서 존폐를 정한다.** 에이전트가 실제로 도움이 되는지 숫자로 재고, 도움이 안 되는 역할은 없앱니다.

바이낸스 펀딩은 보통 09:00, 17:00, 01:00(KST)입니다. 종목별로 다를 수 있으므로 `fundingInfo`로 확인합니다.

## 4. 에이전트가 아닌 두 축

### ⑦ 자동 안전장치 (봇 코드, 24시간, 테스트넷 가동 전 필수)
1. **허용범위 관문**
   - 스키마 검증, 절대 한도로 자르기(clamp)
   - 유효기간이 지나거나 파일이 무효면 신규 진입 금지
   - 파일은 원자적으로 교체하고 해시를 기록
2. **가동 감시**
   - 자동 재시작, 1분 간격 외부 데드맨 핑
   - **진입 직후 거래소 측 보호 손절 주문**
3. **데이터 품질 감시**
   - 스트림 수신 시각 추적, 23시간 선제 재연결, listenKey 유지, 누락 캔들 보충, 시계 점검
4. **주문 멱등성과 재시작 복구**
   - `bot_` 접두어 clientOrderId, -1007이면 조회 후 재시도
   - 시작할 때마다 거래소와 장부를 대조하고, 불일치면 진입 차단
5. **킬 스위치**
   - 텔레그램 `/status`, `/halt`, `/flatten`(2단계 확인). 두 사람의 chat_id만 허용
   - 연속 에러나 장부 불일치가 생기면 자동 정지
   - 심각 알림에 무응답이면 자동 안전 모드
6. **포트폴리오 하드캡과 넷팅**
   - 봇별 서브포지션을 종목별 순포지션으로 합쳐 주문하고, 손익은 봇별로 기록
   - 전체 노출 상한, 전략 자동 정지 기준
7. **가상 장부**
   - 실제(메인넷) 시세 기준, 수수료·펀딩·슬리피지 반영
   - 섀도 장부("AI 계획 없이 돌렸다면")를 함께 기록
8. **기록 체계**
   - JSON 로그 + 상관 ID, 커밋·설정·계획 해시 기록
   - 백테스트 시행 기록부, 결정 기록부
9. **notify 모듈**: 텔레그램 발송·형식 담당, 재시도, 중복 방지
10. **AI 파이프라인 실행기**
    - 아침·저녁 `claude -p` 타이머, JSON 스키마 출력, 실패하면 경보 + 안전 모드
    - `--bare` 금지(API 과금)
11. **거래소 규격 변경 감지**: 틱·수량·최소금액, 레버리지 구간, 펀딩 주기

- **실거래 전환 기준 숫자는 테스트넷 성적을 보기 전에** 합의
- 수동 개입 규율: 손실 뒤 "한도 잠깐만 풀자" 금지, 규칙 위반 시 24시간 쿨다운
- 세무·법률 판단은 전문가에게

## 5. 이번에 새로 추가한 것

1. **에이전트 성적표와 존폐 규칙:** 에이전트도 성과로 평가합니다.
   - 장세 라벨 적중률, 파생 경고 뒤 실제 변동, 반론 검토관이 막은 손실, 리스크 책임자 거부의 사후 정답률을 기록합니다.
   - 월 1회 평가해 기여가 없는 역할은 없애거나 합칩니다.
2. **교훈 노트(`docs/lessons.md`):** 포스트모템에서 나온 재발 방지 규칙을 모읍니다.
   - 서브에이전트는 매번 기억 없이 시작하므로, 관련 에이전트가 매번 이 파일을 읽게 합니다.
3. **에이전트 입출력 계약:** 각 에이전트 파일에 입력 파일, 출력 파일, 출력 JSON 스키마를 명시합니다. 형식이 깨지면 코드가 "실패"로 처리합니다.
4. **실시간 차트 페이지(⑨):** TradingView Lightweight Charts로 5종목 캔들 위에 봇 실제 체결(테스트넷·가상장부 색 구분), 손절·익절 선, 봇 상태를 표시합니다. 텔레그램 알림에 링크를 붙입니다.
5. **주간 15분 사람 회의:** 팀장이 1페이지 요약을 만들고, 두 사람이 결정할 것만 봅니다.
6. **용어집(`docs/glossary.md`):** 리포트에 새 용어가 나오면 팀장이 추가합니다.
7. **(나중에, 선택) 텔레그램 온디맨드 호출:** `/brief BTC` 같은 명령으로 분석팀을 즉석 호출합니다. 사용량을 보고 결정합니다.

## 6. 일부러 넣지 않은 것
| 제안 | 넣지 않은 이유 |
|---|---|
| 몇 분마다 로그를 보는 상시 감시 AI | 사용량 소모가 크고, 코드 감시보다 느리고 불안정함 |
| 머신러닝 담당 | 종목 5개가 서로 상관이 높고 표본이 적어 과최적화 위험이 큼. 3개월 이상 기록이 쌓인 뒤 재검토 |
| 거래마다 매매 일지를 쓰는 AI | 사후 합리화 위험. 주 1회 최악·최고 5건 복기로 대체 |
| 별도 포트폴리오 매니저, TCA 전담 | 전략가·리스크 책임자·코드 하드캡으로 충분. 실거래 전환 때 재검토 |
| AI가 트레이딩뷰·Astral로 주문 신호 보내기 | "AI는 주문하지 않는다" 원칙 위반 |

## 7. 만드는 순서
1. **지금 (매매법 없이 가능):** ⑦ 안전장치 코드, 데이터 수집 스크립트, 가상 장부, notify, 실시간 차트 페이지, 개발팀 2명
2. **다음:** 분석팀 4명 + 전략가·반론 검토관·리스크 책임자·팀장 + 아침 파이프라인. 봇이 없어도 "시장 브리핑"만 먼저 돌려 볼 수 있습니다.
3. **매매법 도착:** 전략 연구원 → 전략 검증관 → 테스트넷 가동, 저녁 파이프라인, 운영 감사관·성과 분석가
4. **8주 뒤:** 에이전트 성적표로 존폐 결정, 실거래 전환 심사
