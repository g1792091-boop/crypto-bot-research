## 2. 토요일 순서

1. **01:00 KST 이후** 주간 사용량이 풀렸는지 확인하고 몇 %인지 알려 주기.
2. **서버에서 규칙 봇 결과 파일 다시 뽑기** (읽기 전용, 서버 `/root/rb_export.py`가 이미 있음. 없으면 `analysis/rulebot_1007/scripts/rb_export.py`를 붙여 넣기).
   ```bash
   sudo -i
   nice -n 19 python3 /root/rb_export.py
   ```
   끝나면 `/root/paperbot_export_<날짜>.zip`이 생긴다. 대화에 첨부.
3. **오후(예: 14:15 KST) 시장 자료 내보내기**: `analysis/rulebot_1007/pending_1007_night/market_data/RUN_ON_SERVER_KO.md`의 상자를 그대로 붙여 넣기(읽기 전용, 1분 안, 1~15 MB). 8:30~9:40 KST와 매시 05~12분은 피한다. 결과 zip도 첨부.
4. **Claude가 하는 일**: 압축을 풀고 `analyze.py`를 다시 돌려(약 30초, 에이전트 없음) **기계적 사실만** 확인한다: 비용 수준, 신호 빈도, 0거래 원인, 규칙 봇 건강, 선정한 매매법의 신호 수. **매매법을 다시 뽑지 않는다**(결과를 보고 고르면 판정이 오염된다).
5. **비용 상한 정하기**: 시작은 등급 S(목표 약 $280, 절대 상한 $300), 10/27 예산 관문을 통과하면 M-lite(상한 $490)로 올리는 길을 사전 등록. 확정 금액은 0차 재생 시험(실제 호출 단가)으로 다시 계산.
6. **정할 것** (문서 12장, 전체 41개 중 급한 것): 좋아 여부, 등급, 크기 규칙, 진입 질문 방식, 청산 기준, 체결 방식, 연습 방식, 콘솔 한도(조직 등급·다른 작업 공간 사용액 확인), 청구 기준(콘솔 사용액 vs 카드 청구서), 시작일, 한도 값(3/1/8 vs 4/1/10), 2차 명단 교체(S2→N09, N02→F9_IFVG).
7. **두 분이 "좋아" 하시면** 그때부터 만든다. 그 전에는 코드·설치·API 호출을 하지 않는다.

## 3. 일정 주의

설계 v3는 "10/9까지 결정, 10/17 시작"으로 쓰였다. 토요일(10/10)에 결정하고 만들기 양이 약 28.8일(줄인 범위 기준)이라, 현실적인 시작은 **10/24, 늦어도 10/31**이다(12장 40번). 일정 숫자(0차 시험, 사전 등록, 2차 열기)는 토요일에 한 번에 다시 계산한다. 시작이 늦어지면 판정 기간이 짧아져(10/24 시작이면 약 62일) 판정에 쓸 거래 수가 줄어든다.
