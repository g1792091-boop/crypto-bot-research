# 레버리지 규칙 B 평가 방법 — 미리 정함

작성: 2026-10-04 (KST), 새 실행이 시작되기 전. 두 분이 승인한 추가 작업입니다. 이 문서는 해시로 고정합니다(`docs/levrule-eval.sha256`). 고치지 않고, 바꿀 일이 생기면 새 문서를 씁니다.

규칙 B는 `docs/paper-v3-rules-change-1.md` 6절의 레버리지·증거금 규칙입니다(코드 `paperbot/levrule.py`, `config.V3_LEVERAGE_RULE = "quality_v1"`). 진입 품질이 `best`인 신호(**좋은 자리**)는 50배·50% → 40배·40% → 30배·30% → 20배·20%, 나머지 신호(**보통**)는 30배·30% → 20배·20%를 차례로 시도합니다. 동전 던지기 봇은 신호마다 봉별 확률 p_best(약 21%)로 좋은 자리가 됩니다.

## 1. 질문

**좋은 자리 진입이 보통 진입보다, 노출 1단위당 더 잘 되는가?**

레버리지가 크면 손익도 커지므로 손익 자체를 비교하면 "레버리지가 커서"와 "자리가 좋아서"를 가를 수 없습니다. 그래서 크기를 나눈 숫자로 봅니다.

## 2. 숫자

- 거래 하나의 **노출 1단위당 수익** r = (그 거래의 자금 대비 손익) ÷ (레버리지 × 증거금 비율).
  - 증거금 = 자금 × 증거금 비율이므로, r = 손익 ÷ (증거금 × 레버리지) = 손익 ÷ 진입 명목금액 = ROE ÷ 레버리지입니다.
  - 코드: `trades.pnl ÷ (trades.data.margin × trades.leverage)`. 손익은 수수료·슬리피지·펀딩을 뺀 순손익(엔진 기록 그대로), 강제청산은 증거금 전부 손실 그대로입니다.
- **묶음**: 거래 기록의 `tier` 칸입니다. `best` = 좋은 자리, `normal` = 보통. 좋은 자리가 50·40배에 막혀 30·20배로 들어가도 좋은 자리로 셉니다(신호의 묶음이지 들어간 배수가 아님).
- **기간**: 새 실행 시작부터 첫 판정(시작한 UTC 날짜 0시 + 30일 = 09:00 KST, `paperbot/checkpoint.py`의 `checkpoint_ts(시작, 1)`)까지. 이 사이에 **진입하고 그 전에 끝난** 거래만 셉니다. 판정 때 열려 있는 포지션은 넣지 않습니다.
- **계좌**: 매매법 계좌(`kind = strategy`, 36개 × 15분·30분·1시간·4시간 = 144개)와 동전 던지기 계좌(`kind = random`, 12개). 복제 계좌·새 매매법 계좌는 넣지 않습니다.

## 3. 검정

1. **칸** = 매매법 × 봉 계좌 하나(동전 봇은 동전 봇 하나 × 봉). 좋은 자리와 보통 **둘 다 끝난 거래가 10건 이상**인 칸만 씁니다(적격 칸). 적격 칸은 원래 자료로 한 번 정합니다.
2. 칸마다 **d = 평균 r(좋은 자리) − 평균 r(보통)**. 매매법 쪽 차이 **D_s** = 적격 칸 d의 단순 평균(칸마다 같은 무게). 동전 봇 쪽 **D_c**도 같은 방법.
3. **차이의 차이 DiD = D_s − D_c**: 매매법의 좋은 자리 효과가 우연(동전 봇의 같은 구분)보다 큰가.
4. **불확실성: 주 단위 블록 부트스트랩.** 블록 = 시작 시각부터 7일씩(진입 시각 기준, 마지막 블록은 짧을 수 있음). 블록을 블록 수만큼 복원 추출하고, 뽑힌 블록의 모든 계좌 거래를 함께 씁니다(같은 주에 같은 시장을 겪은 거래끼리 닮은 것을 살림). 10,000번, 시드 20261004. 매번 적격 칸에서 d를 다시 계산하고(그 번에 한 묶음의 거래가 없는 칸은 그 번에서만 뺌) D_s*, D_c*, DiD*를 구합니다.
5. **한쪽 p값**: p_s = (D_s* ≤ 0인 횟수 + 1) ÷ (10,000 + 1). 계산할 칸이 하나도 남지 않은 번은 0 이하로 셉니다. DiD의 p_did도 같은 방법으로 구해 함께 적습니다(참고용, 판정 조건은 아님).

## 4. 판정 (30일 체크포인트에서 한 번)

다음 두 조건을 **모두** 만족할 때만 규칙 B를 **다음 30일에도 유지**합니다.

- (가) **D_s > 0 이고 p_s ≤ 0.10**: 매매법 계좌에서 좋은 자리가 보통보다 노출 1단위당 더 잘 됨.
- (나) **D_s > D_c**: 그 차이가 동전 봇의 좋은 자리 − 보통 차이보다 큼. 동전 봇에 적격 칸이 없으면 (나)는 만족하지 못한 것으로 봅니다.

그렇지 않으면(적격 칸이 없어 계산할 수 없는 경우 포함) **다음 창은 모든 신호를 20배·증거금 20% 고정**으로 돌립니다. 규칙 버전에 따라 새 계좌로 시작하고(`docs/paper-v3-rules-change-1.md` 4절), 두 분이 확인합니다.

- 계산은 코드가 합니다: `paperbot/agents/leveval.py`의 `levrule_eval`. 같은 자료에서는 언제 돌려도 같은 결과입니다(시드 고정).
- 유지되면, 그 다음 창의 끝에서 그 창의 거래로 같은 방법을 다시 씁니다.

## 5. 지키는 것

- **에이전트는 규칙 B를 이 문서의 방법으로만 평가합니다.** 다른 지표, 다른 기간, 칸 골라내기, 그림자(`lev30`~`lev50`, `lev20m20`~`lev50m50`)나 실제 배수별 표(`rr.tiers`)로 B를 판정하지 않습니다. 그것들은 설명용입니다.
- **창 중간에는 아무것도 바꾸지 않습니다.** 30일 전의 숫자는 중간값이고 "30일 판정 전 결론 없음"입니다.
- 판정 결과(유지 / 20배 고정)는 코드가 낸 그대로 전합니다. 결과를 보고 기준(10건, 0.10, 블록 길이)을 옮기자는 말은 하지 않습니다.
