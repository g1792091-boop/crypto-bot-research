## 5. 코드가 하는 일 (AI가 아님)
- **매매법 봇**: 신호, 진입·청산
- **동적 엔진**: 셋업 점수 → 레버리지 20~50배, 증거금 20~40%, 자동 손절 선택, 15% 한도 검사, 계좌 청산 거리 검사
- **paper 엔진**: 호가 기반 체결, 수수료, 펀딩, 교차 마진 청산 공식. 실행 확인 장부(1배)와 두 분 규칙 장부(20~50배) 동시 운영
- **② 신호 기록 장부**: 미통과 매매법의 신호와 가상 체결가만 저장
- **안전장치**: 킬스위치(`/status`, `/halt`, `/flatten`), 가동 감시, 데이터 품질 감시, 재시작 복구, 신호 위생, 허용범위 관문
- **실험실**: 청산 실험실, 가정 실험실, 요일·시간대 분석, 조합 분석기, 장세 판정기, 유사 패턴 엔진
- **검증 관문**: DSR, PBO, FDR, walk-forward, Purged CV, 상관 필터, 모든 시도 기록
- **기록·알림**: 3등급 알림, 근거 검사기, 버전·배포, 백업
- **기술 스택**: Kafka, TimescaleDB, Parquet, Airflow, MLflow, DVC, Prometheus·Grafana, Docker

## 7. 부족한 부분 최종 점검
**에이전트: 충분합니다.** 거래 전 과정(분석 → 계획 → 리스크 → 실행 → 복기 → 가정 → 개선 → 발굴 → 검증 → 승인)에 모두 담당자가 있습니다.

**남은 것 (에이전트가 아닌 것)**
1. **만들어야 할 코드**: 위 5장 전체
2. **검증을 통과한 매매법**: 다른 세션 예상으로는 ① 통과가 0개일 수 있습니다. 그러면 paper 봇은 ② 신호 기록과 자기진화팀의 새 전략 검증부터 돌아갑니다. 에이전트가 없는 엣지를 만들어 낼 수는 없습니다.
3. **고레버리지 팩트 확인**: 최소 등급도 포지션이 계좌의 4배, 최대 등급은 20배입니다. 1회 15% 손실이 연속되면 5번에 444달러가 남습니다. 다른 세션의 "두 분 규칙 시뮬레이션" 5년 결과로 이 설정의 성과를 팩트로 확인해야 합니다.
4. **실거래 전 주문 경로 점검**: paper는 실제 주문 API를 확인하지 못합니다. 전환 직전 최소 금액으로 1~2주 점검합니다.
5. **"20배 최소"와 넓은 손절의 충돌 처리**: 최소 등급에서도 15% 한도를 넘는 넓은 손절은 **진입하지 않음**으로 확정합니다. 20% 증거금 기준 ROE -75%, 20배에서 가격 약 3.75%가 한계입니다.

## 8. 만드는 순서
1. **지금** (매매법 없이 가능): paper 엔진, 동적 엔진, 안전장치, 텔레그램, 가져오기 코드, 가정·청산 실험실, 개발팀 2명
2. **백테스트 결과 도착**: 저장소 `backtest/results` 브랜치로 가져오기 → 재현 검사 → ①②③ 분류 → 가정·요일시간·조합 분석
3. **paper 가동**: ① 매매법은 두 장부 운영, ②는 신호 기록. 에이전트 아침·저녁 파이프라인 시작
4. **자기진화 가동**: 발굴·개선 루프, 연구 서버
5. **3~6개월 뒤**: ② 재판정, 성적표로 에이전트 존폐, 실거래 전환 심사


## 9. 가정(What-if) 분석 전체 목록

손절만이 아니라 **진입, 청산, 크기, 필터, 시간, 포트폴리오, AI 판단, 비용, 기준선, 스트레스**까지 봅니다.
계산은 코드(가정 실험실)가 하고, 가정 분석가는 결과를 해석합니다. 항목이 많아 가정 분석가는 **분야별로 나눠 여러 번 실행**합니다.

### A. 진입 (매일)
| 만약… | 비교 값 |
|---|---|
| 진입을 늦췄다·당겼다면 | 신호 봉 / 1봉 뒤 / 2봉 뒤 |
| 되돌림에서 지정가로 들어갔다면 | 0.25·0.5·1×ATR 되돌림, 미체결 건 포함 |
| 돌파를 한 번 더 확인했다면 | 종가 1봉 / 2봉 확인, 리테스트 진입 |
| 나눠서 들어갔다면 | 50%+50%, 33%×3 |
| 주문 방식이 달랐다면 | 시장가(테이커) vs 지정가(메이커 수수료) |
| 방향을 한쪽만 했다면 | 롱만 / 숏만 |

### B. 청산 (매일)
| 만약… | 비교 값 |
|---|---|
| 손절이 달랐다면 | ROE -10/-20/-30/-40/-50%, 구조·ATR·박스·무효화 손절 |
| 익절이 달랐다면 | ROE 10/15/20/30/50%, 구조 익절, R배수 |
| 트레일링을 했다면 | ATR 2/3/4배, 시작 조건(ROE +10/+20% 도달 후) |
| 나눠서 익절했다면 | 절반 익절 + 나머지 트레일링/본절 |
| 본절로 옮겼다면 | ROE +10/+20/+30% 도달 시 |
| 시간으로 정리했다면 | N봉 안에 목표 미도달 시 청산 |
| 반대 신호가 나왔을 때 | 청산 / 반전 / 무시 |
| 펀딩 직전에 정리했다면 | 정산 10분 전 청산 여부 |
| 손절·익절 조합이 달랐다면 | 손절 × 익절 격자 (예: -20% × 30%) |

### C. 크기 (매일)
| 만약… | 비교 값 |
|---|---|
| 레버리지가 달랐다면 | 20/30/40/50배, 1배(실행 확인 장부) |
| 증거금이 달랐다면 | 20/30/40% |
| 셋업 점수 대신 고정이었다면 | 동적 등급 vs 20%×20배 고정 |
| 복리 vs 원금 고정이었다면 | 현재 잔고 기준 vs 1,000달러 기준 |
| 격리 vs 교차 마진이었다면 | 청산 발생 차이 |

### D. 필터 (주간)
| 만약… | 비교 값 |
|---|---|
| 상위봉 추세와 같은 방향만 탔다면 | 1h/4h/1d 기준 |
| 박스·혼조장을 피했다면 | 장세 판정기 기준 |
| 거래량 조건을 걸었다면 | 평균 대비 1.5배·2배 이상일 때만 |
| 펀딩·미결제약정 과열 때 피했다면 | 과열 반대 방향 금지 |
| 셋업 점수 기준 이상만 들어갔다면 | 기본 / 좋음 / 최상만 |
| 연속 손실 뒤 쉬었다면 | 2·3연패 후 N시간 휴식 |
| 같은 박스 재진입을 막았다면 | 첫 손실 후 금지 |

### E. 시간 (주간)
| 만약… | 비교 값 |
|---|---|
| 요일·주말을 피했다면 | 요일별, 주말 제외 |
| 세션을 골랐다면 | 아시아·유럽·미국·새벽 중 제외 |
| 이벤트 시간을 피했다면 | 미 개장 ±1h, 경제지표 ±30분, 펀딩 ±10분 |
| 주말을 넘겨 들고 있지 않았다면 | 금요일 밤 정리 |

### F. 포트폴리오 (주간)
| 만약… | 비교 값 |
|---|---|
| 매매법을 빼거나 더했다면 | 한계 기여도, 시너지 행렬과 연결 |
| 종목을 뺐다면 | 5종목 중 하나씩 제외 |
| 동시 포지션 상한을 두었다면 | 1/2/3개 (현재 규칙은 상한 없음) |
| 일일 손실 정지를 두었다면 | -15%/-30% 도달 시 (현재 규칙은 정지 없음) |
| 같은 종목 반대 포지션을 허용·금지했다면 | 넷팅 효과 |

### G. AI 판단 (주간)
| 만약… | 비교 값 |
|---|---|
| AI 계획(허용범위)을 따르지 않았다면 | 섀도 장부 대비 |
| 리스크 책임자가 줄이지 않았다면 | 축소·거부 건의 사후 결과 |
| 반론 검토관 의견을 따랐다면 | 반론이 맞았던 비율 |
| 자기개선 수정 전 버전이었다면 | 챔피언 vs 도전자 |
| 사람이 수동 개입하지 않았다면 | 개입 건 사후 결과 |

### H. 비용·체결 (주간)
| 만약… | 비교 값 |
|---|---|
| 슬리피지가 2배였다면 | 비용 스트레스 |
| 수수료가 달랐다면 | 메이커 위주 / VIP 등급 |
| 체결이 늦었다면 | 1초 / 5초 / 30초 지연 |

### I. 기준선 (월간): "실력인가 운인가" 팩트 확인
| 비교 | 의미 |
|---|---|
| 무작위 진입 | 같은 빈도·같은 손절·익절로 무작위로 들어갔을 때보다 나은가 |
| 신호 반대로 | 반대로 했을 때가 더 나으면 신호에 문제 |
| 보유만 | 그냥 들고 있었을 때와 비교 |

### J. 스트레스 (월간 + 코드 변경 시)
| 만약… | 비교 값 |
|---|---|
| 폭락일에 지금 포지션이었다면 | 2022 하락장, 2025-10 폭락 등 실제 날짜 재생 |
| 가격이 갭으로 손절을 건너뛰었다면 | 손절 체결가 악화 |
| 5종목이 동시에 역행했다면 | 교차 마진 계좌 청산 여부 |

### 공통 규칙 (팩트만, 과최적화 방지)
1. **거래 한 건 결론 금지**: 한 건 단위 가정은 설명용입니다.
2. **판정은 규칙 단위**: 규칙 하나를 모든 거래에 똑같이 적용하고, 현행과 짝 비교해 신뢰구간이 0을 넘을 때만 "좋았다"고 판정합니다.
3. **시도 수를 셉니다**: 가정 항목이 많을수록 우연히 좋아 보이는 결과가 늘어납니다. 전체 비교 수를 기록하고 그만큼 기준을 높입니다(다중비교 보정).
4. **이익·손실 거래를 모두 포함**합니다.
5. **15% 한도 초과와 청산 건은 "불가"로 표시**합니다.
6. **여러 가정을 동시에 바꾼 효과**는 따로따로 더하지 않습니다. 상호작용이 있으므로 전체 백테스트로 다시 확인합니다.
7. 좋다고 나온 가정도 **바로 적용하지 않습니다.** 전략 검증관 → paper 도전자 → 자율 승인관을 거칩니다.

## 10. 학습 시스템: 에이전트가 "생각만" 하지 않고 배우게 만드는 구조

### 10-1. 먼저 팩트
- Claude 같은 AI 모델은 우리 데이터로 **두뇌(모델 가중치) 자체가 바뀌지 않습니다.** 이 프로젝트에서는 모델을 재학습시키지 않습니다.
- 그래서 에이전트는 매번 기억 없이 시작합니다.
- 따라서 "학습"은 아래 **4개 층**으로 구현합니다. 에이전트는 실행할 때마다 자기에게 필요한 학습 결과를 **자동으로 받아서** 판단에 씁니다.

### 10-2. 학습 4층
| 층 | 무엇이 배우나 | 어떻게 | 결과 |
|---|---|---|---|
| **① 지식 기억** | 에이전트 | 검증된 가정·복기 결과를 **교훈 카드**로 저장합니다. 에이전트가 실행될 때 해당 매매법·종목·봉·장세에 맞는 교훈을 자동으로 넣어 줍니다 | "이 매매법은 박스장에서 -0.4R, 손절 ROE -20%가 우위" 같은 지식을 매번 기억한 채로 판단 |
| **② 사례 기억** | 에이전트 | 대표 거래(큰 손실·큰 이익·전형적 실패)를 차트 상황, 태그, 가정 결과와 함께 **사례집**으로 저장합니다. 비슷한 상황이 오면 과거 사례를 찾아 줍니다 | 복기 분석가: "이번 손실은 3월 12일 사례와 같은 유형" |
| **③ 규칙 학습** | 봇 | 검증을 통과한 가정은 자기개선 절차(L1~L5)로 **매매법 파라미터·필터·손절·익절 규칙에 실제로 반영**합니다 | 봇의 행동이 바뀜 (버전 v1.0 → v1.1) |
| **④ 모델 학습** | 코드 ML | 가정 실험실이 만든 "상황 → 어떤 규칙이 나았나" 데이터로 **기계학습 모델**을 훈련합니다. 대상은 셋업 점수 가중치, 메타라벨링(진입할지·크기), 장세별 손절·익절 선택기, 연구 서버의 강화학습 | 점수·크기·청산 선택이 데이터로 개선됨 |

여기에 **⑤ 에이전트 자기 교정**이 더해집니다.
- 에이전트의 예측(장세 판정, 과열 경고, 반론, 거부 판단)을 사후에 **채점**합니다.
- 채점 결과를 다음 실행 때 본인에게 알려 줍니다. 예: "지난 30일 박스 판정 적중 62%, 추세 과대 판정 경향".
- 성적이 계속 낮은 에이전트는 업무 지침(프롬프트)을 고치고, 과거 입력으로 회귀 시험을 한 뒤 교체합니다.

### 10-3. 학습 흐름 예시
```
가정 실험실: "매매법 X 15분봉, 손절 ROE -20%가 -10%보다 우위 (212건)"
   ↓ 관찰 메모로 저장 (아직 판단에 쓰지 않음)
전략 검증관: 전체 기간·미관측 구간 확인 → 통과
   ↓
paper 도전자 운영 → 우위 확인 → 자율 승인관 승인
   ↓ 동시에 4곳에 반영
① 교훈 카드 등록 (근거: 거래 수, 신뢰구간, 기간, 재검토일)
② 대표 사례 3건 사례집에 추가
③ 매매법 X v1.1로 손절 규칙 변경 (봇이 배움)
④ ML 학습 데이터에 추가 → 다음 주 재학습
   ↓
다음 날부터: 손익 복기 분석가·가정 분석가·전략가가 이 교훈을 기억한 채로 판단
재검토일: 여전히 맞는지 다시 확인 → 틀리면 교훈 폐기 + 규칙 롤백
```

### 10-4. 잘못 배우지 않게 하는 규칙 (팩트만, 과최적화 방지)
1. **검증된 것만 교훈이 됩니다.** 가정 결과는 먼저 "관찰 메모"로만 저장하고, 전략 검증관의 미관측 구간 확인을 통과해야 교훈으로 올라갑니다.
2. **교훈 카드에 근거를 필수로 적습니다.** 거래 수, 신뢰구간, 기간, 장세, 재검토일이 없으면 등록하지 않습니다.
3. **틀린 것도 기록합니다.** 기각된 가설은 "기각 목록"에 남겨 같은 아이디어가 반복 제안되지 않게 합니다.
4. **잊는 규칙도 있습니다.** 시장이 바뀌면 교훈도 틀려질 수 있습니다. 재검토일마다 다시 확인하고, 반대 증거가 쌓이면 폐기합니다.
5. **ML 모델은 과거로만 학습하고 미래로 채점합니다**(walk-forward). 학습 전후 성능을 미관측 구간에서 비교해 나빠지면 이전 모델을 유지합니다.
6. **교훈끼리 충돌하면** 학습 관리 에이전트가 표시하고, 전략 검증관이 판정합니다.

### 10-5. 새 역할: 학습 관리 에이전트 (1명, Sonnet)
- **하는 일**
  - 검증 통과 결과를 교훈 카드와 사례집으로 정리합니다.
  - 중복·충돌·만료를 관리합니다.
  - 각 에이전트에게 맞는 교훈을 골라 넣어 줍니다(어떤 교훈을 넣을지는 코드 규칙으로 선택).
  - 에이전트 채점 결과를 전달합니다.
  - 월간 "무엇을 새로 배웠고, 무엇을 버렸나" 보고서를 씁니다.
- **소속과 인원**: ⑧ 자기진화팀. 에이전트 총 **23명**이 됩니다.
- **저장소**: TimescaleDB 표(교훈·사례·채점·기각 목록) + 사람이 읽을 수 있는 `knowledge/` 마크다운. 교훈 추가·폐기 이력은 Git과 MLflow에 남깁니다.

### 10-6. 학습 주기
| 주기 | 학습 내용 |
|---|---|
| 매일 | 사례집 추가, 에이전트 예측 채점, 관찰 메모 저장 |
| 매주 | 검증 통과 교훈 등록, ML 모델 walk-forward 재학습, 규칙 반영(도전자 → 승인) |
| 매월 | 교훈 재검토·폐기, 에이전트 업무 지침 개선, "배운 것·버린 것" 보고 |

## 11. 업무량과 인원 운영

### 11-1. 팩트: AI 직원의 "힘듦"은 피로가 아니라 과부하입니다
- AI 에이전트는 지치지 않습니다.
- 다만 **한 번 실행에 일과 자료를 너무 많이 주면** 품질이 떨어집니다. 놓치는 내용이 생기고, 숫자를 섞고, 근거 없는 말이 늘어납니다.

### 11-2. 과부하를 막는 운영 규칙
1. **실행 1번 = 업무 1건**: 한 에이전트에게 여러 업무를 한꺼번에 주지 않고, 업무별로 따로 실행합니다. 같은 직원이 여러 번 출근하는 방식입니다.
   - 가정 분석가: 분야별 실행 (진입 / 청산 / 크기 / 필터 / 시간 / 포트폴리오 / AI 판단 / 비용 / 기준선 / 스트레스)
   - 손익 복기 분석가: 매매법별 실행
   - 성과 분석가: 지표 / 요일·시간대 / 드리프트 따로
   - 전략 검증관: 후보 1건당 1번 실행. 통계 계산은 코드가 하고, 자동 관문에서 떨어진 후보는 에이전트에게 가지 않음
2. **필요한 자료만 넣습니다**: 코드가 요약표를 만들어 넘기고, 원본 로그를 통째로 주지 않습니다.
3. **실행 시간·턴 수 상한**을 둡니다.
