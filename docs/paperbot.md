# paperbot: paper 엔진 v1

거래소에 주문을 보내지 않고, 실제 시세 봉 위에서 체결·수수료·펀딩·격리 청산을 계산하는 엔진입니다.
외부 라이브러리 없이 Python 3.11 표준 라이브러리만 씁니다(테스트에는 pytest).

## 들어 있는 규칙 (인수인계 문서 5.1과 두 분 결정 기준)
| 규칙 | 구현 |
|---|---|
| 진입 | 확정봉 신호 → **다음 봉 시가** 시장가. 테이커 수수료 0.05%, 불리한 슬리피지 0.02% |
| 손절 | 스톱-마켓. 손절가에서 슬리피지 적용. 봉이 손절가를 **건너뛰어 시작하면 시가 체결** |
| 익절 | 지정가, **ROE 기준**(기본 10%) → 가격 = 진입가 × (1 ± ROE/레버리지). **닿기만 하면 미체결, 뚫어야 체결**. 메이커 0.02% |
| 한 봉에서 손절·익절 모두 닿음 | **손절 먼저**로 가정 (보수적) |
| 증거금 | **격리**. 청산은 **마크 가격** 기준, 청산 시 그 포지션 증거금 전액 손실 |
| 청산가 공식 | 바이낸스 격리 공식: LP = (증거금 + cum − 방향×수량×진입가) / (수량×MMR − 방향×수량) |
| 펀딩 | 정산 시각에 방향×수량×마크가×펀딩률. 격리 증거금에서 차감하고 청산가를 다시 계산 |
| 크기 등급 | 기본 20%×20배 / 좋음 30%×30배 / 최상 40%×50배(안 되면 40배) |
| 등급 강등 | 요청 등급부터 아래로 내려가며 첫 번째로 통과하는 등급을 씀: ① 거래소 레버리지 구간 허용 ② 손절이 청산가보다 max(3×ATR, 진입가 0.2%) 이상 안쪽 ③ 손절 시 손실(수수료·슬리피지 포함) ≤ 잔고 15%. 기본 등급도 안 되면 **진입 거부** |
| 포지션 | **한 번에 1개**. 보유 중 신호는 "건너뜀"으로 기록. 동시에 여러 신호면 점수 높은 것 1개 (동점은 종목 순서) |
| 낙폭 | 고점 대비 -20/-30/-40% 경고, **-50% 자동 정지**(포지션 청산 + 신규 진입 거부). `resume()`은 사람이 호출 |
| 킬스위치 | `kill()`: 포지션 청산 + 정지 |
| 기록 | 모든 신호 결과(진입/건너뜀/거부 + 사유), 거래(수수료·펀딩·MAE/MFE·ROE·등급), 자산 곡선 → SQLite(WAL) |
| 알림 | INFO / WARN / CRITICAL 3등급. 텔레그램 토큰·채팅 ID는 환경변수로만 받음 |

## 아직 확인 안 된 것 (팩트)
- 청산가 공식과 레버리지 구간은 **예시 표(`Brackets.example()`)로만 테스트**했습니다. 이 작업 환경에서는 바이낸스 접속이 막혀 있습니다. Vultr 서버에서 `GET /fapi/v1/leverageBracket` 실제 값을 받아 쓰고, 바이낸스 화면 계산기 값과 대조하는 테스트를 추가해야 합니다.
- 수수료율은 VIP0 기본값입니다. 실계정 값은 `GET /fapi/v1/commissionRate`로 확인해야 합니다.
- 슬리피지는 고정 0.02%입니다. 호가 기반 모델은 다음 단계입니다.
- 마크 가격 봉이 없으면 최근 거래가 봉으로 대신합니다(결과에 표시 필요).

## 실시간 데이터 (v1.1)
| 파일 | 역할 |
|---|---|
| `paperbot/binance.py` | 바이낸스 USDⓈ-M REST 클라이언트(표준 라이브러리만 사용). 429/418/5xx는 대기 후 재시도, 451/403(지역 차단)은 즉시 중단. 서명 요청(레버리지 구간·수수료율)은 읽기 전용 API 키 필요 |
| `paperbot/feed.py` | **확정된 1분봉만** 가져옵니다(형성 중인 봉 제외). 마지막으로 본 봉 이후 빈 구간은 자동으로 채웁니다(backfill). 마크 가격 봉을 결합하고, 펀딩 정산을 해당 분에 붙입니다. 종목이 늦으면 20초 기다린 뒤 "데이터 누락" 경고와 함께 진행합니다. 4분 이상 새 봉이 없으면 경고하고, 서버 시계를 기준으로 삼습니다 |
| `paperbot/aggregate.py` | 1분봉 → 5분·15분·30분·1시간·4시간·일봉 (UTC 경계). 1분봉이 빠진 봉은 "불완전"으로 표시하고, 그 봉에서는 신호를 내지 않습니다 |
| `paperbot/live.py` | 실행기. 1분봉 t마다 ① 엔진이 t-1 신호를 t 시가에 체결하고 청산·펀딩 처리 ② 확정된 봉(t, 그리고 t에서 끝나는 상위 봉)을 매매법에 전달 ③ 나온 신호는 t+1 시가에 체결 |

### 명령
```bash
# 서버에서 바이낸스 연결 점검 (시계, 6종목 규격, 1분봉·마크가·펀딩, 키가 있으면 레버리지 구간)
python3 -m paperbot.live check

# paper 실행 (매매법이 아직 없으면 데이터·엔진·기록만 돔)
python3 -m paperbot.live run --ledger paper.db
python3 -m paperbot.live run --ledger paper.db --max-steps 30   # 30분만 시험
```
레버리지 구간은 `--brackets 파일`, 또는 환경변수 `BINANCE_API_KEY`/`BINANCE_API_SECRET`(**읽기 전용 키**)가 있어야 실행됩니다. 예시 표로 돌리려면 `--allow-example-brackets`를 명시해야 합니다. 실수로 가짜 표를 쓰지 않도록 기본값에서 막아 두었습니다.

### Vultr 서버 준비 순서
1. **지역 선택**: 미국 리전은 바이낸스가 차단합니다(HTTP 451). 서울·도쿄·싱가포르 등으로 만든 뒤 `check`로 확인합니다.
2. Python 3.11 이상 설치 후 저장소를 클론합니다.
3. `python3 -m paperbot.live check`: 모든 줄이 `[OK]`인지 확인합니다.
4. 바이낸스에서 **읽기 전용 API 키**를 발급합니다(주문·출금 권한 끄기, 서버 IP 허용). 키는 서버의 환경변수 파일(권한 600)에만 둡니다. 저장소에 넣지 않습니다.
5. 텔레그램 봇 토큰과 채팅 ID를 환경변수로 설정합니다(`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_CRITICAL`, 선택으로 `_WARN`, `_INFO`).
6. `--max-steps 30`으로 30분 시험 후 systemd 서비스로 상시 실행합니다(자동 재시작).

### 이 작업 환경에서 확인한 것
- 테스트 43개 통과: 가짜 거래소로 시험했습니다.
  - 형성 중인 봉 제외, 빈 구간 채우기, 종목 지연 대기와 누락 경고
  - 펀딩 분 매칭, 429 재시도, 451 즉시 중단, 서명 요청
  - 5분봉 합성, 불완전 봉 표시
  - 5분봉 신호가 다음 1분봉 시가에 체결되는지
- `check` 명령은 이 환경에서 **"프록시 403"으로 실패**합니다. 바이낸스 접속 차단 때문이며 예상된 결과입니다. **실제 연결 확인은 Vultr에서** 해야 합니다.

## 두 장부 동시 운영 (v1.2)
같은 신호를 두 장부에 동시에 넣습니다. 차이는 **규칙뿐**입니다.

| 항목 | 두 분 규칙 장부 (`owner`) | 권고 규칙 장부 (`recommended`) |
|---|---|---|
| 크기 | 증거금 20/30/40% × 20/30/40~50배 등급 | **한 번 위험 = 잔고 1%** (최상 등급은 검증 통과 후에만 2%). 수량 = 위험 금액 ÷ (손절 거리 + 수수료·슬리피지) |
| 레버리지 | 20~50배 | **계산 결과**. 증거금이 잔고 안에 들어가는 가장 낮은 배수, 상한 10배 |
| 익절 | ROE 10% (레버리지로 가격 환산) | 매매법이 준 목표가, 없으면 **2R** |
| 손절 | 매매법의 손절가, 청산선 안쪽 검사 | 같음 |
| 하루 손실 한도 | 없음 | **-3%** 도달 시 그날(UTC 00:00 = KST 09:00까지) 신규 진입 중지 |
| 연속 손실 | 없음 | **5연패 시 24시간 중지** |
| 낙폭 | -20/-30/-40% 경고, -50% 정지 | 같음 |
| 포지션 | 1개, 격리 | 같음 |
| 규칙 버전 | `paper-v1` | `recommended-v1` |

- 권고 장부의 -3%, 5연패, 2R은 **초기값**입니다. 인수인계 문서는 장치 이름만 정하고 숫자는 정하지 않았습니다. 바꿀 때는 버전을 올립니다.
- 기록은 같은 DB에 `run_id-owner`, `run_id-recommended`로 나뉘어 저장됩니다.
- 알림에는 `[owner]`, `[recommended]` 표시가 붙습니다.
- 실행: `python3 -m paperbot.live run --ledger paper.db` (기본 두 장부), `--books owner`로 하나만 돌릴 수도 있습니다. `replay`도 같은 옵션을 씁니다.

**테스트에서 확인된 팩트:** 한 번 위험을 1%로 잡으면, 왕복 수수료(명목의 0.1%)만으로도 1% 예산이 다 찹니다. 그래서 손절을 아무리 좁혀도 포지션이 잔고의 약 10배를 넘지 못합니다. 권고 장부의 10배 상한은 사실상 수수료가 먼저 지켜 줍니다.

## 거래 분석: 원인 태그 · 가정 실험실 · 요일/시간대 (v1.3)
모든 기능은 **이미 끝난 거래를 설명**할 뿐입니다. 결과를 보고 규칙을 바로 바꾸지 않습니다. 좋아 보이는 것은 "가설"로 적고, 2026-09-30 이후 새 데이터에서 다시 확인한 뒤에만 채택합니다.

```bash
python3 -m paperbot.analyze --ledger paper.db --run-id <run_id>-owner --out report
# report.json, report.md 생성. --by strategy_id 로 매매법별 시간대 표 추가
```
1분봉은 `live run`이 같은 DB의 `bars1m` 표에 자동 저장합니다. 백테스트 데이터로 돌릴 때는 `--bars 폴더`(CSV)를 씁니다.

### 1) 진입 시점 차트 상황 (`context.py`)
신호가 나오는 순간, **이미 확정된 봉만** 써서 차트 상황을 적어 둡니다 (`signal.meta["ctx"]` → 거래 기록 `context`).
- 국면: 추세 상승 / 추세 하락 / 박스 / 횡보(경계 없음) / 불명. 효율비(ER), 기울기, 위·아래 경계 접촉 횟수(각 2회 이상)로 판정. 경계는 고가 95%·저가 5% 분위수라 꼬리 하나에 흔들리지 않습니다.
- 박스 안 위치(0=바닥, 1=천장), ATR, EMA20에서 몇 ATR 떨어졌는지, 추세 나이, 상위 시간봉 국면과 위치.
- 상위 시간봉: 1분→15분, 5분→30분, 15분→1시간, 30분→4시간, 1시간→4시간, 4시간→1일. 실시간 실행에서 자동으로 만들어집니다.
- 기준 봉 수: 1분 60, 5분 72, 15분 64, 30분 48, 1시간 48, 4시간 42, 1일 30. 모든 기준값은 **초기값**이며, 사람이 붙인 정답 라벨과 맞추는 용도로만 조정합니다. 수익이 좋아지도록 맞추지 않습니다.
- 실시간 시작 직후에는 봉이 모자라 "불명"이 나옵니다 (예: 1일봉 30개 = 30일).

### 2) 손익 원인 태그 (`tags.py`)
이긴 거래도 모두 태그를 붙입니다. 그래야 "이 태그가 붙으면 정말 더 잃는가"를 기준선과 비교할 수 있습니다.

| 구분 | 태그 | 뜻 |
|---|---|---|
| 진입 시점 (필터 후보) | H0 | 상위 시간봉 추세 반대 방향 진입 |
| | B1 | 박스 한가운데(0.35~0.65) 진입 |
| | B2 | 박스 천장 근처 롱 / 바닥 근처 숏 |
| | B3 | 추세·돌파형 매매법이 박스·횡보에서 진입 |
| | R1 | 역추세형 매매법이 추세 반대로 진입 |
| | E1 | 추세 늦은 진입 (EMA20에서 2.5 ATR 이상 벌어진 뒤) |
| | B7 | 상위 시간봉 박스 벽 근처 진입 |
| 결과 (설명용, 필터로 안 씀) | LIQ | 강제 청산 |
| | G1 | 1R 이상 이익이 났다가 손실로 끝남 |
| | T1 | 손절 후 20봉 안에 목표가 도달 (손절이 좁았을 가능성) |
| | W1 | 익절 후 가격이 1R 더 감 (익절이 빨랐을 가능성) |
| | W2 | 최대 이익의 절반 이상 반납하고 익절 (익절이 늦었을 가능성) |
| | W5 | 수수료 빼기 전엔 이익, 뺀 뒤 거의 0 |
| | W3 / N0 | 특이사항 없는 이익 / 손실 |

- 손익 구분: 순손익이 -0.1R 이하 = 손실, +0.1R 초과 = 이익, 그 사이 = 본전.
- 대표 원인은 정해진 순서로 하나 고릅니다. 1R 이상 이익을 봤던 손실은 **진입은 맞았다**고 보고 청산 쪽 원인(G1, T1)을 먼저 봅니다.
- 태그 표의 "lift" = (손실 거래 중 이 태그 비율) ÷ (이익 거래 중 이 태그 비율). 1보다 크면 손실 쪽에 더 자주 붙은 것입니다. 거래 30건 미만이면 "표본 부족"으로 표시하고 결론을 내지 않습니다.

### 3) 가정 실험실 (`whatif.py`)
같은 진입(시각, 가격, 수량, 레버리지, 증거금, 청산가)을 그대로 두고 **청산 규칙만 바꿔서** 1분봉으로 다시 계산합니다. 체결 규칙은 엔진과 같습니다.

| 묶음 | 규칙 |
|---|---|
| 기준 | C0 = 원래 손절·익절 (엔진 결과 재현 검사) |
| 손절 | ROE -10 / -20 / -30 / -40 / -50% |
| 익절 | ROE 10 / 15 / 20 / 30 / 50%, 1.5R / 2R / 3R |
| 관리 | 1R 이익 뒤 본전 손절, 60분 / 4시간 / 24시간 시간 청산, ATR 1.5배 / 3배 추적 손절 |

- **C0 재현 검사**: C0 결과가 엔진 장부와 다르면 "MISMATCH"로 표시합니다. 이게 맞아야 나머지 비교를 믿을 수 있습니다.
- 비교 방법: 같은 거래끼리 짝지어 (규칙 수익 − C0 수익)을 구하고, **하루 단위로 묶어** 부트스트랩합니다. 규칙이 여러 개이므로 Holm·Bonferroni 보정을 합니다. 30건 미만이면 "표본 부족".
- 판정: "C0보다 좋음(가설, 이후 데이터로 확인 필요)" / "C0보다 나쁨" / "뚜렷한 차이 없음" / "이 거래들에선 C0와 동일".
- 경고 표시: 넓힌 손절이 **계좌 15% 한도를 넘는 거래**는 `over_cap`으로 셉니다 (실제라면 수량을 줄였거나 거절됐을 거래). 강제 청산 횟수도 따로 셉니다.
- 한계 (보고서에 항상 적힘): 펀딩비 제외. 포지션을 1개만 잡으므로 청산이 달라지면 다음에 잡을 수 있는 신호도 달라지는데, 이 연쇄 효과는 계산하지 않습니다. 운영자 정지(HALT)로 끝난 거래는 제외합니다.

**테스트에서 확인된 팩트:** 무작위 가격(엣지 없음)에 신호 125개를 넣고 돌렸을 때, 19개 규칙 모두 "뚜렷한 차이 없음" 또는 "동일"로 나왔습니다. 실험실이 없는 우위를 만들어 내지 않는다는 점검입니다. C0 재현은 124건 모두 일치했습니다.

### 4) 요일·시간대 표 (`sessions.py`)
**진입 시각을 한국 시간(KST)**으로 봅니다. 주말 = KST 토·일.

| 시간대 | KST |
|---|---|
| 아시아 | 09~16시 |
| 유럽 | 16~22시 |
| 미국 | 22~05시 |
| 새벽 | 05~09시 |

- 기본 표: 평일/주말 × 4개 시간대 = **8칸**. 칸마다 거래 수, 승률, 평균 R, 손익. 30건 미만 칸은 "표본 부족".
- 특수 구간 안/밖 비교: 펀딩 정산(UTC 00/08/16시) ±10분, 미국 개장(뉴욕 09:30, 서머타임 자동 반영) ±1시간, 미국 지표 발표 시각(뉴욕 08:30) ±30분. 지표 구간은 "보통 발표되는 시각"이며 실제 발표 일정표는 아닙니다.
- 요일별 표와 7×24 히트맵도 만들지만 **설명용**입니다. 168칸을 하나하나 검정하면 우연히 좋아 보이는 칸이 반드시 나옵니다.
