# 장세 문지기 밤 계산 (두 분용 설명)

친구분 말씀 "추세장이면 추세장 매매법을 사용, 횡보장이면 진입 금지"와 사장님 말씀 "횡보장에서도 발라먹고 추세장에서도
발라먹는"을 그대로 규칙으로 만든 **장세 문지기**를, 규칙봇이 실제로 돌고 있는 기간에 매일 밤 확인하는 계산입니다.
2026-10-11 두 분이 합의한 (B)입니다. 규칙은 결과를 보기 전에 `research/regimegate/PREREG_REGIMEGATE.md`에 고정했습니다.

**실제 계좌 · 주문 · 30일 판정은 하나도 바뀌지 않습니다.** 규칙봇 데이터베이스는 읽기만 하고, 주문을 내지 않고, 자기
텔레그램도 없습니다. 규칙봇과 다른 폴더의 코드 복사본에서 돌아서 규칙봇을 다시 시작하지도 않습니다.

## 무엇을 기록하나

- **신호 전부**: 규칙봇 36개 매매법 × 15분·30분·1시간·4시간 × 코인 6개의 기본값 신호를 하나도 빼지 않고 씁니다.
  실제 계좌는 포지션이 있으면 다음 신호를 건너뛰지만, 여기서는 **신호 하나 = $5,000 계좌의 한 번 매매**로 따로 계산합니다.
- **기간**: 신호 봉이 **10/05 18:35 UTC(v4 시작) ~ 10/30 00:00 UTC** 사이에 닫힌 것. 10/30 하루는 열려 있는 거래를 마저
  끝내는 데만 씁니다. 그때도 안 끝난 거래는 건수만 세고 뺍니다.
- **결과**: 지금 청산 규칙(2 ATR 손절 + 계단 익절)으로, 실제와 같은 레버리지(진입 강도로 정하는 50·40배 / 30·20배),
  수수료, 슬리피지, 펀딩(실제 값), 청산까지 넣은 손익 ÷ $5,000. 진입 확인에서 거절된 신호는 거래가 아니라서 뺍니다.
- **신호가 난 봉의 장 상황**: 장세(추세장 · 횡보장 · 급변장 · 보통)와 변동성(큼 · 보통 · 작음). 대시보드 '장세 스위치'와 같은
  계산이고, 신호가 난 봉까지의 자료만 씁니다(미래를 보지 않음). 1년치 이력이 필요해서 처음 실행 때 5분봉 약 430일치를
  받아 둡니다.
- **매매법 묶음**: 카탈로그의 '성격' 그대로. 규칙봇 36개는 추세형 19 · 되돌림형 5 · 그 밖 12.

## 문지기

| | 추세형 | 되돌림형 | 그 밖 |
|---|---|---|---|
| **G1 장세 문지기** | 추세장에서만 | 횡보장에서만 | 추세장에서만 |
| **G2 변동성 문지기** | 변동성 큼에서만 | 변동성 작음에서만 | 변동성 큼에서만 |
| G3 안 막음 (비교 기준) | 늘 | 늘 | 늘 |

급변장과 보통 장은 G1에서 모두 막습니다(친구분이 말씀하신 것은 '추세장'뿐이라서). 문지기가 **들여보낸 신호가 막은
신호보다 나은지**, 그리고 **들여보낸 신호가 비용을 빼고도 플러스인지** 봅니다.

## 읽는 법

결과 한 줄 (매일 10:40 한국 시간에 새로 씀):

```
cat /var/lib/paperbot/regimegate/last.txt
```

모양: `장세 문지기(참고 · 판정 아님) 10/14까지 9일: 끝난 거래 N건(안 끝남 N · 장세 모름 N) · G1 들임 N건 ±x.xx% /
막음 N건 ±x.xx% · G2 들임 N건 ±x.xx% / 막음 N건 ±x.xx% · 지금까지 통과 n/8줄 · 실제 계좌 재현 xx%`

- **끝난 거래**: 계산에 들어간 신호 수. 안 끝남 = 아직 열려 있는 거래, 장세 모름 = 이력이 모자라 장세를 모르는 신호(빠짐).
- **G1 들임 / 막음**: 문지기가 들여보낸 신호와 막은 신호의 건수, 그리고 거래당 평균(손익 ÷ $5,000).
- **지금까지 통과 n/8줄**: G1·G2 각각 '전체 · 추세형 · 되돌림형 · 그 밖' 8줄 중 지금 자료로 통과 조건을 모두 넘은 줄 수.
- **실제 계좌 재현**: 실제 계좌가 들어간 진입(코인 · 방향 · 진입 분) 중 이 계산에도 있는 비율. 많이 낮으면 이 숫자를 믿지
  마세요.

8줄 자세히:

```
cd /opt/paperbot-regimegate/app && sudo -u paperbot /opt/paperbot/venv/bin/python -m paperbot.regimegate show
```

줄마다 들임 · 막음 건수와 거래당 평균, **p**(들임이 막음보다 나은 게 우연일 확률), **무작위 p**(같은 수를 무작위로 막은
1,000번보다 나은지), **묶음 p**(그 무작위 평균보다 나은 몫이 하루 단위로 다시 뽑아도 남는지), 그리고 '지금은 통과' /
'못 넘음' / '건수 부족'(들임이나 막음이 30건 미만)이 나옵니다. 통과 조건은 다섯 가지 모두입니다: 양쪽 30건 이상, 들임
평균 > 막음 평균(p < 0.05), 들임 평균이 비용 뒤 플러스, 무작위 p < 0.05, 묶음 p < 0.05.

처음 며칠은 건수가 적어 숫자가 크게 흔들립니다. 기간 중의 '통과'는 **지금까지**일 뿐입니다.

## 설치 (한 번)

개발자가 규칙 고정 파일을 저장소에 올린 뒤에만 설치됩니다(없으면 설치가 아무것도 바꾸지 않고 멈춥니다).

```
cd /root/crypto-bot-research && git pull && sudo bash deploy/regimegate/install_regimegate.sh
```

- 규칙봇 설치가 먼저 있어야 합니다(사용자 paperbot, `/opt/paperbot/venv`).
- 필요한 코드만 `/opt/paperbot-regimegate/app`에 복사하고, paperbot 사용자로 자체 점검(selfcheck)을 통과해야 바꿉니다.
- 매일 10:40(한국 시간) 타이머를 켜고, 첫 계산을 바로 뒤에서 시작합니다. 첫 계산은 15~30분(5분봉 이력 받기), 그다음부터는
  몇 분입니다. 진행: `sudo journalctl -u paperbot-regimegate -f`
- 쓰는 곳은 `/var/lib/paperbot/regimegate`뿐입니다(봉 저장, 신호 표, `last.json`, `last.txt`).
- 실패하면 기존 실패 알림으로 하루 한 번 경고가 옵니다. 빠진 날은 다음 밤에 이어서 계산합니다.
- 업데이트: 위 명령을 다시 실행. 규칙 · 계산 코드가 바뀌면 기간 처음부터 다시 계산합니다.
- 끄기: `sudo systemctl disable --now paperbot-regimegate.timer` (기록은 남습니다)
